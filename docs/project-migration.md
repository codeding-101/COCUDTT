# 旧项目导入与迁移说明

当前程序接受 `schema_version` 为字符串 `0.1`–`0.8` 且满足现有字段结构的项目，保存统一为 `0.8`。这是**容器版本升级**：不会修补缺失的必需字段，不会从旧版本号猜测或补造业务条件。

| 原文件情况 | 导入行为 |
|---|---|
| 0.8，结构完整 | 原样读入（含空输入和未知扩展），继续核对与计算 |
| 0.1–0.7，结构兼容 | 校验后仅将内存中的 schema_version 改为 0.8，其他输入保持 |
| 缺必需字段、错误类型/枚举、重复费用ID | 明确拒绝；原来的当前项目和草稿不被替换 |
| 未知版本、缺版本、非标准 JSON、顶层不是对象 | 明确拒绝，不回退到示例或当前模型 |

导入旧文件不会自动开启中国一般贸易模式、填写申报日期、重算来源确认或补税率/汇率。若原文件显式包含模式及其他扩展字段，则保留这些字段；后续按其输入及当前业务核对决定是否可计算。旧文件的金额字符串精度、人工费用承担、来源、运输/保险和未知扩展保留，不删除空文本。

打开只修改应用内存，不改原磁盘文件。请保留旧文件备份，再“保存项目”选择新文件名另存为 0.8；保存选择器允许选择同名文件，工具不承诺自动防止用户主动覆盖。新程序保存的语义不能据此认为旧程序仍能正确处理，旧版应按版本规则明确拒绝。

## 可复查的迁移步骤

1. 保留原 JSON，核对版本及是否含内部资料。
2. 在编辑器/独立验证器关联[导入 Schema](../schemas/project-import-0.1-0.8.schema.json)，或直接使用工具的“打开项目”。应用还会检查跨费用ID重复。
3. 查看商品、报价/比较基准、费用、商业与海关汇率、税务模式和来源；待确认/失效条件继续存在，不因文件能打开而当作完整方案。
4. 另存新文件。用新文件重新打开，逐项对照输入和金额；客户公开字段、预览检查及假设控件暂不随项目迁移。

当前暂无填补不同历史结构缺口的自动迁移器，也未新增 0.9 或持久化客户条款。本轮覆盖各受支持容器版本、未知版本拒绝、未知扩展/高精度/空值保留以及合成用例保存前后计算一致；真实历史业务文件验收在取得脱敏资料后另做。
