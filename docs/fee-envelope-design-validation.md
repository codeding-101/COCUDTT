## 独立设计证据

命令：`node tools/check-fee-envelope-design.mjs`。

| 协议 | 固定检查范围 |
|---|---|
| ADOPTION | 新业务、旧项目0.8/0.9、配对1.0/1.1、备份、有效/未来封套的预览/采用/恢复；旧来源不自动变成未消费 |
| LEDGER | 原点、序号、前链/内容指纹、业务身份、批内重复、已消费来源/曾创建目标、重复事务、引用零消费、删除仍留历史；两次事务间人工编辑允许 |
| LOOKUP | 新ID仍查来源键、完整计划/行冲突、相同回执无写入、当前后payload改变待核、引用/缺目标、退休目标和未知历史 |
| RECOVERY | 同快照、无最新锚点、旧修订、同修订异内容、删历史、退休集合缩减、不同业务、兄弟分支和保留历史的后继预览；从不自动安装 |
| COPY | 另存/重命名保留历史；新业务必须重建业务/账单/行/拟建目标身份并撤销确认，不把旧回执搬成新业务执行历史 |
| LIMITS | 128MiB外层、512归档、64回执、50行、十亿修订、深度32/节点300000的等界及超界；整体拒绝，不截断 |
| ARCHIVE | 原文/hash、引用闭包、缺引用/根、孤立条目、环/自环、32/33边及共享子图长路径，防止先遍历短路径隐藏超深链 |

**98个有效场景、31个拒绝输入**，其中有效包含大量应该阻断/待核的结果，并非97笔可应用交易。另有**15个回执叶字段变更、8组身份变体、2个固定指纹向量**，分别计数。固定预期写入向量，不调用生产函数生成答案；运行前后逐字比较输入。检查器不导入src，附带生产路径扫描禁止封套误接入；真实旧源码字节比对另外执行。

归档图和ledger为缩减模型：原文仅作普通JSON可解析性/长度检查，引用边和target_present等事实由向量明确给定；不证明真实格式、重复键防御、完整嵌套源关联或费用已执行。LIMITS只比较整数边界，没有创建128MiB真实封套。SHA用于一致性，不是签名、真实订单证明、跨标签锁或全局防重复。
