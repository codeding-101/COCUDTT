# 业务副本组合交接设计

2026-11-05，第127轮，本地候选。将既有独立业务副本的真实交易面板接入受信同源弹窗组合，保留原始输入文件及完整业务容器。没有重新实现贸易、税务或利润算法。

| 已接入输入 | 处理方式 |
|---|---|
| 项目名称、商品名称 | 原文本与2048字符限制 |
| 商品数量、数量单位 | 原项目校验；数量变化不会自动缩放整票报价或费用 |
| 货物净价／成交货值 | 与报价分开；沿用原金额和币种 |
| 卖方采购成本 | 允许未知，未知利润不补零 |
| 当前固定报价金额 | 只在固定报价口径可编辑，其他比较基准继续只读 |

[原交易面板](../tools/fee-recovery-trade-panel.ts)通过可选重绘端口协作，默认调用方保持既有行为。[原交易模型](../tools/fee-recovery-trade.ts)仍经过原项目解析、校验、费用包含推导、分析与方案比较。贸易术语、运输方式、汇率、税务、费用、合同、付款及归档资料在本轮保持，不自动采用旧核对或费用执行身份。

[组合入口](../tools/fee-business-modal-dom.ts)使用真实的七字段表单，字段说明与引导仍采用原组件源码的诊断适配。移动面板迁移同一棵details，不克隆File。文件选择只保留原File引用，没有读取或导入权限，必须继续处理或明确放弃选择。合成项目替换在业务表面被拒绝。

[重绘与关闭协调](../tools/fee-business-modal.ts)最多保留一个待绘任务，完整表单重绘优先于仅结果更新。上层弹窗存在时先遮蔽旧金额，保留原控件、数字原文与File；关闭上层不会自动执行，须明确更新显示。重绘失败仍留待办，失效上下文不能消费它。停止或失效后的表单事件不采用为业务数据；未采用DOM原文与模型有差异时仍阻止关闭。

来源核对仅选择project_json，通过原来源管理器准备完整候选、展示变更及未解决事项、单独勾选并明确确认。不应用费用，不修饰历史未知状态。完整交接沿用原继续文件格式、原文父链、来源历史和保存依据。准备文件不等于交付，下载开始不等于已保存；须核对完整交接文件后明确确认。单独项目JSON不能代替整套保存依据。重新打开会按原契约清除previous_raw及五项会话计数器；旧封套原文仍保存在完整来源历史，不能把旧计数器当成新执行身份。其余业务来源、历史及保留字段逐项保持。

关闭审查采用私有身份并再次检查业务资料、原文和显示版本。未提交交易、未读文件、未结束的模块/工厂/来源/写文件任务、延后显示、未保存修改及未完成交接均拒绝关闭。关闭与保存分别确认；关闭不改保存依据，不执行费用、不生成客户文件。清理开始后停止业务监听、保留只读原文，失败保留句柄，明确重试；已成功清理部分不重做。取消逻辑操作后仍等实际任务结束，迟到写入不能生成有效保存确认。

[适配输出检查](../tools/fee-business-modal-types.ts)使用已锁定TypeScript7 API，在内存文件系统编译实际三个适配模块、实际端口及业务面板；三项缺失成员反例必须被拒绝。没有用手写类型替身或只凭字符串往返证明接口完整性。

本轮不等于完整工作台重开、整个frame资源均已接管、原应用整体解绑或正式组件安装。只保留可信同源诊断副本，不宣称恶意脚本隔离、任意DOM失败原子性或浏览器总内存上限。
