# 第五十四轮：最近项目独立存储模块验收

2026-10-16。完成[设计边界](recent-projects-design.md)与两个独立数据模块。本轮不接入界面、自动草稿、恢复文件或客户输出；没有“最近项目”操作入口，也不会创建/读取新缓存。下一轮再单独验收页面接入。

## 实现

`src/data/recent-projects.ts`负责严格信封/条目检查、容量、原文取出、手动添加及单条删除。`src/data/recent-project-store.ts`只使用调用方注入的Storage，负责读取分类、原文租约、单键变更和读回核对；构造不做I/O，不访问全局localStorage。

- 最多3份，项目原文UTF-8上限256 KiB、序列化缓存上限1 MiB；中文、emoji及JSON外层转义计入大小。容量满不自动淘汰，空白税率/金额不补零。
- 相同项目原文复用既有条目；不同内容即使同名也不覆盖。时间只记录手动加入，不更新报价、申报或来源有效期。取出返回原项目JSON，含旧版本文本、精度字符串和未知扩展。
- 整体检查后才提供列表，坏条目不静默丢弃；未知/未来信封格式、超过上限和损坏内容保留原文供备份，新增或删除拒绝覆盖。明确接受丢弃后才允许清空该键。
- 写入前按完整原字符串比对租约，过时事件拒绝；写入/删除后读回。配额错误、权限失败、读回失败或并发改写返回错误，不误报成功、不擅自回滚其他页面内容。检查不是跨标签原子锁或事务。
- 已有交易草稿、配对、付款、客户文字和模式偏好不由本模块收集或清理；完整项目的未知扩展仍可能含敏感资料。缓存不替代独立JSON备份。
