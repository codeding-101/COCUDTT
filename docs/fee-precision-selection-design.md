# 精度选择记录：来源、版本与失效设计

2026-10-18，第六十五轮。承接[独立精度API](fee-precision-module-validation.md)与[成分附件1.0](fee-tax-attachment-file-validation.md)。本轮交付实现前契约、固定合成状态向量和独立检查器；**没有新增生产文件解析器、Schema、页面控件、草稿键或费用写入**。下述1.0是拟议格式，不能作为当前可导入文件。

## 记录什么，不能证明什么

精度记录只表达“对这份资料的这个原成分，记录了哪项算术政策”。它与成分来源核对、抵扣/海关资格、实际记账、付款、费用应用分别处理。界面未来同时展示三栏：来源是否相符、政策记录状态、原业务待办；不提供全局通过状态。

- `RECORDED_POLICY_ASSUMPTION`只表示当前软件绑定下的人工政策记录。EXAMPLE仍是示例，原凭证、金额失配、包含/重复、税务待办及`CORE_PRECISION_LOSS`全部保留。
- 不要求先消除全部业务待办才能记录算术选择，否则正是要解释的超六位原值将无法留档；但来源失配、目标孤立、原成分未知或选择未明确时，不能记录新的政策回执。
- 原成分附件回执的`RECORDED_ASSUMPTION`不迁移为精度回执；精度回执也不修改原附件。即使候选为零、可表示为六位或差额为零，都不能提升费用应用资格。
- G、N、T、X、E、C分别对应cash、net、tax、credit、economic、customs。X未知时E未知；C独立，不能用税额、净额或舍入差额代替。风险转移、付款和费用承担不从精度政策推断。

## 首版范围与独立格式

使用专用内部文件`INTERNAL_FEE_PRECISION_SELECTION / 1.0`，不改变项目0.8/0.9、账单1.0、配对1.0/1.1或成分附件1.0。专用入口明确打开，不能由项目扩展或附件自由字段自动激活。

```text
kind, version: INTERNAL_FEE_PRECISION_SELECTION / 1.0
selection_id: ASCII 1..80，新文档身份
revision: 1..1,000,000,000 安全整数
pair_snapshot_json, pair_snapshot_sha256: 完整配对原文及UTF-8 SHA-256
attachment_snapshot_json, attachment_snapshot_sha256: 完整成分附件原文及UTF-8 SHA-256
records: 0..48条
  record_id: ASCII 1..80，文档内唯一
  component_record_id: 原附件记录ID，不能用input.line_id代替
  target: 完整{mapping_id,bill_id,line_id,cost_id,operation}
  channel: cash | net | tax | credit | economic | customs
  currency: 原币三位代码
  original: null | {numerator,denominator} 原精确成分，非负既约分数
  choice: UNRESOLVED | ROUND | FX，结构见下文
  acknowledgement: null | {basis_sha256}
retired_record_ids: 0..500个已删除ID，禁止复用
content_sha256: 除本字段外规范JSON的SHA-256
```

活动槽位`(component_record_id, channel)`唯一：一个原成分首版只留一个当前选择，不能靠改目标币种新增第二份而被误合计。最多8个原附件记录×6通道=48；不是允许将同一原金额复制48次入账。slot、完整target和record_id不可编辑；换原记录、通道或映射须删除退休后新建。原附录短ID与账单/费用最多200码点的既有引用分别验证，不截短或混用。

`ROUND`保存`{kind:'ROUND',policy:{kind:'EXPLICIT',unit,mode,basis}}`，在原币上调用`reviewFeeRounding`。`FX`保存`{kind:'FX',to,purpose,as_of,rate_source,policy}`，from/amount/channel必须由本记录的currency/original/channel构造，不能另收一份可矛盾字段。policy和rate_source复用[数值模块](../src/domain/fee-precision.ts)的严格契约；不默认步长、汇率或方式。`UNRESOLVED`只有kind，没有候选或可记录回执。未完成文本留给独立编辑草稿，不伪造成正式choice。

新记录FX政策回执时，as_of首版必须等于配对账单review_date，rate_date≤as_of且valid_from≤as_of≤valid_to；不读取系统今天。重绑后允许保留旧as_of作为历史政策，但与新review_date不同则不能确认，须明确编辑政策。商业目的仅cash/net/tax/credit/economic及CONTRACT/MARKET；海关诊断仅customs、CUSTOMS、目标CNY及明确0.01/HALF_UP，并保留既有日期限制。这只是明确海关组成金额的诊断，不替换实际进口计税、估价或税款路径。

逐行/汇总、成分守恒和阶段顺序API仍可独立诊断，**首版不把它们存为可选政策**。合计结果不映射回单行，不拆分尾差；没有完整FX来源的单个rate不作为业务换汇记录。未来如需保存合计/顺序选择，须另定集合身份与版本，不能隐式扩大此格式。

## 三份原文必须相互一致

外层同时保存完整配对与完整原成分附件；后者本身已包含配对原文。打开时须严格验证三层JSON，且附件的pair_snapshot_json必须逐字等于外层pair_snapshot_json，指纹亦相符。验证原配对及附件既有content_sha256，不能凭selection_id、文件名、修订号或摘要相等省略原文。

所有原文按实际UTF-8字节计算SHA-256。源配对或源附件只换空白、键顺序、尾部换行也视为来源变化，不自动规范化续用回执；外层文件排版不属于来源，另存可使用稳定排版。外层内容指纹/政策basis规范化对象键，按UTF-16代码单元升序；数组顺序、字符串、金额尾零和依据空白保持，不做Unicode或数值文本规范化。

记录basis覆盖`contract='fee-precision-selection-1.0-policy-0.1'`、selection_id、record_id、pair_snapshot_sha256、attachment_snapshot_sha256、component_record_id、完整target、channel、currency、original、完整choice。当前记录回执、外层revision/content_sha256不进入basis，避免回执自循环和一条确认使其余失效。外层content_sha256则覆盖全部字段、修订和回执。

**原附件的修订、回执和content_sha256包含在完整源附件原文中。**所以仅确认原附件的一项来源也会使本文件全部记录待复核；这是首版保守规则，不优化为业务投影。操作顺序是先完成成分来源核对，再捕获精度资料。重复记录完全相同的当前政策回执应幂等；这不代表外部文件的全局事务锁。

## 原成分必须重算，结果不作为可信输入

正式模块实现时，从严格验证的源附件记录调用`reviewFeeTaxComponent`重算六通道，与currency/original和完整target逐项核对；不能把fixture中的合成通道表、旧UI展示字符串、已舍入候选或附件用户自填结果当作原金额。original只存规范既约分数或null；尾零等原文本由完整附件保留。

打开允许保存历史孤立/原成分失配记录，但必须显示待复核，不能确认或作为当前结论。非法结构、坏指纹、双份配对不一致、重复活动槽位/ID、复用退休ID整体拒绝。结构有效与业务当前相符是两个判断：实际源映射/成分删除、退休或换目标不删除历史记录，也不按名称或同值金额自动连回。

原成分为null可留档、结果仍null，不记录政策回执；明确0/1可记录，不能把两者合并。既有数值API的分数输入限额80位适用于原单成分，不套到派生结果。文件不持久化候选/差额/audit等可信缓存，展示和内部导出重算；派生600位以上分数保持完整。若原成分将来超过本版可接受上限，应整体明确报错，不截断或偷偷降精度。

## 修订、编辑、重绑与身份

所有变更携带`{revision,content_sha256}`完整租约，异步之前脱离调用方冻结候选。租约任一部分不符拒绝；真变更递增修订，上限拒绝不回绕。canonical完全相同的choice和original编辑为无变化，不增加修订；数值等值的不同原政策文本（例如0.01→0.010）仍是真变更。

| 事件 | 设计行为 |
|---|---|
| 仅记录一条当前明确政策 | 写该basis回执、修订+1，其余记录回执保持；不清除原业务待办 |
| 改choice、依据、FX来源或有效期 | 该记录回执清空；原源附件与其他记录不变 |
| 当前完整配对或原附件任意变更 | 全部显示来源失配；只读旧快照保留，不自动重绑 |
| 显式重绑同一pair_id和attachment_id的新完整原文 | 验证双份配对一致，全部回执撤销，修订+1；原记录、original、target和choice原样保留，失配项待复核，不静默改原值 |
| 重绑到不同pair_id或attachment_id | 拒绝；新建空文档，不能以重绑搬运旧业务政策 |
| 删除或换slot/目标 | 原ID退休，替换必须新ID；保留其他记录；槽位可由新ID明确使用，退休record_id永不复活 |
| 同一资料另存、文件重命名 | selection_id、修订及有效回执保持，不延长日期、不新建业务 |
| 新业务副本 | 新selection_id、修订1、空记录/退休集合；需提供该新业务一致的配对和新附件，不复制旧政策/确认 |
| 打开历史文件或恢复草稿 | 独立候选预览、重验实时来源；不自动安装项目/附件、确认、重绑或清除孤立记录 |

original不是普通可改表单：源金额变化后先重绑保留历史失配，用户删除退休旧记录，再从原附件重取新值新建；检查器中的人为original改动只用于证明假回执/不一致数据不能通过。恢复离线旧分支不可回退当前修订后冒充同一最新状态，须显示冲突并保留两份备份。

## 限额与严格解析

拟议外层最大64MiB，内嵌成分附件24MiB，外层独立配对10MiB，附件内部配对也须通过既有10MiB限制；实际转义后外层可能超过64MiB，应明确拒绝，不能承诺所有各自达上限的组合都能装入。先检查文本与UTF-8字节上限，再逐层解析；最大深度32、节点300000逐层限制、记录48、退休ID500、reference/basis200 UTF-16、原分数各80位。拟议值在正式模块中须实测，不是本轮性能承诺。

每层拒绝重复JSON键（含转义后同名）、孤立代理项、非有限数、未来版本、未知活动字段。对象API仅普通自有可枚举数据，拒绝访问器/原型/符号/稀疏数组/循环；不执行getter，不回显内部异常。旧容器同名`fee_precision_selection`扩展留在原处，不复制到活动槽位，不在打开旧项目时触发升级。SHA只是内容一致性校验，文件作者可以重算，不是签名、真实单据证明、加密或跨标签锁。

## 后续控制器、恢复和内外交接门槛

- 两份新版本草稿分别保存“已提交文档”和“未提交编辑”；编辑绑定selection_id、完整源双指纹、文档revision/content_sha256及slot。不注册现有草稿键，不让未完成编辑混入正式导出。恢复明确预览/采用，迟到读取和期间编辑须用操作令牌、完整实时租约与原始槽位原文比对阻断覆盖。
- 另存冻结完整候选；保存期间发生编辑，下载成功仅标记被保存的旧候选，当前仍未保存。取消/失败保留原文、编辑和内存。存储失败/部分写失败/跨标签冲突提供两份备份，不自动合并回执或宣称localStorage为原子事务。
- 内部JSON/HTML/Excel包含完整来源、输入、政策、精确原值/候选/有符号差额、未知与原待办，以及独立来源/政策状态。大型Excel输出要单独定限额并实测，不能截原文冒充完整备份。
- 客户HTML/XLSX/PDF/双语摘要继续只取既有公开白名单。精度原文、成分附件、内部依据/成本/回执/差额不能透传；自填公开文字仍由用户复核。正式客户隔离测试须植入完整附件和metadata哨兵并生成真实文件，本轮缩减投影不替代它。
- 来源、成分、精度、费用映射及原子应用是分别验收的层。最后才实现完整租约重验证、一次安装可保存项目/账单/映射新修订、重复/迟到/部分失败回滚；原`CORE_PRECISION_LOSS`不能通过“已记录政策”直接消除。

[固定状态向量](cases/fee-precision-selection-design.json)与[独立检查器](../tools/check-fee-precision-selection-design.mjs)验证缩减设计协议：双来源原文、完整槽位/basis、回执局部失效、保守全失效、重绑/身份、租约、保存/打开竞态、独立草稿、旧扩展、客户投影及限额。用简化配对/附件和预先给定通道值，**不调用生产解析器或数值模块，也不证明真实原成分重算、JSON攻击面、大文件、存储、浏览器或费用事务已实现**。固定状态答案预先写入，检查器不生成预期；自动单叶变更只作为补充不计入应用测试数。
