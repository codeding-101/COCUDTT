# 独立封套保存与恢复控制器（第七十四轮）

2026-10-19。承接[只读文件](fee-envelope-file-validation.md)与[内部交接审计](fee-envelope-handoff-validation.md)，交付[独立控制器](../src/ui/fee-envelope-controller.ts)及[87项专项测试](../tests/fee-envelope-controller.test.ts)。没有工作台入口、浏览器存储适配器或费用写入，不把注入接口的测试当作真实下载/跨标签页验收。

## 文件、候选与来源

构造不读写存储，不接触项目或附件。当前原文、最初采用原文、一个上次被替换版本、候选原文和已观察缓存分别保留。`openFile`只预览；`previewMemory`接收严格字符串候选；`prepareLocalRecovery`只检查本机候选。`adoptIncoming`携带令牌并明确采用，不能自动安装封套中的项目、账单、配对、附件或精度记录。

文件读取使用ArrayBuffer及fatal UTF-8解码，检查声明/实际字节数、整数字节上限、编码与严格JSON；不采用可能替换坏字节或删除BOM的File.text()路径。BOM保留后按现有严格JSON规则拒绝，已解码原文可备份；损坏UTF-8拒绝解码、不产生替换字符，原外部文件不被修改。本模块不提供损坏二进制文件的字节备份。JSON沿用128MiB及全部来源/历史约束，报告8MiB不限制JSON另存；大于报告上限的完整1.1历史实际验证可逐字另存。

只提供完整来源捕获更新，不提供任意表单文本编辑器。`updateSources`复制完整输入和对象租约后校验；只有来源变动才生成新修订，保留全部历史、档案与业务身份。不变来源保持原始排版与文件保存状态。旧租约、坏输入、访问器或操作期间显式失效均不提交部分修订。来源失配仍由原模块保留为待办，不自动重绑或确认政策。

## 采用与冲突规则

- 无当前锚点或历史未知须明确acknowledge_unverifiable；不同完整业务身份须switch_business；替换未保存的不同原文须replace_unsaved。确认选项只表示用户意图，不是调用方提供的业务认证。
- 旧修订、同修订不同内容、原点/回执前缀改变、退休集合减少、同身份历史起源改变、只换一半身份等均阻断；全部确认也不能绕过。历史未知的更高修订同样核对原点和历史，不跳过这些门槛。
- 同身份未知历史不能提升为已知，也不能将已知改为未知；新业务须由既有独立复制API重建完整身份，另作候选明确切换。本地命名空间不识别真实订单。
- 未识别的新比较状态默认阻断。格式排版变化与业务修订区分，但原文不同仍完整保留；候选不会自动选择“最新”。latest_proven始终false，结构核对不证明真实业务、付款或全局未重复。

读取令牌与内存epoch分开；新读取、取消、来源提交及显式失效阻断迟到结果。采用期间重新严格验证，并对LOCAL候选重新读取缓存。异步错误不能覆盖新提示或候选。未来运行适配器必须在外部业务上下文变化时调用`invalidatePending`，包括变化后又恢复原值的ABA情形；只检查blocked布尔值不足以证明期间没有外部变化。

## 缓存的原子接口契约

只在用户明确缓存/恢复/移除/备份时读取本机接口；没有自动缓存。版本化独立键为`trade-cost-engine:fee-envelope-v1`，值是完整封套1.0原文，不新增外层缓存格式、Schema或迁移，也不读取旧项目扩展。已有原文默认受保护，须明确恢复或备份后按精确原文移除，普通打开/采用不会覆盖它。此阶段没有未提交表单编辑槽。

注入存储接口必须提供`compareAndSet(key, expected, next)`，在协作写入者之间一次比较并提交；不提供普通get/set回退。测试用共享Map中的同步比较写入和延迟CAS验证竞争。**本轮没有浏览器CAS适配器**：运行接入需单独验证锁/事务及所有新键写入者遵守同一协议；不支持可靠原子协议的环境应保持文件交接，不启用缓存写入。读回不能替代该原子契约，也不证明任意外部写入者或另一设备没有变化。

缓存写入后还须读回与epoch核对。CAS失败、异常、配额失败、读回异常或写入期间内存变化均不宣称当前版本已缓存，保护槽位并保留当前/已观察/待写原文；实际缓存可能已发生写入，必须重读。不自动写回旧值“回滚”，以免覆盖外部分支。明确移除也要求精确预期原文和CAS；被移除的最近非空原文留在内存备份槽。清除缓存不会清掉当前封套。

文件128MiB上限不代表浏览器缓存配额能容纳该文件。尚无真实浏览器配额、跨标签锁、存储事件及大文件内存实测。

## 冻结另存与备份

另存捕获点击时完整原文；后续编辑、换文件或ABA返回同一文本均不能被旧保存标记清除未保存状态。只有写入器明确返回SAVED且当前epoch/原文仍一致才记为文件已保存；DOWNLOAD_STARTED只表示发起下载。缓存不充当文件落盘，内存候选/恢复始终待另存。

可分别备份当前、最初采用、上次替换、候选、已观察/实际缓存、最近移除缓存、上次文件写入和上次缓存写入的完整原文；取消/失败不清空资料或改变保存状态。坏JSON可作为TXT备份，坏UTF-16、不可读取或超限原文整份拒绝、不截断。最初/上次版本与备份槽有明确单份边界，不是无限撤销或多版本文件管理；每份封套内部的完整历史从不因此裁剪。主动选择新候选会替换候选槽，外部原文件保持，重要资料应先备份。
