# 配对资料交接界面设计

2026-10-15，第三十八轮。接入独立配对1.0打开/另存、捕获当前修订、已有引用的明确加入/移除、实时失配及独立草稿/原始异常备份；不应用费用、不推定承担或税务。导入的新建费用提案只读保留，本轮不生成新费用编辑器。

配对打开明确替换项目与账单，付款/资金计划、客户公开输入与假设参数重置，按钮及说明提醒先另存。先读取/验证整个容器、克隆资料、准备汇率行及账单文本，然后同步安装两个内存对象，最后重算/渲染。渲染或计算异常时隐藏结果但保留已安装完整资料，恢复备份不重跑验证。

原项目汇率簿可能含名字、编号、空簿/扩展/分别报价；现有rowsToBooks会合并。配对安装保存原簿与行快照，未实际编辑行时计算/保存仍使用原簿；本地草稿带可核验的行键。实际编辑后沿用原编辑器行为，配对显示失配，不能自动确认来源。未完成/重复汇率编辑行会在rowsToBooks中遗漏/覆盖，本轮阻断这类捕获/另存，原行留在草稿/异常备份，不能假称完整交接。原项目打开/新建保持已有流程。

任何界面字段修改（含安装时会重置的客户/付款参数）、其他操作/文件读取或异常取消迟到配对载入；配对开始/安装取消已有项目/账单/付款读取。保存冻结点击时完整文本，后续编辑不能改变本次写入；普通项目另存也核对点击时版本/数据，旧完成回调不得修改后来安装的配对项目保存状态；取消/失败不覆盖输入或显示底层路径。保存不是多键浏览器存储事务；独立草稿只恢复配对快照，不自动覆盖项目/账单，重启后失配保持，完整配对文件才是一份可靠交接资料。

新建配对默认空选择；加入已有引用需明确按钮，保留原提案并避免重复行。移除选择保留映射删除历史；删除账单行或换账单时须先移除悬空选择。实时核对显示完整项目/账单失配，不把旧提案待办当当前结果；失配时不能直接另存，须明确捕获当前修订。不支持自动新业务fork；另存拷贝保留身份。

客户HTML/Excel/PDF及项目/账单单独文件不携带配对提案私有字段。内部HTML/Excel仍是已有项目/账单报告，不新增配对审计工作表；完整提案与映射用配对JSON交接。异常备份新增可选配对及原始存储文字；旧6/8部分只读恢复保持，5MiB检查上限不变，大备份人工核对。真实手机、人工专业及实际单据复核继续暂缓。
