2026-11-03，第123轮。本轮是原行为盘点与可重复验证，尚未修复下表缺口，尚未安装新的移动组件。本地保留，不更新main或公开网站。

原实现见[src/ui/mobile-settings.ts](../src/ui/mobile-settings.ts)，调用方见[src/ui/app.ts](../src/ui/app.ts)。这里复用原工作台、原高级设置及全部168个控件，不用空面板副本代替表单。

## 已确认的调用与边界

1. `isSmall()`以700px为上限；701px直接打开返回false。原页面点击入口会先记录返回点、提交活动输入，再调用`open`。
2. `mount`为原高级设置节点放置占位，将同一节点移入原生dialog，展开details，设置body的overflow，再调用`showModal`。普通打开/关闭没有复制业务数据、控件或File对象。
3. 返回按钮和原生Escape走宿主`flushInput`，有效费用按原精度提交后再返回。原生`close`事件只有在当前dialog确实关闭且控制器仍活动时才处理，排队的旧close没有关闭重新打开的弹窗。
4. 同项目重绘先记录内部滚动，随后`app.innerHTML`替换整个表单，再调用`afterRender`。这与“移动同一节点”不同，控件和File选择不会自动继承。
5. 项目对象替换先关闭旧面板，清除返回点，重绘后回到页首。宽度变为701px时关闭面板，并尝试把焦点留在原控件。
6. 宿主`runUi`会处理部分抛错并进入恢复界面，不能据此宣称控制器内部具备事务回退。故障测试分别记录直接调用和实际页面点击。

## 原生验证发现，均未修复

| 缺口 | 实际复现与影响 | 后续验收条件 |
|---|---|---|
| 无效费用触发整页恢复 | 实际输入`-e`后按Escape，模型与输入原文仍在，但进入`INTERACTION`恢复；普通计算错误标记没有建立 | 原文可继续编辑，明确定位无效字段，保留其他输入；不能补零、继续导出或用整页恢复代替正常校验 |
| 重绘丢失文件选择 | 同项目重绘后新表单无已选文件；旧File仅由测试探针保留引用，不能冒充应用已保全 | 明确保留输入节点/选择，或在替换前阻断并交代未交接选择；不得写伪造路径恢复File |
| 折叠状态反向Tab停在首项 | 原候选列表的末项不能接收焦点；从首项按Shift+Tab被阻止后仍停在首项。全部内层面板展开时双向循环通过 | 在实际折叠/禁用/隐藏组合中选择可聚焦边界，验证原生Tab及Shift+Tab |
| 内联overflow优先级丢失 | 原`auto !important`返回后只剩`auto` | 同时保存并恢复原值及priority，区分原来缺失与显式声明 |
| 覆盖其他所有者的overflow | 活动期间其他所有者设为`clip !important`，返回时被旧值覆盖 | 只撤销自己仍持有的样式变更，外来修改保留并明确冲突 |
| 占位丢失使表单不可见 | 删除占位后返回，原控件与File仍在已关闭dialog中，控制器已非活动 | 丢失/移动/替换占位时仍保留可访问表单；不能静默结束或删除原文 |
| 宿主缺失仍报告打开 | 删除host后`open`返回true且active为true，dialog却未打开 | 在修改活动状态前完成真实宿主与节点关系检查；失败应准确返回且无迁移副作用 |
| showModal异常需宿主救援 | 直接调用时节点已移动、body已锁且active为true；实际页面点击会由外层恢复流程解除body锁 | 控制器自行回退节点、状态和自有样式；区分外层恢复与内部回退 |
| close异常留下弹窗锁 | 直接关闭抛错后active为false，但原生dialog仍open、body仍hidden，表单已移回 | 在失败时保留可重试状态，finally处理自有锁，不能假报完成 |

缺失host、占位、被替换的原生方法和外来样式均为专用测试页注入的故障条件，不代表普通用户每次操作都会遇到。无效费用、原页面重绘及折叠键盘路径直接使用既有原行为。文件选择用例没有派发解析事件，覆盖的是尚未交给导入器的控件状态；它不证明正常导入或已启动的File读取会丢失资料，后续需先核对实际异步读取所有者。

另做了同源码的直接引擎定位：在原合成样例中，分别把`goods`、`freight`、`insurance`三项费用的amount设为`-e`，都在`analyze → graph → computeGrossAmount → q → Decimal`抛出普通Error，而非EngineError。UI的`recompute`只把EngineError转为字段计算错误，其他异常重新抛出，因而进入外层恢复。该专项定位没有改引擎，也不是46套财务浏览器重跑。后续应修正常输入校验与错误归类，不能吞掉所有异常或将无效费用补零。
