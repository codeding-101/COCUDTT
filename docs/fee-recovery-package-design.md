# 完整内部项目包与独立只读打开

2026-10-30，第106轮。本地开发原型；公开工具与main保持第100轮。本格式用于内部保全，尚不安装到正式工作台，也不是完整业务重开。

## 解决的问题

第105轮来源同步已保存每次更新前后封套，但普通捕获与原四／五份交接文件没有包含这份完整更新记录。本轮提供一份可下载的内部JSON包，连同当前交易、来源历史和原始恢复档案一起保留。旧文件原文不改，旧格式与原交接接口继续可用。实现见[格式模块](../tools/fee-recovery-package.ts)、[传输协调器](../tools/fee-recovery-package-transfer.ts)及[面板](../tools/fee-recovery-package-panel.ts)。

## 文件与版本

包种类为 `INTERNAL_RECOVERED_BUSINESS_PACKAGE`，独立版本0.1，固定 `INTERNAL_HANDOFF_ONLY`。严格拒绝重复JSON键、未知顶层字段、未来版本、未知文件名、重复文件及不一致的字节数或摘要。版本不兼容须另外实现显式迁移，不以删字段或补业务事实兼容。

| 内嵌文件 | 保留内容 |
|---|---|
| recovered-project.json | 当前已提交的正式项目原文 |
| recovered-envelope.json | 当前封套原文；其中项目及五类来源必须与当前业务一致 |
| original-recovery.json | 原恢复档案；source_wire和supplement_json逐字保留 |
| new-application-backup.json | 本副本新应用一次费用时存在，保留完整原备份载体 |
| internal-handoff-manifest.json | 原四／五文件交接清单0.1原文，不扩充其字段或暗改版本 |
| source-update-audit.json | 新增独立审计记录：全部来源同步前后封套、五来源字节与摘要、未解决事项 |

清单按原交接顺序绑定原数据文件；新增审计文件由外层包绑定。外层保存各文件完整文本、UTF-8字节和SHA-256，并以规范JSON计算自身内容摘要。**摘要只证明包内自洽和帮助发现损坏，不证明来源真实、合同有效、全局没有重复或已经专业审核。**

## 原校验与连续历史

打开时复用原项目、原恢复档案和原封套完整解析。来源事件必须保持业务ID、封套ID、历史来源、账本与所有归档原文，只将来源修订加一；用原 `updateFeeEnvelopeSources` 重新产生并逐字对照结果，同时重新计算五类来源指纹和原待办。事件从原恢复档案中的封套开始连续衔接，最终必须到达包内当前封套，不能删除中间历史或拼入其他业务。

若有本副本的新费用应用，原完整备份提供它前后的封套桥接。核对原回执与账本前缀、原归档保留、来源、事务ID、新增／引用数量及原引擎前后金额，不执行其中补丁。旧已有回执和退休费用编号继续由原封套验证；历史未知保持未知。此版本明确支持本副本0或1次新应用，更多应用会拒绝，不截掉更早备份冒充完整交接。

## 限额及资源

外层完整JSON最高64 MiB、5或6个内嵌文件，来源记录最多64条且原独立审计预算仍为64 MiB。序列化前按实际JSON转义后的UTF-8字节预检，不能把未转义文本总量当最终大小。超过外层上限会明确拒绝，保留当前数据与原交接方式；这并不保证64条历史都能装入一份包。

原应用备份的压缩载体仍是原0.1、gzip/base64协议，编码最高64 MiB、展开最高256 MiB。读取使用原生有界流，逐块限制实际展开量并核对声明字节、严格UTF-8及JSON，再验证应用事件。没有新增压缩协议或改变原128／256／48／64 MiB预算，也未测得容量提升或峰值内存改善。

## 明确选择与失败保持

准备与选择只是候选；下载必须明确选择“下载内部项目包”，读取必须另选“打开独立只读视图”。候选私有身份与当前业务所有者、代次和检查点绑定；复制JSON、跨容器、重复操作、输入ABA与关闭均不能恢复执行资格。准备期间不允许重叠文件任务；逻辑取消立即返回，底层任务结束前仍占用物理槽。

新业务输入会使旧文件候选失效。文件读取、校验、准备和交付失败保留当前项目、费用、回执、原档案和旧只读视图。写入取消不会重新应用费用；原生下载一旦发起便无法撤回。浏览器锚点只返回 `DOWNLOAD_STARTED`，不声称操作系统已完成保存；`SAVED` 仅供明确返回完成的适配器，本轮没有测试操作系统保存对话框。交付后的显示失败不会回滚已发起的下载。

## 只读权限

只读打开将经完整校验的摘要安装到独立文件阅读槽，不触碰产生它的业务会话、原只读会话或正式页面DOM。原候选、确认、付款及客户字段和待执行补丁只保留为原始档案，均不转成新的执行资格。包内固定零费用写入、无导入／确认／客户权限；只读视图可显示包内已有费用应用次数，但打开动作本身不产生费用。

包含内部成本和历史，不是客户文件；客户HTML／Excel／PDF仍走已有公开字段投影和新的客户核对。当前原型没有正式入口、完整表单切换、自动草稿写入或业务重开。下一阶段目标及发布门槛见[开发计划](development-stages.md)，实际验证与边界见[验收](fee-recovery-package-validation.md)。
