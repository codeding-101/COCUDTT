# 明确期间汇总与舍入：实现前设计

第二十七轮，2026-10-13。**设计与独立验收基准已完成，运行工具尚未启用自定义期间，付款格式仍最高1.4。** 本文中的1.5、PERIODS及新字段均为后续实现方案；不能据此创建当前可导入的付款文件。

## 先分开三个概念

| 概念 | 当前或拟采用的事实 | 不能推定的事实 |
|---|---|---|
| 计算分段 | 本金/新利率的生效日改变计算输入；现有引擎按其分段 | 生效日就是结息日、应付日或实际扣款日 |
| 明确计息归集期 | 用户按合同或内部假设填写一组起止日，归集期内未舍入利息 | 期间已被银行认可，期末已确认债务或已资本化 |
| 付款/实际清偿 | 现有付款计划为独立约定输入；实际到账仍需单据 | 归集金额已经支付、期末本金自然归零或资金成本自动计入贸易利润 |

设计参考[FpML官方PaymentDates说明](https://www.fpml.org/spec/fpml-4-3-11-rec-1/html/fpml-ird-4-3.html)：其计算期间与付款日期分别描述，一个付款金额可以关联多个计算期间。这里仅借鉴日期分层；该文档属于金融衍生品数据模型，不作为银行贷款结息、贸易税法或本工具合规认证的依据。查阅日期2026-10-13，未据此推定任何统一银行政策。

首版拟显示“按明确期间汇总后舍入”，使用“计息归集期”表达模型范围。只支持一个主体、单币种、明确ACT/360或ACT/365F的非负单利；融资利息与机会成本仍分别说明。合同按日复利、付息后资本化、最低收费、跨币种、业务日调整及实际利息扣款继续不支持。

## 首版输入与就绪条件

拟新增`funding.period_schedule`，仅在显式升级后的付款1.5解释。外层结构允许未完成草稿；以下业务条件仅在选择PERIODS并应用舍入时必须全部满足。

| 字段（拟议） | 规则 |
|---|---|
| status | UNCONFIRMED / PROVIDED；未知不当作没有期间或按整期 |
| reference | 整体期间划分的合同或内部假设依据，应用时非空 |
| periods_confirmed | 用户明确确认本次归集范围与各期边界，默认false；与旧intervals_confirmed分别保存 |
| periods | 按用户列表顺序填写，不自动排序；最多100期 |
| periods[].id | 非空、唯一内部ID，删除后不用于重绑其他期 |
| periods[].start_date / end_date | 有效YYYY-MM-DD，含起、不含止，正长度 |
| periods[].reference | 本期起止与尾期处理依据，应用时非空 |
| rounding.scope=PERIODS | 每期先精确汇总、舍入一次，再相加；TOTAL/INTERVALS原含义不变 |

正天数时：首期开始必须等于资金起始日，各期首尾连续，末期结束必须等于测算截止日，禁止缺口、重叠、越界、零长度、重复ID及错序。不得自动补齐首尾、月末、节假日或“最后一期”。零天数时：只有用户明确填写的空期表可就绪，零个归集期、金额零；仍核对其他资金条件及当日事件，不能自动删除错误零长度期。

若合同实际结息期末在测算截止日之后，不能将该未来期末直接录入本模型。用户须明确选择完整测算区间，或按内部应计假设显式定义短尾期并注明依据；短尾期结果不叫“已结息金额”。首版不同时生成实际银行账单与内部应计账单。

金额步长、舍入方式、时点及依据沿用原显式字段，不按币种推定。归集期不自动生成付款日期或银行费，也不凭CIF、TT、信用证或付款比例确定。本期清偿若改变本金，须另外录入有依据的本金事件；未建模的利息抵本金、代付或保证金不得自动净额处理。

## 精确计算与边界日

1. 校验原资金、本金和利率模型，保留原始计算分段及结果。PERIODS不能通过先调用旧INTERVALS舍入再汇总实现。
2. 取每个原计算分段与归集期的日期交集。交集天数为正才计算片段，不能用整段近似小数按天数比例再分摊。
3. 每片段直接由原十进制本金、实际年利率、整数天数及明确年基数重建精确分数，按期求和；不把256位循环小数或12位展示值作为舍入输入。
4. 每个归集期按明确步长与HALF_UP/HALF_EVEN/DOWN舍入一次；最终相加，不再次舍入、不补尾差、不将利息加入本金。
5. 同日事件沿旧列表顺序处理，期初生效的本金/新利率影响当日起日，归入后一期间；截止日事件仅审计，不多计一天，也不新增空期。

应满足：各期精确原值之和=整个测算期间原始精确单利；各交集天数不遗漏、不重复；新增仅作归集的切点不改原计算分段数量、期末本金或利率。**即使切点恰好等于本金/利率事件，也须独立期间依据。** 期末事件不证明本金已归还，明确零年利率不等于缺利率。

示例：6 USD、36%、ACT/360、3天，同率事件形成三个一天计算段，原值均为`0.018=9/500`。若归集表只有一期，HALF_UP/0.01得到0.02；三期各一天得到0.03；先两天、后一天得到0.01+0.01=0.02。删去同率事件时，仍可在原单段中按明确期间切分，原单利不变。各期0.005时，HALF_UP两期合计0.02、HALF_EVEN两期合计0.00；原值均0.01，不补成合计后舍入的0.01。

## 确认失效与并发操作

| 操作 | 拟定确认行为 |
|---|---|
| 首次启用期间字段、切换舍入层级、重绑定交易 | 舍入应用回待确认；新期间确认false；旧逐区间确认不得继承 |
| 修改资金起止日、主体、币种、年基数、融资/机会成本 | 期间确认false，保留原期表作为待核对输入 |
| 编辑/增删/改序本金或利率事件，修改期初本金或年利率 | 期间确认false；不得因日期不变自动保留金额分摊确认 |
| 编辑/增删/改序任一期，修改整体/本期依据 | 期间确认false；不能用新相邻期自动填补缺口 |
| 修改金额步长、方式或舍入依据 | 舍入应用回待确认，期间确认false；重新核对整套假设 |
| 只展开审计、导出、调整窗口宽度 | 不改变确认、输入或自动草稿 |

新字段必须接入现有读取撤销、导出前快照和资源忙碌机制。编辑后不得沿用旧异步读取；JSON、内部HTML/XLSX均保存同一次输入和确认快照。手动异常备份保留原始1.5输入；只读恢复检查与重试须同一轮支持，不能先启用新格式而漏掉恢复路径。以上是新模式的拟定规则，不宣称当前1.4全部遵循此表。

## 兼容、审计与隐私

拟通过1.4独立启用1.5；升级保留旧输入及未知扩展，资金/舍入应用回待确认，期间对象空白待确认，两个边界确认false。若旧`funding.period_schedule`重名，拒绝升级，原文件保留；1.0–1.4旧容器不解释此未知扩展，另存原版本。新建付款仍1.1；项目0.8不加入独立付款资料。旧1.4的逐区间模式继续原语义，不能静默改成按月或按新期表。

审计拟新增：整体/各期依据、确认状态、每期范围和天数、命中的原段ID/交集、每片段本金和利率来源、每期精确原值与舍入调整、按期合计、合计后舍入及两者差额。原始计算段和原值继续独立保留；不把内部近似展示称为完整精度。

内部HTML/Excel保存上述审计与输入；XLSX仍为生成时快照。客户公开白名单不读取期表、金额或依据，界面错误不暴露私有路径。保存新付款格式不标记项目已保存，也不写用户客户确认或自动草稿。
