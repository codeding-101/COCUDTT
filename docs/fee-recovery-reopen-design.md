# 恢复清单与独立已提交资料会话
2026-10-27，第100轮。此实现属于开发原型，**尚未接入正式工具，也不是完整工作台重开**。第99轮共享方案不作为容量修复接入的结论继续保持。

## 本轮具体增加什么
[原恢复格式0.1](fee-recovery-format-design.md)继续负责版本、原文、摘要与展开预算校验。[新还原器](../tools/fee-recovery-reopen.ts)在它之后生成清单，列出六类已提交资料、展开大小、十组新所有者、输入待办、历史记录和不可恢复项。只有同实例、当前代次的清单，在用户明确选择后，才能打开独立会话。

独立会话使用现有五类控制器及三个工作区，加上项目和工作流，共十组真实状态所有者。全部准备和重新计算先于会话切换。它们的环境关闭存储、文件写入和通知；构造和安静安装不调用原工作台方法、不应用费用。原文、未知扩展、历史与完整备份仍保留在冻结档案中，活动状态采用新值。

| 资料 | 会话处理 |
|---|---|
| 已提交项目、账单、配对、成分附件、精度文件、封套 | 各自按原业务解析器校验；重建后与六份原来源逐字核对 |
| 汇率输入与保留簿 | 保留原行和簿；明确核对行键、簿投影及项目汇率一致，不用行覆盖冲突 |
| 文件证据、保存时间及脏标记 | 保留档案事实，不产生新的物理保存证明 |
| 已应用费用及回执 | 从已提交资料读取；旧应用记录与备份只归档，不重放补丁 |
| 候选、确认、客户勾选、读取令牌与Promise | 不恢复执行资格，客户须重新核对，运行代次重新建立 |
| 未提交输入、坏数字缓冲、未读文件 | 清单阻断本轮打开，不自动采用；原文/元数据保全，要求处理或重新输入/选取 |
| 敏感性、付款及客户输入、视图与未知UI历史 | 完整档案保留；本轮不声称重建所有表单、视图、结果缓存或原DOM |

[清单面板](../tools/fee-recovery-reopen-panel.ts)使用原生文件输入和明确打开/取消按钮。文件读取与解码分别有代次保护；取消后迟到的File.text结果不能打开会话。显示文本转义，未知金额不会补零。入口仅由[专用浏览器桥](../tools/fee-recovery-reopen-bridge.mjs)挂载到隔离测试页面，不进入生产构建。

## 失败保持与边界
准备期间保留当前会话引用。坏格式、业务解析失败、六来源重建不一致、部分新控制器准备失败、取消、外部终止、迟到、ABA或重入均不切换；已发放清单的JSON副本、其他实例与重复确认无效。每次恢复重新建立所有者，旧私有身份不能跨档案传递。

只读会话可以用原预览器检查当前已提交来源，不提供费用提交或文件交付入口。完整恢复后重新准备候选、明确应用一次费用/回执、正式导出、客户隔离、未提交UI复核以及生产页面切换尚需下一轮验证。**十组所有者的建立不等于完整运行恢复。**

原128 MiB聚合、256 MiB原载荷、48 MiB明文和64 MiB最终文件上限分别保持。原4/8笔限制和第99轮超限结论未改；本轮不复跑1/4/8容量测量、不主张容量、耗时或峰值内存改善。真实手机、真实业务资料及人工专业复核继续暂缓。见[本轮验证](fee-recovery-reopen-validation.md)和[后续阶段](development-stages.md)。
