# 来源适配兼容矩阵与接入保护

2026-10-21，第八十九轮，承接[页面来源适配](fee-source-adapter-design.md)。本轮完成可复现的开发诊断；发现普通JSON的边界反例，正式`app.ts`继续原捕获函数。没有接入新模块，也没有自动失败回退。

## 四个观察阶段

[诊断器](../tools/fee-source-compatibility.ts)接受原所有者、受信任同步的原捕获回调和明确来源读取器，分别记录：

1. `legacy_capture`：真实页面原`captureCurrentFeeWorkbench()`是否返回完整捕获。
2. `retained_parse`：使用[原严格解析器](../src/data/fee-envelope-json.ts)单独解析其`retained_json`。原[交易入口](../src/data/fee-workbench.ts)也有这一层；不能把外层字符串捕获成功当作该层通过。
3. `source_frame`：[独立适配模块](../src/ui/fee-workbench-source-adapter.ts)是否返回完整冻结帧。
4. `reconstruction`：帧能否重建原完整捕获；两份捕获都成功时，比较完整JSON文字，包含原保留文字。

每层分别为`ACCEPTED`、`REJECTED`或`NOT_RUN`；未知或未执行不填false、零或空数据。观察前后检查原所有者私有检查点；变更后停止后续读取，标为`STALE_OBSERVATION`。诊断本身不签发可跨调用使用的有效性、候选、恢复或业务确认资格。

结果固定`production_action:KEEP_ORIGINAL_CAPTURE`、`financial_writes:0`、`application_readiness:NOT_TESTED`，且不含来源原文和文件名。错误仅导出明确固定代码，未知异常统一为`SOURCE_READER_REJECTED`；不读取异常的message访问器。回调必须受信任且同步，诊断器不能回滚回调自己造成的外部副作用。

## 已证实的普通JSON差异

[原生浏览器矩阵](cases/fee-source-compatibility.json)运行未改动的真实`app.ts`。扩展放在现有敏感性输入的未知字段，不调用重算、来源采用或费用应用入口。

| 反例 | 原外层捕获 | 原保留解析 | 新帧 | 原因 |
|---|---|---|---|---|
| `depth_29` | 通过 | 通过，叶深31 | 拒绝，叶深33 | 新帧多两层结构包装 |
| `depth_30` | 通过 | 通过，叶深32 | 拒绝，叶深34 | 同上，超过原32深度 |
| `nodes_frame_over` | 通过 | 通过，299956节点 | 拒绝，300001节点 | 新帧包装与附加投影占节点预算 |
| `nodes_retained_at` | 通过 | 通过，300000节点 | 拒绝，300045节点 | 原保留层合法并不表示帧能容纳 |

本次默认页面基线是保留数据314节点、帧359节点；45节点差只属于该基线，不是所有项目的常数。构造用每次实际基线计算长度，完整记录目标和实际节点数。`nodes_frame_at`在帧300000节点时通过且逐字一致；原保留300001节点、扩展深31/32等则在原保留层已拒绝，另行记录。

四个反例只证明捕获/原保留解析边界差异，**没有证明完整项目、来源、历史、FX或费用交易已经合法可提交**。本轮未打开交易候选，不能把`retained_parse:ACCEPTED`当作交易就绪。

## 普通JSON与JavaScript对象分开

矩阵共42场景，21场景完整捕获逐字一致，覆盖Unicode、组合/分解形式、未解析坏原文、标记样式键、键序、null原型、重复引用，以及项目、五个控制器和三个工作区的未知扩展。重复引用按展开后的树计节点，不共享可变持有者。

另有14个不受支持JavaScript场景：undefined、函数、symbol值/键、不可枚举属性、稀疏数组、自定义原型、循环、NaN/Infinity、孤立代理码元、访问器、toJSON。旧JSON.stringify可能丢弃或转换这些值；新严格复制会拒绝，不能把这类差异统称为普通JSON兼容反例。旧路径访问器/toJSON各执行一次，新适配执行零次；这些受控计数副作用与“费用无写入”分别表述。

## 接入门槛

[CI核对脚本](../tools/check-fee-source-compatibility.mjs)检查记录结构、四个固定反例、正向覆盖、源文件指纹和生产隔离。42场景费用/回执/客户确认及所有者状态保持；比较期每场景读取存储20次、写入0。场景设置与还原发生在比较之外。

已知差异尚未关闭时，`app.ts`不得导入新来源适配或开发诊断；生产`src`不得引用诊断。正常离线产物与上一轮完全相同，测试桥接只在专用Vite服务器内存追加。CI只核对已提交浏览器记录与指纹，不冒充在CI重跑了原生浏览器。

下一阶段设计与原保留数据一致的语义预算，明确结构包装如何计入内部帧，先用四个反例验证方案。不提高原128MiB/300000节点/32深度，不丢未知扩展或绕过原校验。边界关闭之后才逐步接入只读捕获，复验预览、候选、确认时重准备、恢复和客户隔离；完整浏览器与同条件1/4/8通过前不宣称容量变化。
