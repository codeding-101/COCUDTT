# 应用后新记录与再次报价验收

2026-10-20，第八十四轮。

本轮沿用现有控制器和文件格式，把第八十三轮停止在悬空目标的流程继续走完。界面在最近应用提醒下提供五步人工交接说明，仅定位既有面板，不解析文件、不重绑、不提交、不记录来源或客户确认。同页重开文件保留真实的应用历史提醒；页面刷新后不凭文件或缓存内容编造本机刚应用提示。

## 业务与历史边界

- 先备份历史，移除旧选择并保留退休映射；明确核对已有费用引用，建立新映射。
- 成分附件重绑后旧目标仍悬空，须明确删除并新增新目标记录；新编号不同，旧编号退休，三项确认初始为null。税务、抵扣及海关来源分别重新核对，未知不当零。
- 精度在成分最终确认后重绑完整双来源，删除失配政策，再明确选择新成分、通道和政策。新记录不继承旧政策确认；政策确认不证明业务或税务资格。
- 明确更新封套来源，保留历史与首份回执。完整检查及单独整批确认后，已有113 USD仅新增一份引用回执；费用数量、原币原金额、买方总支付和卖方利润保持，未知利润仍为null。
- 费用资料核对不自动改动实际合同报价。客户公开内容须重新确认，按既有白名单生成HTML、Excel、PDF；内部来源、成分、退休编号、回执及利润不进入客户文件。
- 六类文件分别保存，恢复备份不成为导入或重放权限；下载发起不证明本机已保存。

## 专项自动化

[5项连续测试](../tests/post-application-requote.test.ts)使用原十组状态参与者，实际应用后更换成分和政策，分别验证新确认、缺失抵扣/政策确认阻断、正式JSON重开、旧候选因后续编辑失效及原备份保持。软件夹具的USER_SUPPLIED资料为合成测试条件，不是实际凭证或专业审定，不修改可下载EXAMPLE练习包。

[原生浏览器连续流程](../tools/post-application-requote-browser-check.mjs)通过原面板与确认按钮完成全过程；六类正式JSON与客户HTML/XLSX/PDF使用实际浏览器下载。正式文件逐字节对照当前原文并经现有解析器验证，再通过原文件输入重新打开，保留两份回执并重置客户公开字段与确认。文件输入使用DataTransfer替代手选文件；工作台检查备份使用保存API替身；上述九份正式与客户下载不使用保存替身。PDF在此检查实际下载结构与元数据，全文/版式继续由原PDF和客户视图回归覆盖。

自动化仅覆盖桌面浏览器和四种模拟屏宽；真实手机、实际业务单据及专业人工复核继续按用户要求暂缓。

完整回归、原生检查和发布结果在本轮发布时核对，不以测试数量代替实际业务验收。
