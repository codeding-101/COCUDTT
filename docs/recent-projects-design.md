# 最近项目：手动快照与本机存储边界

2026-10-16，第五十四轮设计及独立模块基线。第五十五轮已按本文门槛接入手动界面，见[界面验收](recent-projects-ui-validation.md)。以下“下一轮”描述的是当时的接入要求，不代表当前仍无入口；启动仍不自动读取/创建缓存。

## 范围与容量

最近项目是用户主动加入的内部项目JSON快照，不是文件句柄、自动版本历史或备份。最多3份，每份原始项目文本UTF-8不超过256 KiB，整个序列化缓存UTF-8不超过1 MiB。字符长度先检查，再检查UTF-8字节；这些是应用上限，不保证浏览器配额足够，浏览器实际计量可能不同。

保存内容是当前可导出的完整项目JSON，包含采购成本、来源、合同及未知扩展，可能含客户资料。已知的独立付款计划、账单/配对及编辑草稿、客户公开文字和界面偏好不由本模块收集；未知项目扩展原样保留，不能承诺其中没有上述敏感内容。缓存只在同一浏览器和来源内可见，清理站点数据/私密模式退出可能丢失；file与HTTPS来源之间不保证共享。容量满时拒绝新增，不自动删除、替换同名项目或合并内容。

只有再次明确点击加入才捕获新快照；打开、修改、导入、另存、切换模式和生成报告不自动加入。完全相同的项目文本复用既有条目，不更新时间、修订或排序；这不是业务身份去重，不同文本即使同名也可分别加入。顺序是加入顺序，打开不更新“最近使用时间”。

## 内部格式

单独键`trade-cost-engine:recent-projects-v1`，信封为`kind=COCUDTT_RECENT_PROJECTS`、`version=1.0`、安全整数修订号和条目数组。每条只有不重复的ASCII标识、规范UTC加入时间及`project_text`字符串。加入时间不替代项目/报价/税务日期；标识也不代表真实订单或业务身份。

存入后修订从1开始；键缺失时返回内存中的空列表、修订0，不立即写盘。信封/条目不接受未知字段或未来版本，保留完整原文供备份；项目文本按已有项目解析器校验，保留其原始版本、空输入、精度字符串及未知扩展。读取或取出快照不把解析后的规范化内容写回缓存，也不计算利润、税款或确认来源。结构通过不证明可计算或业务成立。

整体校验成功后才提供列表，任一损坏条目都不被静默跳过。添加/删除拒绝损坏、超限和未来格式；读取保留原字符串，后续界面可下载原文，再明确丢弃该缓存。正常删除只移除指定条目、增加修订；清空只删除这个键，不调用localStorage.clear，也不清理其他业务资料。

## 写入与冲突

模块只接受注入的Storage接口，构造无副作用，没有默认localStorage或后台监听。调用者提供上次读取的完整原文作为租约；每次变更前重新读取并逐字比对，过时事件拒绝。候选先完成容量、结构和ID检查，再写入一次或删除一个键，随后读回比对；只有核对成功才返回操作结果。

配额不足、存储被禁用、删除失败、读回失败或被其他页面改写时返回明确错误，不显示成功，不擅自回滚覆盖别人写入的内容。原文不同即视为冲突；该检查不是跨标签原子CAS、锁或多端事务，不能阻止两个页面极短时间内同时写入。下一轮界面应监听该键的storage事件撤销准备操作，但仍说明这是本机便捷缓存，必要资料须另存JSON。

## 下一轮界面接入门槛

1. 默认不创建缓存键；用户勾选完整内部副本范围后手动加入。必须先提交当前输入；若汇率行不完整或重复会被普通项目投影忽略，应阻断加入，保留原草稿并提示修正，不能静默丢行。
2. 列表区分可用、损坏与存储不可用；长度受控的纯文本标题、时间、术语/币种和大小，内容须转义。模式偏好、恢复备份和客户文件不带该缓存。
3. 打开先准备并展示替换范围，再明确接受后执行；同时绑定缓存原文/条目标识和当前完整编辑状态。准备后编辑、打开其他文件、迟到读取或storage事件均须撤销旧接受，防止覆盖新输入。按原项目导入流程重算/重置临时资料，不更新业务日期、税率或来源确认。
4. 删除/清空须明确对象和影响；损坏/未来缓存可导出原文，明确丢弃后清空。写入失败不得改变当前交易/保存状态或自动改用另一套隐藏缓存。用户取消或存储冲突可重新读取重试。
5. 独立验收真实键盘/鼠标、未提交输入、存储错误与跨标签事件、旧格式/精度/内部资料隔离，以及320/390/768/1440模拟宽度；通过后才接入和发布该功能。

真实手机、实际业务资料与人工专业复核继续按用户安排暂缓。计算、项目格式、Schema和原有自动草稿不在本轮变更范围。
