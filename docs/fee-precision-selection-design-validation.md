# 第六十五轮：精度选择记录设计验收

2026-10-18。交付[独立选择记录设计](fee-precision-selection-design.md)、[固定合成状态案例](cases/fee-precision-selection-design.json)及[独立检查器](../tools/check-fee-precision-selection-design.mjs)，加入Windows/Linux CI。没有新增生产解析器、Schema、模板、控件、草稿键、确认入口或费用写入；已有精度API仍独立于运行工具。

## 本轮可执行证据

- **81个固定有效案例**：完整配对/成分附件原文和排版变更失效，来源回执变动保守失效；政策文本、汇率来源和日期的局部失效；未知原值/未明确选择留档、明确零可记录；来源重绑保留原记录、另存身份和新业务空记录；局部回执/重复记录幂等、删除退休及新ID替换。
- **60个固定拒绝案例**：版本/身份/指纹、重复槽位/ID和退休ID复用、外层正确指纹仍内嵌配对不一致、非既约/越界分数、错误政策/商业与海关目的、FX日期/币种/零率、不明确/未知/失配原值的新回执、完整租约失效、跨业务重绑、修订上限与结构限额。
- **50个来源单叶变更**：简化完整配对及附件，包括扩展、业务待办、原成分表、来源及回执，任一变更都不能沿用政策回执；原文空白/键顺序另外有固定案例。
- **51个basis单叶变更**：文档/记录身份、双来源指纹、原组件身份、完整目标、通道/币种/精确原值、政策/依据/汇率及日期均绑定；回执本身和外层修订不进入basis，避免确认相互循环。
- **4个固定SHA-256向量**：标准空串/abc及预先写入的合成双来源指纹。固定状态预期不由检查器反生成，输入保持不变。

81/60/50/51/4均为独立设计证据，不加入应用测试总数。检查器使用缩减配对/附件及预先给定通道表，不导入生产文件或数值API；保存/打开/草稿状态是协议模拟，没有真实存储、文件系统或浏览器动作。不能据此声称正式JSON解析、真实原成分重算、性能、客户真实文件隔离或费用事务已经完成。

## 本轮明确的边界

政策回执只记录算术假设，不能确认成分税务来源或应用资格。原`CORE_PRECISION_LOSS`、原金额失配、包含/重叠和税务待办完整保留；明确零和未知分别处理。即使所有政策都已记录，也没有可应用/已合规状态。

首版拟议独立1.0，单原成分/通道唯一槽位，ROUND/FX/UNRESOLVED；不持久化可信候选或审计缓存，不把合计候选拆回单行。双份配对原文必须一致，源附件任何字段变化（包括仅来源回执）使全部旧政策待复核。重绑不改历史original/target/choice；旧FX核对日可保留，和新账单日期不同则不能记录回执。

64MiB外层/24MiB附件/10MiB配对、48活动/500退休、32深度/300000节点等仅为拟议工程限额；本轮边界向量未分配相应大文件，也未证明接近限额时的性能。SHA不是签名、真实性或跨标签事务锁。
