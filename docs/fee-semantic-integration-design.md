# 只读语义捕获接入设计

2026-10-22，第九十一轮。将第九十轮已独立验收的语义根读取迁入正式工作台，避免包装层改变原始 JSON 的深度和节点预算。

## 读取与业务提交分别处理

[正式模块](../src/ui/fee-workbench-semantic-capture.ts)按原二十项保留根校验，额外来源文档各自在自己的根校验；重建完整捕获仍执行原 128 MiB 限制及原保留文本解析。模块沿用原型实现，仅调整生产导入路径。固定协议字段不提供来源采用、候选、确认或恢复权限。

[app 的显式连接](../src/ui/app.ts)读取十组真实生产者及 DOM/存储观察，不展开含 DOM 引用的 workflow。未初始化项目不读取；未提交控件、文件读取代次、FX 行与保留 books、保存原文和时间分别保留。存储缺失、空字符串和读取失败仍可区分。

每个同步读取前后和最后检查所有者修订；A→B→A 也失效。受信读取函数的外部副作用不能回滚，嵌套修改仍须 touch。已有预览私有身份、确认时重准备、一次根替换和提交后恢复均沿用原实现，没有通过序列化数据恢复资格的入口。

## 独立参照与发布门槛

[历史捕获参照](../tools/fee-legacy-capture-oracle.mjs)固定第九十轮 app 的函数，只在专用测试服务器内存中追加。[新矩阵驱动](../tools/check-fee-semantic-integration-browser.mjs)实际调用当前 app 连接，与历史函数对照，不能用两次调用新模块代替旧参照。四个旧反例、十四种不支持 JS 值和原语义边界分别观察。

旧 [0.1 矩阵](cases/fee-source-compatibility.json)、[补丁矩阵](cases/fee-source-compatibility-patch.json)及 [0.2 原型矩阵](cases/fee-source-semantic-budget.json)原样保留。历史检查仅允许 app 指纹和离线产物由本轮新证据资格连接；其余历史源指纹继续精确检查。[接入门槛](../tools/check-fee-semantic-integration.mjs)另核对新源指纹、完整原生流程记录及产物，没有删除旧负例或放宽 JSON 预算。

发布须通过完整单元回归、全部 46 套原生浏览器流程、客户资料与正式文件交接、模拟窄屏、双平台 CI，以及公开产物哈希核对。测试桥接和历史参照不得进入生产产物。
