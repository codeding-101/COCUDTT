# 新建费用提案编辑设计（第三十九轮）

2026-10-15。沿用独立配对1.0、选择0.1及项目0.8/0.9；本轮仅编辑假设和核对来源，不应用费用，不改变计算规则或公开网站。

## 编辑与提交

未填完的表单是独立、本地的0.1编辑草稿，不冒充结构完整的CostItem。一次编辑绑定配对身份、修订及完整内容键；配对或当前项目/账单变化后拒绝提交，不静默改绑。用户须放弃编辑、捕获当前修订再重新开始。打开/新建/清空/捕获/另存配对前须提交或明确放弃编辑，避免导出旧快照却以为包含表单。

新建目标仅生成UUID元数据，不填金融条件。用户明确选择账单行并点击取用原币事实，复制该行精确金额、币种、收费类型/范围及当前项目本位币、术语。复制不确认来源、不推定承担方或税务；表单明确选择类别、节点、发生原因、合同单方承担、支付方、经济承担方、含税口径、海关加计/排除及汇率类型。只支持FIXED、USER自定义、当前单术语、独立且未含报价的提案，这些限制需用户明确接受。

已保存的新建提案可以载入编辑；不支持编辑的可选字段原样保留，继续列出包含、非固定计费等待办，不静默清理。已有费用引用不转成新建提案。表单不完整、坏枚举、重复/已退休目标、无效行及超限均拒绝整笔提交；保留原快照和草稿。合法但业务待核对的完整选择可以保存，仍只读且不得应用。

## 来源与精度

完成提交后单独点击“确认当前提案来源”，调用已有完整项目＋账单＋选择快照校验；来源文字、有效期、核对日期必须填写，示例来源不能直接确认。任何费用字段、说明或来源元数据变化会将旧确认降为UNVERIFIED；保存旧快照不代表新事实已确认。快照仅记录用户假设，不构成专业认证。

原金额始终为十进制字符串，不转Number、不舍入。超过核心6位的非零尾数继续显示CORE_PRECISION_LOSS；账单18位精度保持，本轮不提供舍入或清除候选的捷径。

## 保存、恢复与边界

编辑草稿使用独立浏览器键和严格字段白名单，恢复后仍按原修订核对，不自动提交。坏草稿原文保留；存储失败时保留内存并提示。配对文件只包含已提交选择；提交或放弃编辑后才允许另存。异常内部备份可附编辑原值及草稿原文，检查仅验证结构，不自动恢复或改变费用。旧6/8/10部分恢复文件保持兼容。

界面字段转义、白名单事件、焦点恢复、冻结读取竞态、客户导出隔离和320px模拟操作均需验证。业务复制、带依据的包含/候选解决、项目映射新版本与原子费用应用留待后续阶段；真实手机、真实账单及专业复核继续暂缓。
