# 包含、重叠候选、含税与精度：实现前设计（第四十一轮）

2026-10-15核验。本轮交付设计、独立手算/反例和现状回归，不新增运行入口、费用应用或有效文件字段。拟议配对1.1/核对计划0.1均未启用；当前配对1.0仍拒绝新版本及未知活动字段。

## 现状与不能混用的口径

| 路径 | 当前行为 | 后续接入约束 |
|---|---|---|
| `engine/inclusion.ts` | 报价内含避免买方报价外重复支付；卖方实际费用仍属成本；父项包含排除子项；疑似THC/同组只告警 | 不能以“已含报价”删除卖方费用，也不能据此排除海关加计 |
| `engine/scenario-costs.ts` | 先筛术语费用；活跃费用不能引用停用父项/基数 | 核对与应用使用同一活跃集合；旧方案的确认不覆盖新方案 |
| `engine/tax/dutiable-value.ts` | 中国模式用独立海关汇率；加计/排除与商业报价分别处理；父项包含避免重复；各组成金额按分处理 | 不用商业汇率或报价内含旗替代海关依据；不同计税成分不能靠单一金额表达 |
| `engine/analyze.ts` | 中国模式货值声明包含运保费时阻断，要求先明确净货值 | 不把整笔CIF成交金额当净货值后再加运保费 |
| `engine/pricing.ts`、`domain/decimal.ts` | FIXED/ACTUAL金额规范化至6位小数；费用的tax_included/tax_rate_ref没有拆税运算 | 这些字段当前仅记录，不能宣称自动价税分离/抵扣；应用前必须明确口径 |
| `engine/aggregate.ts` | 买方扣除的可抵扣VAT仅来自归买方的衍生进口VAT | 不把每笔服务/运输发票税额自动当成进口VAT，不能重复扣抵 |
| `engine/container-bill.ts` | 独立18位精确金额；同方向/标签/箱号/模式及期间列潜在重叠，含免费日交集；不跨行合计 | 无候选仅表示该筛选范围没命中，不证明全局无重复；不同scope标签也可能描述同一箱/期间 |
| `engine/container-cost-proposal.ts` | 完整来源/快照核对、原币精确匹配；6位精度损失、已有包含与候选继续阻断 | 没有费用应用函数；来源确认不能消除其他待办 |

现有计算/含税字段限制由新增现状回归固定。回归描述的是当前行为，不证明这些字段已具备未来所需的税务功能；新语义必须显式版本化，不能在旧文件中悄悄改变金额。

## 已核对的官方依据及范围

核验日期为2026-10-15；仅核对下列相关条文，不宣称完成全部现行法规审查或实际申报验收：

- [财政部公布的《关税法》](https://www.mof.gov.cn/jrttts/202404/t20240429_3933790.htm)，第二十四至二十六条：计税价格考虑交易及运保相关费用；到境内输入地点起卸前后及列明税费的处理有区别。设计据此要求费用实际范围和单独列明依据，不能只凭“目的港费”“滞期费”名称或Incoterm归类。
- [税务机关公布的《增值税法》](https://shanghai.chinatax.gov.cn/zcfw/zcfgk/zzs/202412/t474694.html)，第七、十四、十六、二十二条：价外税、进口组成计税价格、扣税凭证和不得抵扣情形分别规定。进口VAT与服务发票税额不是同一笔税，含税旗不证明可抵扣。
- [《增值税法实施条例》](https://shanghai.chinatax.gov.cn/zcfw/zcfgk/zzs/202601/t478908.html)，第十一、十二、十六条：凭证规则与合并定价换算分开。下述税额拆分例只验证给定税率的算术，税率/征收率、纳税人和凭证适用性仍需具体依据；不预设任何费用通用税率。

成交价格调整、关联交易估价、具体THC/滞期/滞箱税务认定、多国家税制、服务税实际抵扣、退款红字及复杂税种不在首轮自动化范围。原进口模型的资格、申报日期、海关汇率和税率核对继续独立生效。

## 三条金额通道

后续核对要分别展示：①应付/收付原币总额；②经济成本及有依据的可抵扣税额；③海关加计或排除的成分。不能把同一个`amount`同时当含税应付额、不含税成本和海关加计额。

合成示例：应付113，给定税率0.13，算术净额100、税额13。没有抵扣依据时经济成本仍为113；在明确满足条件且税额13有凭证的假设下成本才为100。海关加计额仍需另外依据，不能从“可抵扣13”直接推出，也不能把服务发票VAT再当进口VAT扣除。旧`customs_value=EXCLUDE`是排除该费用的加计，不会自动从已含税费的商品整价倒扣；整价应先拆分并核对。

首轮独立核对模块不实现服务税抵扣或自动拆税。允许记录“保持录入额、不作税务调整”的明确假设并输出待办；`tax_included=true`或未识别税种不能因此成为可应用状态。净额/税额/海关成分拆分、已有衍生进口税与代缴税去重需在后续新版本逐项接入，再考虑费用应用。

## 包含和候选的证据

拟议核对计划按配对完整内容键、术语、账单行/稳定映射/目标、原币及对象快照绑定。不能只绑定金额或用可编辑scope标签作身份证明。来源定位、有效期、核对日、EXAMPLE隔离及修改失效沿用已有规则；确认是用户假设，不是程序或海关认证。

| 拟议结果 | 所需事实与首轮边界 |
|---|---|
| 报价内含 | 当前实际报价/费用及合同定位；只解释支付/成本归属，不自动改海关成分 |
| 父项全额包含 | 活跃且存在的父项、完整覆盖、当前术语和合同依据；拒绝自引用、环、失效父项、部分包含、跨币金额比较和不支持的拆分 |
| 不同收费内容 | 明确服务/箱号/期间及合同依据；保留原候选，记录人工说明；不把程序找到交集说成必然重复 |
| 不同覆盖范围 | 独立枚举箱×选中日可证明该明确范围不交，但不证明其他账单/作业事件没有重复；不同标签/币种本身不构成证明 |
| 未确认/不支持 | 保留待办，禁止应用；不提供IGNORE/强制通过 |

后续候选核对会补充同箱/方向/期间但不同scope标签的反例，以及项目已有费用缺少箱日范围时的保守核对。联合D&D、分开demurrage/detention及THC内含仍保留原数据，不自动相加、扣减或按交集天数分摊。免费日也属于合同覆盖，金额为零不证明可以忽略重叠；混合计费模式/未知截点保留人工待办。

拟议上限：50条意图、单行沿用账单箱/天上限、核对目标总数不超过2000。超过范围整笔阻断，不截断候选后宣称完成；界面可分页，但完整待办数量和来源都要保留。

## 精度和明确舍入

原币金额保留原18位字符串，不经Number。首轮仅接受与核心6位可精确兼容的数值；末尾额外零不算损失，非零尾数继续阻断。不得修改全局Decimal精度、先舍入再冒充原金额，或用两位展示值进入计算。

明确舍入仅为后续设计：单位、方法、层级、合同来源都必须输入。原值、拟入账值和有符号差额并列；差额不自动变成新费用。逐箱逐日/逐行先舍入与合计后舍入可能不同，不能默认选较低者。商业换算6位、人民币计税组成至分及税款至分是不同阶段，不能用一次显示舍入替代全部规则；也不按币种名称推定单位。
