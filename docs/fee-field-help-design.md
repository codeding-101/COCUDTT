# 字段说明组件的独立实例设计

2026-11-03，第120轮，本地诊断候选。

目标是复用现有字段说明组件，先证明两个新副本可以独立操作和关闭，再考虑扩大工作台接入。原组件包含全局 document 查询、固定 dialog/title/content ID 和两个匿名监听器；仅创建第二个控制器不能证明实例隔离。

本轮使用受信、同源的 iframe 文档限定 document 查询范围。专用本机 Vite 只适配带明确查询参数的原模块响应：替换三类固定 ID，并把原 close/keydown 两处注册交给实例创建者的监听器端口。适配前核对原组件指纹，逆向替换必须恢复完整原文；七类帮助文案、转义和控制器业务代码均复用。普通模块和仓库 src 文件不改。

每个完整实例明确登记五项资源：弹窗关闭操作、root click、dialog close、dialog keydown 和 MutationObserver。先预留所有者容量再安装监听器，记录实际原生回调引用。重复绑定保持幂等；复制或跨端口的释放身份拒绝。

关闭前重新核对根、文档、ARIA 关联与关闭确认。停止时先让新回调静默，再尝试实际移除；移除失败保留资源和原回调身份，只能明确重试剩余项。已缓存回调也不能恢复作用。初始化到一半失败时不自动开放组件，保留 DOM 和未提交原文，允许单独核对并关闭已登记资源。

对观察范围内的结构和标识变动，含改后改回，永久使该实例失效，并撤销旧关闭确认；重新核对只授权清理，不使组件重新可用。关闭保留副本 DOM、iframe 和未提交文字。关闭、资源归零与保存完成分别判断。

原工作台只增加诊断读取桥，不包装它的应用监听器。浏览器逐步核对原 root、原生回调引用、业务/文件保存证据，以及原页面继续输入和计算。焦点验证使用真实鼠标、Tab、Shift+Tab 和 Escape；清理副本时保留已经移到原页面的焦点。

同源 iframe 仅用于受信代码的文档和生命周期隔离，不是恶意脚本安全沙箱。本轮没有管理整个 iframe、模块启动过程或全部浏览器资源，也未验证启动取消。完整工作台恢复、原应用整体解绑、最终安装、客户报价授权与源文件保存状态均不由该组件获得。
