## 真实代码核对

新增11项测试，完整99文件3804项。实际调用旧汇总、成分、海关组成金额、提案、边界复核与精度文件API，验证：

- G=113、X=13、E=100和C=40是不同口径；旧服务费汇总只使用单金额，tax_included标记不建立服务抵扣台账。买方服务费不会被误当成已有派生进口VAT抵扣项。
- 相同G按卖方归属计113成本/87合成利润；改成100会变成100成本/100利润，不能声称还保留113应付金额。数字仅为固定合成算术，不是适用税率或财务资格建议。
- 中国模式ADD加计完整113，EXCLUDE排除本项；不能表达部分40，也不从独立C覆盖旧计税价格。测试不新增或认证法规口径。
- 付款人与承担方不同没有自动垫付清偿台账；汇总仍按明确责任决策。
- 已记录舍入政策后，真实提案的CORE_PRECISION_LOSS仍在；没有插入费用。直接向项目插入目标后，原CREATE_NEW提案会提示COST_ID_ALREADY_EXISTS。
- 含税/服务税率引用的旧只读待办仍在，数学拆分不清除原经济金额未知状态。

这些测试验证现状及后续模型必须面对的限制，没有实现“正确应用”或证明全部真实业务场景。

## 独立设计反例

`node tools/check-fee-application-design.mjs`核对六类缩减协议：

| 协议 | 核对内容 |
|---|---|
| MAPPING | G/N/T/X/E/C隔离、未知、完整原值/候选重算、六位精度、FX/币种变化、来源/政策回执、跨付款方、旧问题及未知未来问题保留 |
| LEASE | 项目/账单/配对/成分/精度/账本六份完整原文；只改空白也失配，不靠名字或revision续用确认 |
| DEDUP | 业务/账单/行消费键、同批目标唯一、旧目标/退休目标、只读引用；改mapping/术语/新事务ID不逃逸来源历史 |
| REPLAY | 同一完整计划与后payload不重放；同ID异计划冲突、后状态变化保留历史；坏回执拒绝，新事务仍须完整前检 |
| COVERAGE | 显式箱日相交，scope/币种/联合收费标签不删除候选；缺条件保留未知，无交集不构成金融授权 |
| ATOMIC | 明确确认、整批阻断/重复、修订上限、提交前十个故障阶段及提交后的缓存/渲染/保存故障；旧格式/备份不得隐式应用 |

固定**106个有效场景、36个拒绝输入**；有效场景包含大量“应该阻断”的结果，不是103笔可应用交易。另有**303组构造、6份来源变更、2个指纹向量**。固定预期来自独立手定情形，构造只验证补充性质，不由生产函数生成答案。输入前后逐字比较，检查器不修改输入。

检查器只执行缩减算术、身份和状态判定，MAPPING中的来源状态及上游问题是合成注入事实；没有验证真实完整附件/政策回执或实际支付。ATOMIC为状态协议，不是浏览器指针提交、真实存储/磁盘回滚实现。`UNCHANGED_ORIGINAL_CASH`仅说明数字投影兼容，不是业务ready或应用资格。检查器的生产路径扫描只是防误接入提示，完整旧源码字节比对另外执行。
