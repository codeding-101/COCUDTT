# 完整费用状态的分阶段容量诊断

第九十二轮，2026-10-22。接入只读语义捕获后，按原1/4/8笔合成夹具重新测量。先区别保留语义根、完整捕获、预览、十组候选准备和备份的失败位置，再决定下一项优化。

## 观察范围

[专用服务器](../tools/check-fee-capacity-browser.mjs)仅在内存转换真实app及两个原模块：[绑定](../tools/fee-capacity-bridge.mjs)使用提升的函数包装，让启动时注册的原控制器回调也经过观察。原函数体、解析、业务检查、准备和编码全部照常执行。普通开发和离线构建不加载诊断；不增加财务或确认入口。

| 阶段 | 实际执行内容 | 失败后的记录 |
|---|---|---|
| CAPTURE | app原十组生产者、来源与完整状态捕获 | 子阶段分别记录；后续预览/准备/备份读取不执行 |
| RETAINED_ROOT | 原保留语义根的严格复制 | 原深度32、300000节点、128 MiB保护 |
| WHOLE_CAPTURE | 原完整捕获的严格复制与冻结 | 完整对象仍受原128 MiB保护 |
| RETAINED_REOPEN | 原严格解析器重新打开保留JSON | 记录原异常固定代码，不归并为外层通过 |
| PREVIEW | 原来源/历史/指纹与整批预览 | 只有STAGED才能继续准备 |
| PREPARE | 原引擎重算、十组预备状态及完整备份 | 包含多次来源重捕获；内部阶段有重叠 |
| BACKUP_ENCODE | 准备内的原备份编码器 | 原256 MiB原文、64 MiB输出保护保持 |
| BACKUP_READ | 私有签发候选的已编码备份读取 | 这是缓存字符串读取，不能写成重新编码耗时 |

未执行项使用明确列表和null，不能当零耗时或已通过。原异常由观察器原样抛回；公开记录只允许固定代码，未知异常为UNCLASSIFIED。观察器不把大小预计当严格解析或交易资格。

## 字节计数与计时隔离

[计数器](../tools/fee-capacity-trace.ts)按普通JSON数据描述符读取，计算`JSON.stringify`紧凑文本的准确UTF-8字节、节点与从零起算的深度，不构造额外巨大外层字符串。整串文本计数可暂存，但每处出现都计入；别名按出现次数展开，循环、访问器、toJSON函数、稀疏数组、特殊原型和非有限值拒绝。孤立代理的转义字节可计数，不证明原严格解析器接受它。

每组先进行独立SHAPE轮，再进行首次计时和三次重复。SHAPE收集原保留根及真正构造到的完整捕获，未构造到的外层不猜数值；MEASURE轮不进行字节扫描。各阶段嵌套时间不能相加，不设机器速度门槛，不报告p95、冷启动、峰值内存或逐函数CPU归因。

原[离线页面基准](../tools/benchmark-fee-browser.mjs)另外顺序运行，记录原生点击到结果加两帧；含原页面捕获、准备和绘制。专用服务器分阶段样本含观察包装，不与原离线总耗时互相相减或与历史单次数字作提速结论。夹具算法及113 USD×7保持；随机资料身份和时间可不同，逐轮记录实际原文字节和哈希。

## 保留与恢复核对

每个只读样本前后核对六份原文、FX与文件证据、所有控制器和工作区捕获、存储、客户原确认及所有者私有检查点。成功准备核对十组参与者、原笔数、买方增量791×笔数CNY和卖方利润null；备份经原检查读取器解码，完整capture逐字序列化哈希及十组patch保持。JSON复制的候选摘要必须被拒绝，最后丢弃私有签发对象。

只读测量之后，另外点击原工作台检查备份，并分别另存项目、账单、配对、成分附件、精度选择、封套六类正式文件。保存API替身记录实际输出字节及哈希，与当时原来源比较；费用/回执原文与客户确认保持。保存本来会更新文件证据，不能把这一段写成所有者修订不变。替身不证明物理磁盘或真实手机保存，也不证明六类文件能替代全部未提交状态的完整工作台备份。

本轮不使用整批确认、应用或自动修复。不放大预算、不删历史或文件证据、不截断失败输入、不用相同摘要代替来源/确认权限。真实单据、真实手机与专业人工复核继续暂缓。[结果与后续门槛](fee-capacity-stages-validation.md)分别报告成功、拒绝及可用的文件保留路径。
