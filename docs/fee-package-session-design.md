# 完整包中新建独立已提交资料会话

2026-10-30，第107轮，本地开发原型。实现完整包0.1到真实独立持有者的最小重建验证，尚无继续编辑、再次完整交接或正式工作台切换。

## 当前资料与原档案的边界

[第106轮完整内部包](fee-recovery-package-design.md)含当前项目、封套、原恢复档案、全部来源同步记录，以及本副本0或1次新应用备份。来源同步或费用应用之后，当前项目可能不同于原档案。不能直接打开原档案，便声称重建了最新完整包。

本轮[适配器](../tools/fee-package-session.ts)先通过原包解析器验证全部文件、摘要与连续历史，再从包内当前封套取得五类最新来源。原恢复格式与原会话控制器负责预算核对、完整来源解析、汇率重建、原引擎与对比重算，准备十组全新持有者。确认打开前后逐字核对六份来源，校对利润和买方总支付；无法无损重建的文本会拒绝，不默默规范化或覆盖原会话。

## 中立的界面状态

包中原档案的表单并不一定属于当前项目。最小重建只安装已提交五类来源与当前封套；付款计划置为未录入，敏感性控件清空，客户字段为空，客户审批为未核对。未提交草稿、坏数字、未读文件、候选、补丁、活动任务、显示偏好和未知扩展只随原始档案保全，不恢复执行资格，也不认为相关待办已解决。

工作台用当前项目汇率簿重新构造行及对应依据，不读取本机缓存或沿用旧档案汇率编辑。项目、账单、配对、成分、精度和封套的单独文件证据均为未知，不以打开外层包冒充六份子文件已保存。原配对项目快照失配、历史未知、已消费来源和退休编号继续保持原结果。

临时重建表示使用原恢复协议，仅供私有控制器准备。完整原包、内嵌文件、全部来源更新、应用备份、原source_wire与supplement_json留在独立保全槽，逐字不变；不将这些记录删掉或转成新候选。当前会话对象只提供捕获、诊断、保全和关闭状态读取，不暴露原业务工厂或费用应用入口。

## 明确打开与失败保持

[面板](../tools/fee-package-session-panel.ts)使用真实文件选择；先准备摘要，再勾选关于已提交子集与未恢复内容的声明，最后明确打开新会话。候选是私有、一次性身份，复制JSON、跨所有者、上下文ABA、取消或关闭不能恢复它。原会话在最终新根安装成功之前保持；只有成功明确切换内部阅读槽后，前一个内部会话才关闭，其保全原文仍可读取。

只有一个物理准备槽；逻辑取消即时返回，但底层读文件、校验、编解码或控制器准备结束之前不能启动另一个任务。不会把旧异步接口的提前取消返回当作底层任务已经终止。失败、坏文件、迟到、安装失败均保留旧会话；成功后显示失败不能声称回滚或重新应用费用。

## 权限、预算与后续

所有操作零费用写入、零存储读写、零通知和零文件写入。SHA-256只核对完整性，不证明来源真实或已经专业审核。原包64 MiB、来源历史64条／64 MiB、原128／256／48／64 MiB恢复预算与节点／深度保护分别保持；没有放宽4／8笔容量限制或证明性能、峰值内存改善。

下一阶段要把本轮保全槽接到可继续编辑的独立业务副本，明确原始档案、既有更新和应用备份如何继续追加及再次完整交接。不能直接调用旧业务工厂使来源记录从零开始，或只保存最后一次费用备份。完整表单、真实工作台切换和正式发布继续后置，见[后续目标](development-stages.md)和[验收](fee-package-session-validation.md)。
