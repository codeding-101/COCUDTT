# 第七十七轮：工作台完整快照与提交后副作用边界

2026-10-19。承接[独立整批事务](fee-application-transaction-validation.md)。本轮完成运行工作台接入前的快照持有者和注入式副作用协议，尚未把现有 app.ts、各旧控制器或公开费用入口迁入该持有者。

## 快照交接契约

[领域契约](../src/domain/fee-workbench.ts)与[提交层](../src/data/fee-workbench.ts)整体捕获封套原文、五份当前来源、原始汇率编辑行与保留汇率簿租约、六份文件的名称/已保存原文/时间、五类未提交输入、六类进行中操作，以及其他界面资料的原始 JSON。额外界面资料只作内部归档，不能当作当前计算结果或客户确认；快照始终要求重新计算、客户确认重新建立。

捕获先做有界、无 getter 的完整 JSON 复制，再开始异步解析。原行不补齐、不过滤成已完成输入；空串编辑仍算未提交。工作台来源与封套逐原文核对，只有空白差别也阻断。汇率行不完整、重复币种适用范围、重复行号、保留租约失配或不能对应项目汇率簿时均阻断。原文保留供备份，不以过滤后的汇率行继续写入。

文件是否待另存由当前原文与已保存原文比较，不接收调用方自称的 dirty=false。完整快照沿用严格 JSON 复制的深度、节点与128MiB上限；这是整份快照的独立限额，合法封套也可能因多份原文合计超限而暂存失败，不能截断资料。

## 预览与确认

明确预览提供整个批次的前后来源、费用/引用数量及历史失配提示。沿用真实事务模块的全部资格、消费历史及前后核心计算阻断，不引入新税务、保险、承担或舍入规则。

候选、原始汇率行、文件状态和完整内部恢复备份均在确认前私有准备；确认时再次重验真实事务，再整体替换快照。旧配对、附件、精度政策不重绑；新增费用后明确列为历史来源。项目独立文件和封套待另存，账单及其他来源原文保持。纯引用只新增回执，项目/账单原文及保存状态保持。

能力绑定本实例、完整快照及代次，JSON或其他实例不能确认。取消、父输入ABA、来源/文件/未提交输入替换使旧预览失效；双击返回BUSY，原批次重复确认零写入。确认前错误保持旧快照；修改其他界面资料时保留已提交标记，不把已应用事务显示成未应用。

## 提交后副作用

副作用须显式调用并注入适配器，确认本身不自动执行。这里没有浏览器存储、DOM或磁盘实现。

- 缓存要求原子比较写入和完整原文回读。冲突、回读不同、写后抛错分别保留结果与内部备份，不用普通覆盖或回滚替代协调。
- 显示失败保留新费用与回执，可重新显示；失败不能成为重新写一笔费用的理由。
- 另存只写点击时的封套原文。取消/异常不清除待另存，发起下载不代表落盘。只有适配器确认保存成功且完整上下文仍相同时，才标记封套已保存；项目独立文件仍待另存，保存时间未知保留为null。
- 迟到副作用结果绑定原快照和控制代次，明确标记stale_context，不能覆盖较新的输入或保存状态。同类副作用不并发排队；不把缓存确认当作文件保存。

内部恢复备份保留完整来源、未提交原文、原始汇率行、文件状态、历史和私有界面资料。它不是可导入的封套或已批准费用文件，不能直接交给客户。
