# 配对1.1、核对记录页面与公开体验版（第四十四轮）

2026-10-15。承接[只读模块](container-cost-review-module-validation.md)和[记录层0.1](container-cost-review-plan-validation.md)，本轮贯通显式升级、核对编辑、文件/草稿、恢复、复制及内部审计，并按用户授权发布公开网站。核对记录仍不清除原提案待办、不写入实际费用，也不改变责任、风险或税务算法。

## 可体验的流程

1. 打开网站，展开“项目＋账单配对交接”，先另存自己的资料。
2. 点击“打开合成核对示例（替换项目和账单，先另存）”。示例为中国一般贸易进口，含跨标签箱日交集及一条EXAMPLE记录；不是合同、承运人收费标准或税率推荐。
3. 在“费用核对记录”新增一条记录，明确类型、当前目标、说明和来源日期。保存后仍未确认，单独确认来源才记录该用户假设；示例来源不能直接确认。
4. 修改项目/账单会显示失配；提交或放弃未完成编辑后，再明确捕获当前完整修订。旧确认撤销，原记录文字及失效目标保留，须重新核对。
5. 另存完整配对JSON后可重新打开。客户报价不带内部记录；内部HTML/Excel保留配对、来源、状态和完整快照。

原配对1.0保持读写，不隐式升级；明确启用核对后才是1.1。核对类型只提供当前支持的目标，不能把未知范围或箱日交集当成程序证明不相交；没有IGNORE、拆税、抵扣、舍入或费用应用按钮。新建记录不是新增实际费用。

## 格式、修订与失效

1.1增加必需的review_plan。其basis绑定不含记录的完整1.0业务投影；记录修订与业务修订独立，整体content_key仍覆盖全部数据。因此确认/编辑记录改变整体租约，不改变业务修订或误伤其他确认；业务更新增加业务修订、重绑完整basis并撤销旧来源键。保存或打开不自动确认。

解析器严格区分1.0/1.1，拒绝缺记录、拼接basis、未知活动字段或未来版本。旧项目的同名扩展不激活、不覆盖。[第七份离线Schema](../schemas/container-cost-pair-1.1.schema.json)同源生成，原六份Schema及旧模板保持；跨ID、完整快照、来源和目标资格仍由运行时检查。

记录替换检查同一plan_id、递增记录修订及退休历史，不能回退或静默丢弃旧记录。业务复制的1.1副本使用新计划身份、空记录与空退休记录，原业务和未知扩展保持；旧金额、日期、箱号仍须复核。

## 编辑、恢复及导出

未提交核对编辑使用独立浏览器键`trade-cost-engine:container-review-editor-v1`，绑定完整配对租约。字段可空，不自动补类型、目标、来源、日期或覆盖范围；例题只用于明确打开的合成资料。编辑已有记录不默默改目标；目标JSON字段顺序改变不影响合法身份。

未完成编辑阻断配对另存、打开、捕获、业务复制或其他记录操作，允许明确放弃；迟到读取被取消。刷新只恢复表单，不自动提交，失配编辑保留原文。保存取消/失败保留内存与点击时冻结文件，私有错误路径不展示。

原始恢复备份1.0新增可选container_review_editor及container_review_editor_draft_text；两项并存增加两部分，普通10部分、有核对编辑12部分，与原提案编辑/副本组合按实际可选部分增加。旧6/8/10/11/12/13等文件检查保持；5MiB只读检查上限保持，较大备份仍需人工核对，不自动导入。渲染故障隐藏旧结果，重试保留记录和未提交原文。

内部HTML和Excel展示已捕获配对及核对记录，当前项目/账单失配时明确标为历史快照；未提交编辑不在报告，需提交或另存恢复备份。Excel新增一张“配对与核对记录”，同时保存顺序JSON片段，完整拼接后能重新打开；不跨币合计，不把长文本当公式，继续沿用16工作表与单表100000物理行上限。客户HTML/Excel/PDF继续按公开白名单生成，不接收配对/记录/编辑参数。

页面记录每页50条，显示总数并提供翻页；文件和内部导出保留全部。只读模块2000检查目标、记录/退休ID各2000、配对10MiB、确认键1MiB等边界保持，不截断后宣称完成。
