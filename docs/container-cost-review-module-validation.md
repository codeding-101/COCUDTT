# 只读费用边界核对模块验收（第四十二轮）

2026-10-15。实现[第四十一轮设计](container-cost-review-design.md)的第一步：独立类型及核对函数，没有运行工具入口、人工解决记录、新活动文件字段、税务转换或费用应用。

## 本轮实现

`src/domain/container-cost-review.ts`定义输出0.1；`src/engine/container-cost-review.ts`提供：

```ts
const audit = reviewContainerCostBoundaries(pair, currentPairKey);
const unchanged = containerCostBoundaryReviewIsCurrent(audit, pair);
```

调用先严格校验完整配对1.0，预期内容键必须匹配；输出绑定pair_id、revision、完整pair_key、当前术语及逐行稳定映射。有效性检查重新计算整份结果，输出本身被改、来源/金额/日期/汇率/方案/映射或副本身份改变均失效。它是内容一致性检查，不是合同或业务认证；结果含内部快照，不作为客户资料或新文件格式。

- 原提案及原候选完整保留，包含/来源/精度待办继续有效。没有ready或应用标志，也不改变旧提案的判断。
- 选中行与其他全部账单行逐对检查（两行均选中只记录一对），忽略可编辑scope标签和币种差异作为排除理由。明确日历日期与两端计入规则求交，免费日仍覆盖；联合/分开D&D只核对箱日，交集不证明收费内容重复。不同方向、混合/固定事件或缺失条件标为UNSUPPORTED。精确箱号文本和选中日期不交仅说明这些输入集合不交，不证明真实箱号、其他费用或整笔业务无重复。
- 已有活跃费用无箱日范围，相关D&D/同收费类型跨标签、跨币种仍保留保守候选；THC内含、同去重组分别列依据。未启用术语的费用排除在当前集合外；互斥/依赖校验失败另列问题，不能把失败当空集合。
- 检查活跃父项的存在、失效、自引用、环及跨币关系；拟引用另一未应用提案明确标出。即使结构正确仍保留FULL_COVERAGE_EVIDENCE_REQUIRED，不凭contained_in_cost_id认定合同全额包含。新建提案自身不活跃时不充当活跃父项。
- 原币金额保持字符串；额外尾零不算损失，非零尾数超过核心6位为LOSS，不舍入。账单不可计算为UNKNOWN。现金通道只是账单应付假设，付款仍未核实；经济成本和海关加计额均为null，不以0冒充已确定。含税、费用税率引用、海关ADD/EXCLUDE仅列原记录及待办；不拆税、抵扣、推定税率或倒扣商品整价。
- 已有费用的报价包含按工具相同的当前方案推导清单检查，并明确标为CURRENT_SCENARIO_DERIVATION；新提案仅为PROPOSED_ITEM_FLAG。不活跃/缺目标/无法推导为未知，不能当实际合同证明；报价包含仍不能替代海关排除依据。

检查目标上限2000：活跃已有节点＋所有新提案节点＋至少一边选中的账单行对＋意图数×活跃已有费用数。计算前检查，超限整份拒绝，不截断后宣称完成；输入/输出沿用安全JSON、10MiB等边界，输出过大也整体拒绝。1225对覆盖完整输出，界面预览上限不影响模块。未知扩展不激活、不改写。
