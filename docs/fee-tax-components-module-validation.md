# 第五十八轮：费用税务成分独立模块验收

2026-10-17。本轮实现[独立类型](../src/domain/fee-tax-components.ts)、[严格输入校验](../src/domain/fee-tax-components-validation.ts)和[只读计算模块](../src/engine/fee-tax-components.ts)，遵循第五十七轮[设计基线](fee-tax-components-design.md)。这是开发 API，不是运行工具的新税务功能；不新增有效项目/配对字段，不确认抵扣资格、不改变既有费用、利润、进口税基或税款。

## 输入与结果

`reviewFeeTaxComponent(unknown)`接收一行明确假设，`summarizeFeeTaxComponents(unknown)`接收同币种、唯一行ID的1至8行集合。应付总额、显式价税或给定比例、抵扣假设和独立海关成分分别录入。未知须明确为null或UNKNOWN；不分离不是零税额，不调整抵扣不是法律资格结论，不加计不是从货值扣减。

结果以`READ_ONLY_ASSUMPTIONS`标识；六列分别为cash、net、tax、credit、economic、customs。精确分数使用JSON安全的十进制整数字符串分子/正分母，约分但不舍入，例如1÷1.13保留100/113。原始金额和依据文本在脱离调用方的输入快照中保留；审计记录逐列操作、操作数与结果，没有ready、确认、推荐或应用标志。即使issues为空也只说明这些数值假设可计算。

每列独立汇总：有未知则完整合计为null，另列已知小计及未知行数。不混币、不默认汇率，不将零应付额自动转为已知抵扣/经济成本。显式净额与税额必须精确相加等于应付额；给定比例须在[0,1)，抵扣假设须不超过该行税额，首版海关成分须不超过该行应付额；这些是受限算术约束，不代替法规判断。

## 校验与独立对照

- 金额只接受最多24位整数、18位小数的非负十进制文本；拒绝数值、科学记数、空白、负号、前导零与隐式强制转换。
- 分支字段精确白名单、依据非空/长度限制、行ID/币种及集合限额；拒绝混合分支、重复ID、跨币种、缺行、额外数组属性及访问器。普通数据对象可无原型；非数据对象、撤销Proxy产生受控输入错误。对普通对象不调用访问器；任意Proxy自身陷阱并非沙箱保证，未来文件入口只解析JSON。
- [固定手算案例](cases/fee-tax-components-design.json)保持上一轮原文，31有效与45拒绝案例逐项对照新实现；预期不由实现反生成。
- [计算测试](../tests/fee-tax-components.test.ts)另有200组反向构造、100组非整除高精度比例的整数交叉乘法、32种未知分布/8行独立汇总，冻结输入、输出别名隔离、JSON往返和审计一致性。
- [边界测试](../tests/fee-tax-components-boundaries.test.ts)覆盖无效结构、引用限额、访问器不执行、精确错误路径、旧同名扩展原文存取但不激活，以及旧业务分析前后相等。Decimal全局配置保持。

新增461项，完整82个测试文件3139项通过；原有80文件2678项保持。独立设计检验器另有31/45/200基准，仍不导入生产实现，不能再加到应用测试总数。它仅允许三个新模块互相引用，其他生产源码引用即失败，防止未验收接入。

类型检查、131动作/43字段/46路径的绑定审查、21错误/31警告代码、原设计基准、静态进口演示确定性、证据链接、离线构建及模板/Schema一致性分别核对。Windows/Linux CI执行相同受限检查，最终提交与公开发布证据附在本轮PR。
