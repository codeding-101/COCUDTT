## 计时的解释

原离线页面1笔点击到结果加两帧：首次10,344.5 ms，三次重复7,952.9 / 9,300.5 / 8,285.6 ms，中位8,285.6 ms。原备份动作重复中位1,614.2 ms，含再次捕获、保存API替身检查/哈希和两帧，不含物理磁盘。4/8笔分别是拒绝处理时间，不能与成功预览混合汇总。

专用服务器分别记录CAPTURE内的保留根、外层和保留解析，原PREVIEW、PREPARE及其内部三次重捕获和BACKUP_ENCODE，最后BACKUP_READ仅是缓存字符串读取。所有原始首次/重复阶段时间列在报告；嵌套阶段不可相加。包装、页面绘制和桌面状态不同，不从本轮与第八十五轮数字推导提速/退化百分比，不从这些样本推导p95、峰值内存或逐函数CPU归因。

## 超限后哪些保留路径已验证

在只读测量之后另行点击原“另存当前工作台检查备份”：1笔未准备UI候选的原备份能到保存替身；4/8笔在同一捕获层拒绝，保存器调用0次。**完整工作台检查备份不能绕过当前容量限制。**现有泛化提示仍建议这条路径，下一轮优先改善此处指引。

三组分别通过原按钮另存项目、账单、配对、成分附件、精度选择、封套，共18次。保存输出全部可解析、字节/哈希等于当时当前来源；六份原文及客户原确认保持。只读样本前后另核对所有控制器/工作区、FX、文件证据、存储和所有者私有检查点保持。

这证明六类正式源文件仍有独立另存路径，**不证明它们等价于含全部未提交状态的完整工作台备份**，也不证明物理磁盘或重新导入后可突破容量限制。原始来源、历史、回执、确认代次、业务资格和预算继续保持，不能手动裁剪历史来通过检查。

## 复现

```sh
node tools/benchmark-fee-browser.mjs

```
