# 首次引导的独立偏好与组件协作

2026-11-03，第121轮，本地诊断候选。

本轮复用现有首次引导控制器，与已有字段说明控制器放在同一个受信子文档中，验证步骤、焦点、偏好和清理互不串用。各子文档仍只创建一份字段说明和一份引导，保留第120轮每文档仅一份字段说明的限制。

同源 iframe 仍共享浏览器存储。原引导直接按固定键读写 localStorage，把原组件再创建一次并不能隔离“不再显示”偏好。因此专用本机 Vite 响应将原三处监听器和两处存储调用交给创建者端口，重命名固定 dialog/title/status 标识，并将两句偏好文案改为“本次副本会话”。适配前固定完整原文指纹，逆向替换必须恢复全部原文，四步说明及转义保持。仓库 src 与正式工具不改。

偏好端口只接受 null、show、hidden 三种值，不接收任意浏览器键或业务对象。各实例从独立的显式初值开始；默认不继承原页面偏好。读写均核对当前根和所有者，失败保留旧值，关闭后封存并拒绝后续使用，已保存的值仍可只读检查。该值仅在当前诊断会话内保留，不是浏览器持久化或项目保存证据。

每个完整引导登记八项资源：弹窗关闭、偏好封存、root click/change、dialog cancel/close/keydown、MutationObserver。字段说明继续使用原五项资源，两者独立所有者。登记先检查容量，关闭先使回调静默，再实际移除；失败保留具体回调并只在明确重试时释放剩余项。清理调用原控制器的非持久化关闭分支，不能把资源关闭当作用户保存偏好。

新宿主通过原 entry 输出刷新现有状态文字，不替换整个根或移动输入；这使偏好读取失败提示也能显示。观察范围内的根/标识变动会永久失效本实例并撤销旧关闭身份，重新核对仅授权清理。部分准备失败保留 DOM 和未提交原文，不开放正常操作。

浏览器在原工作台旁创建四个受信子文档。每个子文档自己的 localStorage getter 在诊断开始前设为“访问即失败并计数”，原页面的 getter、偏好和原应用回调保持。该诊断保护并不纳入组件所有者；frame、模块启动及整个文档生命周期仍未完成退役管理，不宣称全部资源归零。同源文档也不是恶意脚本安全边界。

原生验证包括自动/手动打开、四步前后切换、Tab/Shift+Tab/Escape、焦点返回、读写失败、两类组件相反关闭顺序，以及两弹窗叠放时清理引导仍保留帮助。失败注入在 cancel 实际移除前；原回调会取消默认行为，已静默的回调不能取消，用真实事件和缓存回调分别检查。

完整工作台切换、原应用整体解绑、最终安装、客户报价权限和源文件保存状态继续关闭。后续先处理受限会话的启动、取消与组合清理；移动端高级面板涉及真实表单移动和滚动状态，需单独核对。
