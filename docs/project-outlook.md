# 项目后续展望与交付路线

更新：2026-10-11。定位：面向外贸业务人员的、可追溯输入依据的贸易成本与方案测算工具。首条业务路线：中国一般贸易进口，单商品一票。

## 希望把它做成什么

业务人员收到一个进口报价后，可以明确货物净价、运输、保险及其他费用，记录税率与汇率依据，检查业务前提，比较不同组织方式下的总支付，再把完整测算交给同事复核。每个结论都能回到输入、适用条件与公式；不完整的数据会成为待办，避免被当成确定的最优方案。

近期产品以进口买方的成本与谈判需要为中心。境外卖方采购成本通常不可知，现已允许它缺省并显示利润无法评估，仍可比较已知的买方支付；不能用示例采购成本冒充实际卖方利润。

项目的专业价值来自规则建模、证据追溯、方案比较和真实验收；简历材料应展示这些工作的证据与个人判断过程。

## 阶段一：建立可复核的真实案例集

**交付物：** 至少三笔脱敏案例，每笔有输入文件、资料编号、人工对照算式、预期金额和差异说明。优先选支持范围内的无消费税、从价消费税、不同原产地或待遇条件案例。

**完成条件：** 税基、各税种、买方支付逐项对照；差异解释到费用范围、适用日期或舍入。真实资料不足时明确标为合成测试，不计作真实验收案例。已知涉及未支持制度或税种的案例列入待扩展，不冒充已支持业务。

**需要协作：** 你或业务人员提供脱敏合同、运保费、商品与原产地信息、适用税率及汇率依据、税额；我继续整理输入、编写回归和定位差异。资料准备表见 [真实案例采集模板](cases/import-case-template.md)。

当前暂时没有真实资料，已完成合成对照和外部案例目录运行入口；真实业务验收保持待办，不阻塞独立的功能与工程改进。

## 阶段二：完成进口买方的日常测算流程

**交付物：** 空白交易入口、从真实报价填写的引导、未知卖方成本处理、净价与运保费拆分提示、费用缺失和重复检查。

**完成条件：** 不修改示例也能建立一笔交易；在不知道卖方采购成本时仍可完成买方成本测算，卖方利润明确标为未知；坏输入不会静默变成零；用户知道还需补什么资料。

界面按“交易信息 → 费用 → 税率/汇率与条件 → 比较结果”的业务顺序整理，每次调整都维护离线运行、窄屏和文件恢复能力。

本阶段的空白录入、未知采购成本、净价确认和新费用空白已交付并完成自动化及Edge检查；目标业务人员使用效果尚待试用。详见 [买方流程验收](buyer-workflow-validation.md)。

## 阶段三：让方案比较回答真实谈判问题

**交付物：** 方案专属费用或启用条件、卖方运价与买方运价分别录入、待确认费用的承担敏感性、汇率与运费变化分析。

**完成条件：** 两种运价不会一起计入同一方案；一笔不同组织方式的案例能解释总支付差异；调整一个变量能追溯变化；固定报价、固定买方支付、固定利润率分别说明比较假设。比较报告同时展示已知金额、未确认金额及风险转移点。

先完成可解释的并列方案和敏感性范围，再考虑更复杂的推荐算法。合同事实、税务前提和货损风险不能仅被一个利润排名代替。

第六轮已实现逐项适用术语和替代报价组，各方案按实际费用重算税额；第八轮完成[独立合同报价及有效期、逐术语费用约定](actual-quotes-validation.md)。第九轮完成[运输分段、保险配置和集装箱提醒首版](logistics-validation.md)，本地549项测试及四套浏览器验收通过。下一步进入费用推理链、公式展开和费用/税基可视化，再接入运费/汇率假设分析；专业复核、真实业务及设备验收独立保留。

## 阶段四：形成可交给同事的内部测算报告

**交付物：** 可打印的内部报告、方案快照与对比记录。报告包含交易日期、币种、计算模式、贸易路线、费用归属、税额、数据来源、适用期、核对状态及待办。

**完成条件：** 报告金额与项目逐项一致；保留生成时的输入快照；后来改项目不会改历史报告；未经核对的内容在报告中仍可见。现有HTML/打印流程保留，新增Excel、实际PDF文件与中英文摘要按上述新增计划验收。

首版本地HTML报告已实现并验证输入快照、金额、核对状态、未知利润、取消及失败保护；真正打印分页和真实下载落盘仍待验收。

## 更远期：有证据地扩展模型

中国路线通过业务验收后，再决定扩展多商品同票、其他消费税计征方式、贸易救济税、其他目的国税制，或批量录入。每个扩展都需要独立的适用范围、官方依据、真实对照和回归测试。

自动查询税率与汇率可作为后续选项，但查询值需保留日期、来源与适用条件；服务失效时也要能继续使用经过记录的人工数据。团队共享、账号和云端存储由真实协作需求决定，当前继续保持本地运行与单文件分发。
