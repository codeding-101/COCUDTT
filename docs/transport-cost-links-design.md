# 运输费用与运输段关联：边界与接入设计

第三十一轮，2026-10-14。独立模块及测试已实现，尚未接入运行工具、项目文件、恢复或导出。本设计不是新法规、完整运输计价或专业复核结论。

## 现状与依据

现有TransportPlan保存运输段、唯一交货点、承运人合同和卖方运费支付终点；reviewLogistics检查运输衔接、术语交货事实和依据。CostItem已具备适用术语、替代报价组、发生原因、付款方/承担方及报价/费用包含关系。costsForTerm先选方案实际费用，再进入汇率、责任、去重和税务计算。

缺口是费用尚无直接指向运输段的字段。不能凭“海运费”等自由名称推定所涵盖的运输段，不能因路线分成三段就将同一通运报价计三次，也不能把覆盖段数换成费用分摊比例。

2026-10-14核对[ICC Incoterms® 2020原文：任意运输方式规则](https://library.iccwbo.org/content/tfb/BOOKS/BK_0049/BK_0049_04_RulesAny.htm)。CPT/CIP的交货风险点与运输目的地是不同要素；CPT/CIP及DAP的目的地卸货费用还需核对运输合同约定。因此本模块只核查费用引用的服务范围，责任、风险、报价包含及税务仍由各自规则和明确事实判断，不把“关联某段”变成卖方/买方责任结论。

## 独立输入，不激活旧扩展

领域类型位于src/domain/transport-cost-links.ts，函数位于src/engine/transport-cost-links.ts。TransportCostLinkInput是函数参数，不是新项目字段或可导入文件容器；审计输出版本0.1不改变项目0.8、付款1.5或恢复1.0。

| 字段 | 含义与限制 |
|---|---|
| target_cost_ids | 人工选择要核对的费用，最多100项，不根据名称/类别自动选中 |
| links | 每个范围内费用最多一条记录，不允许范围外记录；最多100项 |
| state | UNCONFIRMED草稿、LINKED明确关联、NOT_APPLICABLE明确不适用 |
| segment_ids | 最多100段，引用原路线中的稳定ID，按原顺序连续选择；不补中间段、不自动排序/去重 |
| charge_kind | UNCONFIRMED/CARRIAGE/HANDLING/DELAY/INSPECTION/OTHER，仅说明本关联的服务种类 |
| scope_id | 依据合同/账单人工区分收费内容、范围、期间等，不自动生成真实收费范围 |
| evidence | 沿现有SourceEvidence记录来源、适用期、核对日、状态和核对时快照；不是认证签名 |

草稿可保留未完成字段及重复/坏引用，核对时给出问题；类型、数量、费用重复记录等结构错误直接拒绝。NOT_APPLICABLE须有依据，清空段/类型/范围；不适用不等于金额0或费用未发生。

按当前术语复用costsForTerm检查互斥组和依赖。不活跃费用的关联保留但不参与当前范围、来源或重叠核对；再次启用时检查。不存在的费用不能伪装为“不活跃”。原费用/运输段ID重复会报告歧义，不任意取一条当正确结果。

## 核对过程与确认失效

LINKED核查运输计划、非空段引用、段存在/唯一/连续/顺序、所选相邻段地点衔接、收费类型与范围。来源沿现有checkSource检查，EXAMPLE、未核对、适用期不覆盖、坏核对日、空依据或快照不符不能通过。

快照包括方案/交易ID、术语、比较日期、当前及原合同报价、运输计划和交货事实、原费用输入及关联字段；不把base_amount等派生输出作为事实输入。费用金额、币种、责任/包含关系，运输段、端点、承运人/合同，收费范围、引用、报价或日期变化都会要求重核。函数只指出原快照已失效，不修改原输入的确认状态，也不自动重新确认。

同类收费、完全相同的人工scope_id且所选段有交集时，输出potential_overlaps。保留DIRECT直接包含、COMMON_PARENT共同父费用或NONE标记。它不是重复收费的确定结论：时间、箱号、计费单位及合同服务可能仍需检查。既有包含关系不删除候选，本模块不新增扣减/去重；也不因类别或scope_id不同证明绝无重复，通运费内含THC等跨类别范围须另核现有合同和包含关系。

segments_without_links仅列本次范围未关联的段，不能断言费用缺失、免费或完整。reference_checks_passed只表示有活跃核对范围且引用/来源检查无问题；即使为true，也可能有重叠候选，review_required仍为true。两者都不是业务可用、确定排名、风险/税务合规或专业认证标志。空范围、全为不活跃费用不返回“检查通过”。

## 不产生的业务动作

不生成或拆分费用，不分摊金额，不修改付款方/经济承担方，不决定海关加计/排除，不据关联改写报价包含或contained_in_cost_id，不改变唯一风险点，不按运输段计入第二笔成本。跨类别包含、不同收费期间、箱量、免费期、复利及实际清偿均不据此宣称完成。

## 下一阶段接入门槛

1. 先确定项目0.9的提案字段位置（拟term_scenarios[term].transport_cost_links）、保存/解析边界及Schema。当前0.8继续保留未知扩展，不能直接解释旧同名值；显式升级、重名碰撞保护、迁移预览及坏/未来文件拒绝需同轮交付。新建默认版本是否调整另作明确决定。
2. 界面人工选择核对范围、段、类型和收费范围，显示单段/通运/不适用；不默认选择全部段或推定责任。运输段删除/改名后保留失效引用并提示修正，不能静默解绑或自动重新匹配；复制方案或报价变化须撤销确认。
3. 新核对状态单独呈现，不能提高旧比较资格。启用核对且存在问题/待解决重叠时保留参考金额并退出确定推荐；不通过把新范围留空来宣称完整费用检查。解决候选需明确的范围/包含依据，不能仅点“忽略”提升资格。
4. 内部HTML/Excel保存原始范围、引用、问题和交集；客户白名单保持。保存选择器前固定快照、编辑撤销迟到读取、恢复/重试/只读检查与0.9贯通；覆盖旧格式/扩展、XSS/Excel公式注入、取消/私有路径、真实离线下载和窄屏流程。
5. 100费用×100段、4950对候选做输出/交互上限核验，避免一次展开导致页面卡顿；保留完整内部审计，不静默丢候选。旧业务金额/风险/税费和旧文件资源回归不变后才启用。
