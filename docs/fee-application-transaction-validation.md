# 第七十六轮：独立费用整批提交协调器

2026-10-19。承接[事务边界设计](fee-application-design.md)、[封套协议](fee-envelope-design.md)和[封套工作台](fee-envelope-workspace-validation.md)。本轮实现独立暂存与独立内存聚合状态；运行工作台仍没有费用应用入口。

## 已实现的提交边界

[暂存模块](../src/data/fee-application-transaction.ts)接收完整封套原文和明确事务ID。严格解析完整历史及引用闭包，重算项目、账单、配对、成分、精度来源和既有待办；只允许本地声明的新业务谱系，旧资料历史未知继续阻断。所有行必须一并通过，最多50行，不跳过坏行。

原币现金、政策候选和目标金额必须数学等值且符合核心精度。抵扣非零、部分/未知海关成分、FX政策、舍入差额、付款/承担不齐、含税未支持情况及已有费用覆盖待办全部保留。既有数字相同或使用不同箱号/标签不能代替完整覆盖依据。

暂存前后均执行真实核心引擎；确认阶段再次执行完整历史验证及核心重算。缺商业汇率、坏计算图等真实计算错误必须在替换前失败。使用合成明确商业汇率的固定用例核对USD113对应CNY791，只是测试输入，不是当前市场汇率或贸易依据。

每次候选包含新增项目费用、完整前后payload、原始项目/账单/配对/成分/精度归档、计划、回执和账本新修订。旧费用与未知项目扩展保持；账单原文保持。原CREATE_NEW配对及其成分/政策原文留作历史，相对新项目明确失配，不静默变成REFERENCE_EXISTING，不继承新业务确认。

只有既有引用时，费用新增数和消费数为0，可记录一次引用回执，项目与账单原文排版也保持。独立另存格式继续采用封套1.0，没有新项目Schema或自动迁移。

## 聚合状态、幂等与竞态

[协调器](../src/data/fee-application-coordinator.ts)私有持有一份完整原文/租约/文件状态快照。来源变化、取消、待处理输入状态及新预览递增控制代次，撤销旧确认；真假ABA分别检查。所有解析、重算、引用闭包、序列化均先完成，确认后一次替换私有聚合指针。

预览对象深冻结，真实能力保存在私有WeakMap，协调器还绑定本实例；JSON、浅复制、其他实例及伪造getter不能取得确认能力。能力不是可导入的“已批准”文件格式。异步确认期间的取消、父输入、来源更新或更晚操作使迟到结果失效。双击不会排队形成第二笔费用。

重复确认核对完整原始计划、回执和当前财务payload：相符时ALREADY_RECORDED_NO_WRITE；同ID计划不同为冲突，后续编辑/删除/后来事务为RECORDED_HISTORY_REQUIRES_REVIEW，不重放也不回退当前输入。更换事务、目标或映射不解除来源消费和曾创建/退休目标保护。

解析/指纹/重算失败时，当前封套原文和费用/历史保持；控制代次可以失效。确认校验失败后可重试原冻结事务，不能自动新建ID。手动来源更新亦先完整验证，再替换；相同来源保持打开原文的空白和排版。

## 验证证据与实际限制

- [事务测试](../tests/fee-application-transaction.test.ts)、[协调器测试](../tests/fee-application-coordinator.test.ts)及[完整来源夹具](../tests/fixtures/fee-transaction.ts)：新增72项，完整107文件4157项在Windows/Linux CI执行；实际数量与结论须与本轮具体提交日志一致。
- 配对1.0/1.1、混合新增/引用、纯引用、部分金额/抵扣、核心计算失败、实际责任不符、历史未知/重复消费、计划冲突、后续修改、坏JSON/伪造能力、双击/取消/ABA/异步更新及指纹故障均覆盖。首轮新增用例暴露的缺汇率、保留覆盖待办和高精度夹具构造已修正，既有阻断不放宽。
- 类型和两份独立设计门禁在本机执行通过。独立应用门禁明确independentAggregateCoordinatorImplemented=true、runtimeIntegrated=false；封套工作台门禁保持applicationEntryEnabled=false。非白名单模块不能导入新协调器或绕过工作台边界。
- Windows曾有一项配对1.1完整往返用例达到30秒测试上限，其余4156项通过。去除同一私有已验证快照的重复历史核对与重复序列化验证，不建立跨请求信任缓存；输入及提交前完整解析、历史和核心重算保留。多次真实解析的往返用例采用60秒上限，业务断言保持，最终结论以本轮最终提交的双平台日志为准。
- 本地Vitest在默认沙箱遇到realpath权限错误；提升执行申请因自动审批服务模型容量不足未启动。本轮不能宣称本地Vitest通过，以具体提交的远程双平台CI和日志验收。
- 旧领域计算、既有测试、客户导出、Schema、模板、依赖与离线工具保持原字节。浏览器工具与第七十五轮相同，沿用该轮40套浏览器证据，本轮未重复执行或宣称新增运行界面验证。

本轮不安装实际工作台、不执行缓存写入、界面渲染或文件保存；APPLIED_INDEPENDENT_MEMORY仅指本独立协调器。不能据此声称已完成浏览器缓存、磁盘和界面的跨资源事务。上轮发布后公开URL哈希及原生线上复核仍因审批服务故障待补；真实手机、真实业务与人工专业复核继续暂缓。

## 下一阶段验收目标

将完整工作台状态接到同一个聚合持有者，包括项目/账单、来源文件、原始FX编辑行、未提交输入与文件状态；先展示整个批次差异、保留待办及历史失配，再明确确认。不能逐个调用旧setter让页面出现半新半旧状态。

接入后区分提交前失败与提交后缓存/渲染/另存失败。提交前财务状态不变；提交后保留新费用和回执并提供完整备份，不显示“未应用”诱发重复，也不自动回滚覆盖其他修订。最终同轮验收实际双标签、取消/迟到读取、失败恢复、原生下载、客户两版六文件隔离及320px模拟流程，再开放运行费用入口。
