# 第六十四轮：独立精度计算模块验收

2026-10-18。依照[上一轮设计](fee-precision-design.md)，实现[领域类型](../src/domain/fee-precision.ts)、[严格输入解析](../src/domain/fee-precision-validation.ts)与[纯数值模块](../src/engine/fee-precision.ts)。这是可单独测试的开发API，尚未注册运行工作台，不新增精度文件版本、选择控件、确认状态或费用写入。

## API和计算行为

| 函数 | 输入与结果 |
|---|---|
| `reviewFeeRounding` | 原币金额、明确/未明确政策；精确候选和有符号差额。金额或政策未知则候选为null |
| `reviewFeePrecisionGroup` | 同币种1–8行、明确步长/方式/依据和PER_LINE/TOTAL；同时输出两种合计及层级差额，不分摊。未知行使完整合计为null，已知小计另列 |
| `reviewFeePrecisionSplit` | 原G/N/T须明确且严格守恒；X/C可未知。具名`cash/net/tax/credit/economic/customs`候选、价税/费用净额差额分别保留，不配平 |
| `reviewFeePrecisionFx` | 明确币种对/来源类型/有效日期/用途；直接乘或精确倒数，不先截汇率。商业与海关成分诊断分开，不改变实际税基/税款 |
| `reviewFeePrecisionStageOrder` | 明确原值、比例及两阶段政策；比较直接换算后舍入与先舍入后换算的结果和正负差额，不选择较低的一方 |

结果为`FEE_PRECISION_REVIEW / 0.1 / READ_ONLY_ASSUMPTIONS`，带完整脱离调用方的`input`、`values`、`issues`和逐步`audit`。原十进制文本、尾零、依据空白和来源日期保持；具名成分避免数组位置歧义。上一轮固定向量中的数组和`DESIGN_FX_REVIEW_ONLY`是缩减设计协议，测试使用明确投影对照，不把它们当新生产格式。

数值完全使用BigInt分数，按单位的精确商、余数与半单位比较实现HALF_UP/HALF_EVEN/DOWN。审计记录原操作数、候选、带符号减法和量化时的单位/整数商/余数/是否进位；输出全部是普通JSON数据，不含BigInt对象。不读取或修改Decimal全局配置。

**输入限额不套到派生结果上。**公开输入仍是24位整数/18位小数十进制文本，或各80位的非负既约分数。内部累计、汇率换算、候选和差额不重新走该输入解析器，不截为6位/2位/80位。八个互素80位分母的合计可产生600位以上分母，实际测试保留完整原值及带符号差额；量化后的80位以上分子及104位换算金额也保持。结果不能据此直接作为业务文件输入，未来文件限额和整体大小需单独验收。

严格解析只读取普通自有可枚举数据字段，不执行访问器；拒绝类/自定义原型、符号/额外/隐藏字段、稀疏或扩展数组、Number/指数/负数/坏分数、无依据政策及不完整汇率事实。`FeePrecisionInputError.path`定位字段，不回显底层异常私有文字。null原型数据对象可输入但结果为独立普通对象。这不是Proxy沙箱或JSON文件解析器，不宣称重复JSON键、异步存储或大文件性能验证。
