# 独立显示偏好与重新录入指引

2026-10-28，第103轮本地候选。第102轮776份文件已另存完整本地快照并逐字核对；第101轮旧快照及受保留合成档案继续保持。本轮没有公开上传或发布。

## 只采用明确选择的显示组

[独立显示模块](../tools/fee-recovery-preferences.ts)接收已明确打开的原归档核对会话。用户分别选择新手/专业模式、面板收起、证据面板展开；默认不选，资料切换后清空选择。准备只产生候选，最终明确采用才通过既有状态所有者一次替换独立显示根。

支持的标识来自当前工具的固定输入区及证据面板，独立容器也提供这些显示结构。未知标识只留在原档案，不作为DOM选择器；混合列表只候选受支持部分，全为未知的组保持当前设置，明确的空列表才能清空所选组。列表超过256项整份候选拒绝，此界面预算不改变原档案预算。一个面板同时要求收起和展开时拒绝，不能部分采用模式或猜测优先级。

候选绑定本实例、当前归档的双摘要、归档核对上下文身份及显示所有者检查点。复制、JSON、跨实例、已消费、来源变化或手动显示编辑后的候选不能执行；确认时再查。取消、复位、手动展开/收起及迟到准备均不恢复旧候选。准备完成前失败保持原独立显示；准备期间取消先返回，唯一物理槽待底层结束后释放，不排队读取更多资料。

第102轮[核对模块](../tools/fee-recovery-review.ts)只增加只读contextStamp身份API，读取标记不改变身份；任何候选切换、取消及明确新选择都会产生新身份。因此“读取其他资料后取消回原档案”的A→B→A过程也不会恢复旧显示资格。原API的7组合成行为重新验证，原报告保持历史指纹。

## 重新录入只定位到说明

费用、核对、成分、精度、付款、敏感性及客户草稿只生成说明入口。归档中受支持的完整字段键可定位到对应说明；文件控件只按当前支持的固定ID提示重新选取。未知字段、未知控件或不支持的控件类型只提示人工核对，不以相似名称猜测目标，不拼接归档CSS选择器。

定位凭本次签发的私有指引身份执行，只改变独立显示的展开状态和说明焦点。坏数字仍须重填，文件元数据不能替代原File内容，客户确认必须重新核对；本轮没有业务输入字段，不回填金额、不运行原工作台文件选择器，也不批准报价。

[独立面板](../tools/fee-recovery-preferences-panel.ts)只在自己的宿主节点内查找固定说明标题。调用者在资料切换时通知面板，显示候选和定位资格失效；底层上下文身份检查也防止遗漏通知后旧资格复活。这不是实际工作台完整上下文订阅或跨工作台切换。

## 失败与交付边界

全部字段先在脱离当前视图的数据中准备，只有通过完整检查后才提交显示根。部分准备失败、取消或迟到不改变原显示。提交后显示渲染失败不能据此认为已采用的偏好没有发生；可从当前显示状态重绘，不涉及费用或回执回滚。

原source_wire、supplement_json、旧确认、文件事实及未知扩展留在原档案；显示候选不是项目、封套或完整新工作台文件。本轮不写存储、另存文件或客户批准；原财税、格式、依赖、运行字节和4/8容量限制保持。
