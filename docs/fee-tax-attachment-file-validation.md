## 已实现的文件与记录行为

`createFeeTaxAttachment(pairJSON)`创建空附件；`parseFeeTaxAttachment(text)`和`serializeFeeTaxAttachment(value)`严格往返。保存完整配对1.0/1.1原文与UTF-8 SHA-256，不按字段摘要替代来源；原文空白或字段顺序改变也需要明确重绑。数据与计算结果分开，读取时不信任预存金额或回执。

全部API使用异步Web Crypto进行SHA-256；缺能力时拒绝，不降级为弱指纹。调用时先同步捕获独立数据副本，再开始异步指纹；没有文件系统、网络、浏览器存储、全局Decimal修改或工作区安装动作。日期来自账单明确复核日，身份使用UUID，指纹不是签名或真实业务唯一性证明。

| API | 受限行为 |
|---|---|
| validateFeeTaxAttachment | 返回脱离调用方的完整验证副本；严格结构、两层JSON、指纹、限额及记录唯一性 |
| setFeeTaxAttachmentRecord | 明确新增/编辑一条成分假设；固定目标，不复用退休记录ID；编辑撤销该记录三项回执 |
| acknowledgeFeeTaxAttachmentRecord | 单独核对tax/credit/customs用户假设；不提升为抵扣资格、合规或应用授权 |
| rebindFeeTaxAttachment | 明确替换完整来源原文，撤销全部回执，保留孤立记录/原文字 |
| removeFeeTaxAttachmentRecord | 删除并保留退休ID，限额达到后拒绝，不静默丢历史 |
| copyFeeTaxAttachmentForNewBusiness | 要求不同配对/账单身份，仅创建新身份空附件，不搬旧成分和来源回执 |
| reviewFeeTaxAttachment | 对照调用方提供的当前完整配对、重算六列精确分数和三项回执状态，只读输出 |

更新须携带当前revision和content_sha256完整租约；旧租约、达到十亿修订上限、身份/目标修改、超限均拒绝。无修改编辑、重复确认和同原文重绑保持修订。另存保持同一资料身份，异步保存候选不吸收之后的新输入；调用方未来仍须在安装/提交时核对实时工作区，独立函数不能提供跨标签全局锁。

三项来源允许未填写，仍可保存未知假设。日期如已给出须为有效日历日、起止不倒置；确认另要求USER_SUPPLIED、非空引用、三个日期齐全且在复核日适用、对应分支非UNKNOWN。EXAMPLE不能仅切换标签，须重新提供不同引用再明确核对。NO_SEPARATION的回执仅表示选择已记录，净额和税额仍未知。

目标须匹配完整活动映射、账单行、原币和未舍入金额；衍生费用、IMPORT_DUTIES和货物价值不能当服务费记录确认。既有提案/来源/精度/包含等阻断继续列出，不用新附件消除。未知、跨币、差额、目标退休/失配或原来源未核对仍可保留为待复核资料，不能确认新回执。不同税务成分不由自由费名、旧含税旗或任意凭证编号自动填入。

## 严格输入与验证范围

外层24MiB、内嵌配对10MiB分别按实际UTF-8检查；解析深度最多32、节点最多300000。两层均拒绝重复键（包括转义后重名）、非有限数字、坏JSON及未配对Unicode代理项；对象API另外拒绝访问器、非枚举/符号字段、循环、类实例、稀疏/附加属性数组等，避免序列化静默丢值。任意Proxy陷阱不属于沙箱保证；真实文件入口先处理严格JSON。

记录最多8条，退休ID最多200；record_id、短成分ID、mapping_id分别唯一。账单旧标识按原格式保留，不截短为成分的80位标识。所有原始十进制文本保持，账单金额用整数交叉相乘核对，不按6位核心精度或容差接受；超过原提案精度仍阻断核对，不自动舍入。

Schema是离线结构说明，未嵌入业务默认；其通过不证明真实日历、UTF-8/UTF-16限额、完整内嵌配对、重复键、精确算术、身份引用或指纹有效。源码同源生成并在CI比对。格式有效和全部回执已记录均不表示可交易或可入成本。
