## 原文字节与体积

运行`npm ci`后执行：

```sh
npm run check:fee-text-sharing -- --output benchmark-results/fee-text-sharing.json
```

默认也写入被git忽略的`benchmark-results/`。命令只使用[上一轮同样的合成夹具](../tools/fee-performance-fixture.ts)与[真实控制器环境](../tools/fee-performance-harness.ts)，不读取用户业务文件或本机浏览器存储。USER_SUPPLIED确认是软件夹具条件，不是业务或税务证明；可下载EXAMPLE练习包保持。

| 合成成分数 | 原捕获JSON字节 | 原型编码字节 | 结果 |
|---|---:|---:|---|
| 1 | 32,479,563 | 29,379,547 | 对象JSON相等，五类来源及封套原文逐字相等 |
| 4 | 199,578,320 | 未执行 | 还原预算超128 MiB，编码/解码未执行 |
| 8 | 637,708,233 | 未执行 | 还原预算超128 MiB，编码/解码未执行 |

单笔样本编码减少3,100,016字节，约9.5%；这是开发原型的**编码字节量**，不是运行工具内存、速度或业务容量改善。原型仍把`retained_json`当完整不透明字符串，本轮没有解决其内部嵌套膨胀，也没有处理4/8笔的容量限制。

[机器可读结果](cases/fee-text-sharing.json)保留环境、源文件Git blob指纹、字节数、7份共享长文本/10个文本引用及原文摘要，不含业务原文或用户路径。超限值仅通过工具侧字节预计判定，不安装未保护对象，也不进行编码、还原、候选准备或费用应用；未执行指标为null。此命令不测耗时或峰值内存，不把其与完整回归并行运行的结果用于性能结论。

## 自动化验证

[格式与字节测试](../tests/fee-text-sharing.test.ts)覆盖普通JSON、负零、中文/emoji、原文CRLF/BOM/转义字符、未知标记、原型键、自有持有者、访问器/toJSON不执行、重复键/文本、循环/别名、丢失/外部引用、语义深度、实际展开预算及摘要失配。另有200组固定种子的构造对照，以标准JSON与UTF-8结果作为独立参照；不以机器速度作为通过条件。

[归属与原流程测试](../tests/fee-text-sharing-state.test.ts)验证：

- 相同原文不合并文件名、保存时间、读取代次、未提交输入、存储可访问性或客户确认。
- JSON还原的检查点不能代替私有签发身份；A→B→A后原文字节相同，原检查点仍失效。
- 实际单笔完整捕获还原后经过原预览与十组准备。候选买方增量仍为113 USD×显式7=791 CNY，卖方利润保持未知；当前费用、封套回执、客户确认及拥有者修订保持，没有应用费用。
- 未提交费用原文仍被原预览阻断；还原的候选摘要仍不能取得原私有候选备份资格。
- 实际封套读取取消后，迟到文件不产生候选或覆盖当前文件；诊断快照不重置取消token。
