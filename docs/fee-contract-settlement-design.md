# 独立实际报价与付款草稿交接

2026-10-30，第110轮，本地开发原型。承接[切换前盘点](fee-workbench-switch-design.md)，在独立副本扩展当前术语实际报价和合同价款付款表单；仍不接管正式工作台或开放新费用、客户导出。

[实际报价控制器](../tools/fee-recovery-contract.ts)明确选择实际报价，独立填写金额、币种、指定地点和商业换算类型/日期。保留公共模拟报价和其他术语记录，不以模拟金额补实际合同；调用原项目校验、workspace校验及原单场景/对比引擎，失败保留缓冲与已提交项目。变更当前报价撤销其来源核对，旧费用候选和客户确认不复活。

[付款控制器](../tools/fee-recovery-settlement.ts)使用原实际报价绑定、标准付款JSON和原calculateSettlement。默认新建1.1草稿，结构可保存但计算条件可未完成；TT、L/C、OA不猜日期、不代表款项到账或保证收款。银行费未知不补零，原币分别合计，计划净收付不是利润。报价变化只提示绑定失配；明确重新绑定仍不自动缩放原金额、改写日期或触发条件。

本轮编辑合同价款行、付款方式、银行核对状态和内部备注。银行费逐笔清单及资金扩展保留原文、只读展示；其他标准版本可明确导入并保全，不静默升级到当前编辑版本。资金字段不在此处计算，客户资料不取自计划。单独付款输入上限4 MiB，待提交输入不能冒充已提交计划。

[独立完整载体](../tools/fee-contract-settlement-format.ts)使用版本0.1的GZIP_BASE64_UTF8外层，包含当前旧格式业务包、当前标准付款文件和上一份完整输入。旧项目、封套、恢复、来源历史和付款标准不改版；全历史与已有应用备份保持，旧档案中的付款草稿仍只归档。业务包通过私有组合接口取用，没有伪造内层已保存回执；只有完整外层文件交付后的新手动确认，才清除业务和付款的待交接状态。

完整载体限64 MiB、累计展开链256 MiB及16层；原包64 MiB、来源64条／64 MiB、128／256／48／64 MiB恢复保护及4／8费用容量保持。旧解码器只新增更紧预算参数，默认不放宽。父链、业务和计划逐项校验，解压前核对剩余预算；文件准备失败不截断历史、不回滚已提交交易和付款，可先分项保全。源同步原预算与外层组合预算分别适用，并非所有大资料都能继续交接。

[组合面板](../tools/fee-contract-settlement-panel.ts)先准备、明确打开，再重录、同步和交接。下载发起不等于操作系统保存完成；分项项目或付款导出不清除完整交接提示。取消、迟到、ABA、写入失败和打开失败保留原资料；新根安装成功后显示失败不能声称回滚。

范围与结果见[验收记录](fee-contract-settlement-validation.md)、[阶段目标](development-stages.md)及[用例](../tests/fee-contract-settlement.test.ts)。真实手机、实际业务和专业复核继续后置。本轮不上传档案、不更新main或网站。
