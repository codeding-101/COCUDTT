# 恢复资料逐项核对

2026-10-28，第102轮本地开发候选。用户已选择暂不公开第101轮合成档案；本轮继续本地开发，不上传档案、不更新main或公开网站。第101轮766份源码文件另存完整本地快照并逐字核对，作为冻结候选保留。

## 核对范围与权限

[独立核对模块](../tools/fee-recovery-review.ts)使用原恢复0.1解析器，先验证原格式、摘要、预算及完整性，再为已提交来源、原始汇率、文件事实、编辑器、活动、保留根和补充资料建立清单。`retained_json`由同一解码保留树覆盖，避免重复列出整棵树。草稿、付款计划、敏感性与客户字段分别可读；不把它们写入项目。

| 分类 | 处理方式 |
|---|---|
| 已提交资料 | 仍需经过既有独立载入路径重新校验，本面板不能安装或确认业务事实 |
| 草稿 | 保留原文，核对后在原业务表单重新录入、通过原校验 |
| 须重新输入 | 浏览器坏数字缓冲不可由空字符串补回；未读File仅有名称/大小等元数据，须重新选取 |
| 显示偏好 | 模式、折叠及显示设置仅列出，本轮不安装到原页面 |
| 历史资料 | 原提示、计算与文件保存信息不能当作当前结果、实际落盘或最新业务事实 |
| 旧执行资格 | 候选、确认、代次、活动、Promise、补丁和客户批准不得复活 |
| 未知字段 | 未知组成员与扩展全部只归档；不由字段名或对象原型推定策略 |

每个条目用逐段JSON Pointer标识，斜杠与波浪号明确转义。字段值区分null、false、空串、零和负零；原文的BOM、CR/LF及Unicode保持。完整原source_wire与supplement_json继续留在原档案；清单只建立引用，不产生新业务文件格式。

## 明确选择与安全切换

新读取只产生候选；只有同实例签发、当前代次的明确选择才能替换这个独立面板。读取期间保留旧资料与阅读记录并锁定旧面板操作，取消或失败后恢复；选择新档案会清空旧阅读记录。相同字节也不会继承旧签发身份。

“已阅读”仅记录处理说明已读，没有安装、修复输入、费用或客户批准资格。即使全部条目已读，坏数字及未读文件仍显示须重新输入。读取状态没有执行费用或客户确认的API，也不导出报价或写缓存。

上下文由调用者显式通知变化，包含A→B→A；旧阅读记录及待选候选随即撤销。本轮**尚未订阅或切换实际工作台的完整上下文**，不能把独立面板切换称为原工作台安全切换已经完成。

取消可及时返回，但底层解码结束前仍占用唯一物理槽，拒绝排队读取。迟到结果和异常不能替换当前资料，不读取私有异常内容。原128/256/48/64 MiB等预算保持；另设1024条界面清单上限，超过后整份候选拒绝并保留旧核对，不截断归档。

## 内部原文展示

[核对面板](../tools/fee-recovery-review-panel.ts)默认展示需要留意的条目，支持草稿/历史/全部筛选。原文须逐项点击，使用转义文字显示，绝不执行旧review_html。预览最多2000个UTF16单位、120节点、6层，避免把大资料整段挂入DOM；截短只影响屏幕预览，明确标注完整原文仍在档案，不能称为完整数据导出。

面板接收宿主已在本地读取的文本，没有上传、文件选择器、缓存或另存能力。客户草稿可能含内部资料，只供此独立内部核对，不沿用客户确认。[本地案例构造器](../tools/fee-recovery-review-cases.ts)只生成小型合成资料，不需要第101轮受保留的合成档案。

完整原工作台重开、显示偏好安装、草稿逐项录入定位和正式入口仍待后续。见[验收](fee-recovery-review-validation.md)及[后续阶段](development-stages.md)。
