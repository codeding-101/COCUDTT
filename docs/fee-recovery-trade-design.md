# 独立业务副本的最小交易／报价重录

2026-10-29，第104轮本地候选。接续[独立业务延续](fee-recovery-business-validation.md)和[显示偏好／重录指引](fee-recovery-preferences-validation.md)。本轮有真实业务输入和原引擎计算，尚未接入正式工具或实现完整工作台重开。依用户选择，不上传保留档案、不更新main和公开网站。

## 录入范围

| 字段 | 本轮行为 |
| --- | --- |
| 项目名称、商品名称、数量及单位 | 在第二组独立业务持有者内重新输入 |
| 货值、卖方采购成本 | 只修改金额，原币种与净价口径保持 |
| 当前固定报价金额 | 仅FIXED_QUOTE可编辑；不是货物净价或单价 |
| 实际独立报价、目标利润／目标买方支付 | 当前有效场景报价只读，不回退公共报价，不改比较基准 |
| 贸易术语、运输方式、汇率、税务、费用及合同资料 | 本轮只读，继续由原完整流程核对 |
| 归档草稿、坏数字缓冲、未读File | 不自动回填；原重开清单的阻断保持，不能借新表单绕过 |

数量改变不会自动缩放整笔报价、货值或费用。不同币种不混为同一金额。中国进口采购成本未知继续为未知，利润为null；通用旧例缺采购成本仍由原规则阻断。

## 真实持有者与原校验

[业务会话](../tools/fee-recovery-business.ts)返回一个受限[重录适配器](../tools/fee-recovery-trade.ts)。它只读当前已提交项目，在私有字符串缓冲记录新输入，未提交时不改变项目金额。每次开始编辑立即撤销本会话旧费用候选、确认和客户核对；输入恢复原文字或放弃也不会复活旧资格。

提交先经过原workspaceIssues和parseProject，再使用原toTrade、toScenario、scenarioWithDerivedInclusions、analyze、toScenarios及compare。没有另写简化公式。原错误和参考测算条件继续生效；非有限结果拒绝。原inputReviews提供精度／单位提醒，不把提醒当作法规上限或已经溢出的证明。

只在全部准备完成且当前所有者检查点仍有效时，一次替换app和workflow两个参与者。项目、结果、对比、dirty及缓存失效一起更新；原文件证据、汇率簿、账单、封套、费用回执和应用备份保持。商品相关修改按原表单原则撤销合同／保险／运输来源核对；本视图额外保守撤销固定报价金额变化后的对应来源核对。未知项目字段和未改字段的数值表示保留。

trade_input_commits统计本视图提交的交易输入，业务会话原financial_writes沿用“费用批次应用次数”的含义。不得将“没有应用费用批次”解释为“没有修改财务输入”。

## 表单与失败保持

[面板](../tools/fee-recovery-trade-panel.ts)只查询自己的容器。真实失焦、回车或按钮提交；输入阶段隐藏当前金额，错误逐项定位到本容器的真实字段。点击放弃不会先触发自动提交，输入法组词时回车不提交。两个相同字段名的独立面板互不影响。

输入为空、数量非正、格式错误或原引擎失败均保留字符串和已提交项目；不补零。上下文变化后旧输入保持可见但禁止提交，明确放弃后才能按新上下文录入。准备或根替换前失败不部分安装；原费用／客户确认保持失效。未提交输入阻断费用准备、整套交接和新客户报价准备，避免交付旧结果。2048字符是本小型表单的输入限额，不是贸易金额上限或恢复格式预算。

缓冲仅在这个临时容器内，不写浏览器缓存、文件、恢复档案或原页面。关闭容器会丢失未提交输入；本轮尚未提供缓冲交接及原页面安全切换，不能作为保存／恢复的正式入口。
