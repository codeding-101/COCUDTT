# 独立封套交接与内部审计（第七十三轮）

2026-10-19。承接[只读文件模块](fee-envelope-file-validation.md)，本轮实现[独立交接模块](../src/data/fee-envelope-snapshot.ts)，以[实际文件测试](../tests/fee-envelope-snapshot.test.ts)验证。仅供内部交接，没有工作台入口、保存/恢复控制器、自动缓存或费用写入。

## 交付范围

- `feeEnvelopeInternalSnapshot(raw)`：严格验证完整文件、真实来源与历史闭包，再输出深冻结、无共享别名的交接快照；保留传入的完整原文、文件UTF-8 SHA-256、语义内容SHA-256、对象租约与完整审计。没有另行新建“可执行交接”格式。
- `feeEnvelopeInternalHtml(raw)`：静态内部HTML，摘要区分本地历史与历史未知、当前载荷与当前配对/附件/精度来源；完整保留回执、消费、待办及全部原文件。没有脚本、外链或下载副作用。
- `feeEnvelopeWorkbookSheet(raw)`和`feeEnvelopeInternalWorkbook(raw)`：文本单元格的内部工作表和实际XLSX字节，完整JSON及审计逐片保留。没有金额合计、换币、舍入或新增费用。

导出接收原始字符串，严格验证后才生成结果。不接收调用方填写的“已核实”标记，也不信任由调用方构造的报告对象。原文件文本独立于内部重新排版：文件指纹覆盖全部UTF-8原文，语义指纹覆盖封套规范内容，不能互换；两者均可重算，不是签名，也不认证真实交易、最新版本、实际付款或全局未重复。

旧资料保持历史未知；没有消费记录不能推断未消费。合法历史即使核对通过，相对当前的PROJECT_SNAPSHOT_MISMATCH、HISTORICAL_PAYLOAD_DIFFERS_FROM_CURRENT和原税务/精度待办继续保留。只读引用不算新增消费，当前删除费用不删除旧消费，不重放旧回执。未提交编辑不在报告内。

## 原文、编码与资源上限

HTML对原文及审计转义，特别将CR/LF编码为字符引用，避免HTML解析器将CR/LF或首行换行规范化。XLSX将完整原文先编码为一个JSON字符串，再按240个Unicode码点拆为有序文本片段；按序拼接并解码一次JSON字符串即可还原原文。完整审计片段直接拼接为JSON。该方式保留CR/LF、Unicode及字面`_xHHHH_`，避免XML换行归一和公式执行。序号、指纹、原金额与分数均作为文本，不进入Excel数值或公式。

JSON交接沿用封套128MiB及全部子约束。HTML/XLSX的原始输入和序列化交接快照分别限8MiB；HTML最终UTF-8文本另限8MiB；Excel工作表模型（包含编码和单元格开销）限32MiB，最终XLSX字节另限8MiB。原XLSX写入器的10万物理行等限制仍适用。各限额共同生效，**不承诺任何合法JSON都能转为报告**；完整1.1历史可能已超过报告上限，测试明确覆盖这种合法文件。此时原始JSON仍可交接，HTML/XLSX整份拒绝，不裁剪来源/归档、清空历史或输出部分报告。

只有返回值成功才存在完整文件字节，调用失败不改变输入。没有浏览器保存、取消或下载流程，本轮不宣称已验收这些操作；接入控制器后才验证冻结保存、迟到读取、恢复冲突、取消/写入失败和原始备份。没有128MiB压力测试、浏览器大文件内存测量或真实Office打开验收。

3. 聚合费用提交最后接入：当前完整来源、政策及消费重验证，项目/账单/映射/历史一次提交；重复、失配和失败不得部分写入。
