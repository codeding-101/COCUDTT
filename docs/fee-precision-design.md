# 费用精度选择与差额审计：实现前设计

目标是同时回答：原值是多少、本次明确采用什么政策、候选是多少、差额是多少，以及哪些等式因此不再成立。不能因“可表示为6位”就认定适合入账或可应用。

## 独立数值契约（拟议0.1）

- 首版只研究非负金额；退款、负费用、贷项票据和负数舍入不支持。差额允许为负，必须用有符号分数，不能取绝对值或截为零。
- 输入金额为严格十进制字符串（最多24位整数、18位小数），或非负既约分数`{numerator,denominator}`（各最多80位，分母正，零必须0/1）；null明确表示未知。拒绝Number、空白、指数、千分位、前导加号/零及非有限数。原文本和输入快照仍须保留，数学等值不代表原文相同。
- 政策为`UNRESOLVED`，或`EXPLICIT`且填写`unit/mode/basis`。未明确政策时不输出候选。业务步长`unit`须为大于0、不超过1、去尾零后最多6位小数的十进制文本；如1、0.01、0.05、0.000001。该限制是首版工程范围，不是ISO货币表或各国法定最小单位；不能按币种名称猜步长。
- 方式仅`HALF_UP`（非负正中间向上）、`HALF_EVEN`（正中间到偶数个步长）、`DOWN`（非负向零）。未知方式拒绝；未选择不能默认四舍五入。按金额除以步长后的**精确余数**决策，不先把循环小数转换为有限小数。
- `candidate = 整数步长数 × unit`；`adjustment = candidate − original`，均为既约分数。正差表示上调，负差表示下调，0/1是真正零。候选与原值并列，不生成补差费用；后续展示可按步长格式化，计算仍用原精确分数。
- 不输出`ready/apply/accepted`或专业认证状态；未来API须返回脱离调用方的完整输入快照、政策、原值、候选、有符号差额、逐步操作数与待办。本轮检查器仅核对缩减数值协议，不是此API的实现。

## 舍入层级与未知传播

同币种1–8行、稳定且不重复的行号；跨币种、无行、超过8行拒绝。金额未知的行仍保留。

- `PER_LINE`：每行按同一明确政策取候选，再合计候选。
- `TOTAL`：先合计全部原精确金额，再取一个合计候选；**不把合计差额分摊到行**。
- 两种数值都显示，`scope_difference = PER_LINE − TOTAL`；选中层级的差额为其候选减全部原值之和。不默认采用更低或更高的一种。
- 只要有未知行，完整行合计、原值合计候选、选中合计、合计差额与层级差异均为null；另外列明`known_line_subtotal`和未知行数。小计不得改名“总额”。
- 层级不能由运输段、箱号、计费日、资金区间或界面分组自动推断；联合/分开D&D和报价包含的待办仍保留。

例如两行各0.005，按0.01/HALF_UP：逐行0.02，合计后0.01，层级差0.01。它们是两个明确政策结果，不能据此给合同或凭证挑一个“正确值”。

## 成分守恒审计：不自动配平

对已明确且满足原始`G=N+T`的价税假设，分别展示各成分候选，并核对：

- `price_tax_gap = Q(G) − Q(N) − Q(T)`；非零保留价税差额待办。
- 原X已知时，原E=G−X；`economic_gap = Q(E) − [Q(G) − Q(X)]`。X未知时E及此差额仍未知，不能用N替代。
- C始终独立；不能从税额、净额、费用净额或舍入差额推导，也不把抵扣假设解释成海关减项。
- 示例G=0.05、N=0.025、T=0.025，0.01/HALF_UP分别得0.05/0.03/0.03，价税差额−0.01。不得静默把T改成0.02；若依据凭证需要另一套明确金额，应回到原成分输入和来源重新核对。

首版不提供“尾差塞进最后一行”、自动分摊、优先保某一成分或在不同政策间挑选。全部原金额约束及原提案待办保留，数值候选不自动形成新成分回执。

## 商业换算与海关组成金额分开

汇率是严格正十进制文本，不按金额步长舍入。明确`base_currency/quote_currency/rate`，表示1单位base对应rate单位quote；直接方向乘，反向方向用精确倒数。首版不支持三角换汇、自动找汇率、合并汇率、先把逆汇率截到6位或用1补缺值。

每个核对记录须有有效日历日期`as_of/rate_date/valid_from/valid_to`和来源定位，核对日落在有效期，发布日不晚于核对日；日期和币种对缺失/不覆盖/不相符均拒绝计算，不跳到其他簿。金额未知仍输出未知。

| 目的 | 首版要求 | 不推出的结论 |
|---|---|---|
| `COMMERCIAL_REVIEW` | cash/net/tax/credit/economic之一；明确CONTRACT或MARKET来源类型；指定目标币种和业务步长/方式 | 不认定真实结算、记账汇率、抵扣汇率或会计汇兑损益 |
| `CUSTOMS_COMPONENT_REVIEW` | 仅customs通道、CUSTOMS来源类型、目标CNY、0.01/HALF_UP；使用录入的计征汇率覆盖核对日 | 仅为明确加计成分的诊断换算；不产生实际海关计税价格/税款，不确认应加计/是否已含或日期待遇资格 |

明确商业金额`x`的示例应比较`Q(x×r)`与`Q(Q_intermediate(x)×r)`，差额保留。比如1.0049995先舍到6位为1.005000，再舍至分为1.01；直接舍至分为1.00。由此不能更改旧核心；未来模块必须独立，接入计税前还要核对所有上游组成和税额舍入时点。

2026-10-18仅复核[海关总署第272号令的政府转载文本](https://www.mofcom.gov.cn/zcfb/zgdwjjmywg/art/2025/art_68923263bddd4e95b6b5d98a93987be2.html)第13/14/19条，并交叉阅读[既有政府转载来源](https://www.mct.gov.cn/preview/whhlyqyzcxxfw/ss/202411/t20241106_956082.html)：外币价格/相关费用需按计征口径转为人民币，计税价格和税额存在至分规则，普通完成申报日期与计征汇率有关。此处据此把商业选择与海关诊断隔离，不声称核验了所有现行公告、特殊申报日期、成交币种转换、估价/税种或每项金额的海关操作分组。第13条不作为按任意账单行/日/箱分别舍入的依据。真实申报仍使用现有受限模型并人工核对。
