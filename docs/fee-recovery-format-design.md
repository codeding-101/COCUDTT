# 恢复数据格式0.1与独立还原器

2026-10-26，第九十八轮。此格式用于开发验证，**不是正式工具的完整工作台重开功能**。独立还原器只替换自己的冻结数据容器，不安装运行控制器、不应用费用、不重放备份中的待提交补丁。

## 数据范围与覆盖

原两根协议继续保留20项来源及完整捕获外壳，原Node协议、生产校验、未知扩展和原文不变。新增补充资料覆盖原协议未包含的UI和应用历史。读取实际页面十组所有者的字段清单作为覆盖盘点，不能把“旧捕获相同”当作“全部界面可恢复”。

| 数据 | 保存方式 | 独立恢复后的处理 |
|---|---|---|
| 项目、账单、配对、成分、精度、封套及文件证据 | 原协议原文和持有者逐一保留，不按相同文件名合并 | 原始事实归档，重新用原引擎计算 |
| 未提交编辑、存储原文、存储不可用、空值和未知扩展 | 原20字段与完整捕获外壳 | 不补零、不采用未提交事实 |
| workflow、状态消息、核对页和视图折叠 | 显式补充profile，必需字段缺失则拒绝 | 归档资料，不安装原运行状态 |
| 候选、确认记录、已应用记录、完整备份 | 完整补充原值，不删备份/HTML以降低体积 | 保留历史事实；私有身份、旧确认没有执行资格 |
| 当前表单、未勾选checkbox、多选与选择区间 | 明确描述类型、值、checked、选择及连接状态 | 供核对，不创建DOM或触发事件 |
| 非表单未提交元素 | 存在标记、文本、dataset及contentEditable事实 | 不复活原DOM引用 |
| number的浏览器badInput、未读取File | 保存bad_input、validation_message和文件名/大小/类型/时间元数据 | 明确要求重新输入/选取；不声称取回内部输入缓冲或文件内容 |
| 任务、读令牌、活动状态、客户已确认 | 原值只作为历史资料 | 新数据所有者无活动读取、无补丁重放、无旧客户确认 |
| 原结果、比较、敏感性分析、客户预览及核对缓存 | 派生缓存不构成恢复输入；保留它们所依据的原资料 | 原引擎重新计算；不声称缓存/DOM视图逐项重开 |

补充profile含workflow、app、pair_ui、tax_ui、precision_ui、envelope_ui、view七组，以及pending_present、pending_control、pending_other、extensions。未知JSON字段完整保留，合法负零以`-0`保留；不支持的getter、toJSON、循环、稀疏数组及坏Unicode拒绝。覆盖是数据声明，不是合同正确性或完整运行恢复保证。源码见[补充profile](../tools/fee-recovery-supplement.ts)、[格式](../tools/fee-recovery-format.ts)、[独立还原器](../tools/fee-recovery-workspace.ts)。

## 版本、完整性与资源限制

明文种类为`INTERNAL_FEE_WORKBENCH_RECOVERY_DATA`，版本0.1。保存原source_wire、supplement_json及各自SHA-256；捕获时间必须是有效UTC毫秒时间。可选gzip外层种类为`INTERNAL_FEE_WORKBENCH_RECOVERY_ARCHIVE`，版本0.1，声明UTF8展开长度及SHA-256。导入/确认权限均为false，financial_writes为0。哈希用于完整性检查，不是身份签名或可信业务来源证明。

| 上限 | 范围 |
|---|---|
| 原128 MiB / 300000节点 / 深度32 | 原保留根、完整捕获与原协议，分别按原规则检查 |
| 新128 MiB | 完整捕获compact UTF8与补充资料UTF8之和；比仅保存原捕获更严格 |
| 48 MiB | 明文恢复载荷；AUTO超出后尝试gzip，NONE明确拒绝 |
| 256 MiB | gzip实际展开前载荷；持续累计输出，超声明值或全局上限即拒绝 |
| 64 MiB | 最终恢复文件，包括gzip/base64/外层字段 |

不通过压缩、删除原文、丢弃未知历史或放宽预算声称容量改善。gzip由浏览器原生流实现，独立Node gzip核对实际字节；损坏CRC、截断、多个member和额外尾部均拒绝，依据[WHATWG Compression Streams](https://compression.spec.whatwg.org/)。分块仅限制JS侧输出块记账；原生内部缓冲、物理取消和峰值内存未测量。原格式与历史封套/恢复文件不被隐式升级或混用。

## 独立数据替换与后续接入

stage只产生私有、同实例、当前代次的核对摘要；明确选择`REPLACE_QUARANTINE_DATA`后才一次替换独立容器。JSON复制、其他实例、重复确认、ABA、取消、关闭、迟到解码和重入均不得替换。解码失败保持旧数据引用。独立容器使用新所有者，重新计算利润/买方成本，但不继承缓存或业务批准；未知利润仍为null。

第九十九轮先处理完整待确认候选资料的明确超限，再设计运行适配与安静安装；完整预览、十组候选、用户明确确认、一次费用及回执、正式交接、客户隔离、失败回滚和实际收益全部通过才考虑接入。性能、容量、峰值内存与真实设备分别验证。详见[本轮验证](fee-recovery-format-validation.md)与[后续阶段](development-stages.md)。
