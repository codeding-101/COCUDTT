# 新业务副本设计（第四十轮）

2026-10-15。本轮在独立配对1.0上提供明确生成/另存新业务副本；不应用费用、不改变税务/责任/风险计算。另存原配对继续保持同一身份。

## 身份和引用

项目0.8/0.9没有全局业务ID，运行时trade-1/scenario-1仅为计算内部标识。新配对UUID建立独立资料命名空间，不承诺跨文件识别真实订单。要求不同于原项目的非空新名称（1–200字符，无首尾空白及控制字符），updated_at使用生成时的UTC元数据时间；业务日期不取电脑日期。

| 内容 | 新业务副本策略 |
|---|---|
| 配对/修订、账单、每行、活跃映射 | 新UUID、修订1；不继承删除映射历史 |
| CREATE_NEW目标 | 新UUID；已知费用引用同步替换，原目标与新目标不能混用 |
| 项目内费用ID、汇率簿ID、运输段ID、税率资料ID | 保留为副本内局部查找键，维持内部关系；不是跨业务身份 |
| REFERENCE_EXISTING及账单已有费用引用 | 指向副本项目内相同局部费用；不指向原项目的外部对象 |
| 未知扩展/自由文本中的旧编号 | 原文保留且不解释、不激活，不进行字符串搜索替换；须人工核对 |

只对已知活跃引用字段改写：contained_in_cost_id、COST_ITEMS基数ids、责任覆盖键、账单cost_reference，以及0.9运输关联的目标/费用/重叠候选成本ID。CREATE_NEW目标与项目已有费用ID冲突时拒绝，避免猜测相同编号的含义；活跃已知引用若指向已删除且不存在于副本项目/活跃提案的目标，也拒绝。原有坏引用不被自动“修好”。UUID冲突、失效预期键、坏结构或超限均整笔拒绝，不部分改写。

## 确认与旧输入

明确允许复制旧金额、币种、数量、日期、费率、箱号、范围及合同文字作为待复核输入，不重算、不舍入、不补默认。原币精度、未支持字段、包含/候选待办保持；旧日期和旧箱号不是新业务事实，生成前须明确接受这一范围。

仅处理当前版本已知的活跃确认：项目费用FX、汇率簿各币种对、进口税率/资格/HS、各方案报价/责任覆盖/运输/保险、0.9关联及重叠依据、账单行/已有引用、新建提案来源。USER_CONFIRMED降为UNVERIFIED，EXAMPLE保持示例，全部删除旧values_key；不凭空创建来源。保险两个确认布尔重置false，0.9关联state重置UNCONFIRMED并保留原范围，账单binding置null，需要重新绑定与确认。0.8同名关联扩展不解释，未知字段即使名为status/evidence也不递归重写。

本轮不引入全局“新业务就绪”标志；打开副本后的项目测算沿用既有规则，独立账单和提案仍须处理绑定、来源及候选待办。不能以复制成功推断税率/合同有效、资格成立或结果已经专业认证。

## 完整交接与竞态

用户输入新名称并明确接受复制范围；接受绑定当前配对完整键和名称，资料修订/名称改变后须重新接受。先生成完整、可序列化的内存候选，再独立另存；不自动打开、不更改当前项目/账单/编辑草稿或项目保存状态。未提交费用编辑、资料失配、未完成/重复FX行阻止生成。

候选冻结后，原资料后续变化不改变其内容；取消/失败后可另存同一候选，重复另存保持同一新业务身份。生成另一个副本前需明确放弃现候选。双击只启动一次写入，文件错误不暴露底层路径。候选仅在当前页面内存保留，关闭/刷新前须另存；渲染/交互异常的原始备份可选包含完整候选，重试不丢失。只读恢复检查沿用配对校验，不自动导入。

旧项目、账单、配对、五份Schema/模板保持。客户导出白名单隔离复制名称、内部候选及旧扩展。真实手机、实际订单/单据和人工专业复核继续暂缓；后续先设计有来源的包含/候选、含税和精度边界，再进入项目费用映射新版本/原子应用。
