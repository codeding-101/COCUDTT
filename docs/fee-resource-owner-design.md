# 隔离资源所有权与失败保持设计

2026-11-02，第119轮，开发中，尚未通过完整验收。

创建者明确交付自己新副本的清理能力。登记上限256项、物理任务槽16个，只约束登记量，不是浏览器堆、DOM或事件队列上限。私有身份、修订、勾选与明确选择控制关闭；计数恢复原值不恢复旧确认。静态清单不自动获得原应用解绑能力。

确认前可以撤回核对。确认后拒绝新登记，请求取消任务，释放明确登记资源，等待任务和异步释放实际结束，才进入CLOSED或保留失败项的FAILED。成功项不重复清理；失败须明确重试，能力须可重复调用。部分清理不可回滚。release返回true只表示请求接受；完成须等待whenIdle或close。异步释放须返回Promise，未返回的工作无法自动追踪。

结果身份在取消/关闭后失效；原始Promise已经交付的值、外部副作用不能撤销。消费者仍须检查canUseResult以及业务来源、文件和当前确认。资源关闭不授予已保存、新鲜性、丢弃原文或安装工作台的权限。DOM与原始输入保留。

适配器创建原root之外的新节点，用真实引用移除监听器、清除计时器、撤销Blob URL、关闭弹窗和中止/等待FileReader。原回调未拦截或包裹，全局原型未更改。弹窗关闭后节点和输入仍保留，两个所有者独立。

移除监听器、清除计时器只停止后续调用，不能撤销已启动异步回调。回调启动的异步工作须明确通过runTask登记，void类型不证明工作受管。本轮事件及计时器示例为同步计数，文件与后续等待是明确任务。外部登记、反射和原应用所有资源的生命周期未全部覆盖；完整切换仍关闭。
