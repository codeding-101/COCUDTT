# 集装箱费用提案配对文件与稳定映射

2026-10-15，第三十七轮。独立文件层先验收，不接入运行工具、不执行费用写入。配对容器 `INTERNAL_CONTAINER_COST_PAIR` 1.0，仅收纳项目0.8/0.9、账单1.0与提案选择0.1；原文件语义、旧扩展及版本不升级。

## 一份文件保存同一修订

保存完整项目、账单与选择，映射0.1记录配对ID、映射ID、账单ID/行ID、费用ID及已有/新建操作。配对与映射使用UUID；修订从1开始，内容修改递增，无修改时保持。整个文件先验证再序列化，读取先检查大小、结构、所有快照和引用，成功后才交付一个完整副本。10MiB按UTF-8限制，不部分返回项目或账单。

完整内容快照包括来源记录、所有费用/汇率/方案、意图、映射和删除记录，识别手工修改或不同修订拼接。与当前项目/账单核对时保留独立提案的全部待办，未知条件、失效来源、精度损失、已含与联合/分开候选仍阻断后续写入。快照可被人为重造，不是数字签名、全局锁或专业认证。

## 稳定映射与删除保留

同一账单ID/行ID/目标费用ID/操作的映射保留原编号；修改金额或来源使提案失效但不另建映射。换账单、换目标或切换操作生成新编号并保留旧记录。活动映射最多50项、删除记录最多200项；跨记录编号唯一，不静默丢历史。

已删除的CREATE_NEW目标费用ID保留，不可再用于创建新费用，防止未来应用时把重算/恢复误当新费用。REFERENCE_EXISTING可再次引用真实已有费用，但使用新的映射编号并保留旧记录。行删后重新加入、新账单复用旧行名都不能恢复已删除的新建费用目标。

更新必须携带当前完整内容快照作为预期值；旧修订、迟到更新或已改坏文件拒绝。重复提交与当前内容相同不增加修订/映射。此约束要求调用方传入当时的当前对象，不能阻止两个脱机副本独立产生分支；后续UI需在提交瞬间再次核对实时状态。

## 复制、兼容及应用门槛

另存/拷贝保留配对与映射身份，仍属于同一份资料；不能靠文件名或内容相同认定新业务。创建配对容器的新ID只是文件身份，不证明业务唯一。新业务复制时如何重置项目/账单身份、来源和映射须下一阶段专门验收，当前不提供自动fork业务按钮。

项目或账单旧同名扩展原样保留，配对映射只在本容器生效且是只读记录。项目、账单、付款不能互相误读；未来配对/映射版本及未知活动字段拒绝，Schema仅证明结构，完整快照/跨引用/精度与业务待办另由程序核对。

尚无新apply函数、UI入口、客户/内部导出或异常备份接入。后续先接配对打开/另存、取消/失败/迟到读取、恢复及客户隔离，再设计带来源的候选解决与新版本费用应用；完整门槛通过前不声明费用接入完成。
