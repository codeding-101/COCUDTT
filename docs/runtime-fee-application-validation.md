# 第八十一轮：明确整批应用与提交后恢复

2026-10-20。承接[完整运行候选](runtime-fee-candidate-validation.md)。本轮把已验证的候选接入实际工作台的一次完整提交，费用、回执、计算结果及应用记录同时出现；打开独立封套、只读预览和检查备份仍不应用费用。

## 使用流程与范围

入口为“高级设置 → 项目资料封套 · 内部交接 → 整批费用预览”。只有当前项目、账单、配对、成分附件和精度选择完整一致、历史与既有资格检查通过时，才能准备确认。用户须先看原币金额及当前/候选计算差异，再点击“核对完成，准备整批应用”、勾选核对声明，最后点击“确认整批应用”。声明不能覆盖已有阻断。

仍使用原费用投影与引擎：113 USD 在固定合成案例中按明确商业汇率 7，使买方增加 791 CNY，卖方利润保持；纯引用不增加费用，混合批次只新增应新增的行。每个成功批次一份回执，原币金额不自动舍入或换币。未知、部分海关金额、非零抵扣、复杂代付、精度损失、来源/政策待办及未知历史仍按既有规则阻断。本轮不修改税制、贸易术语、责任或风险规则，也未重查法规。

## 一次提交与确认失效

[实际适配器](../src/ui/fee-workbench-candidate.ts)只接受本实例发出的摘要；复制的 JSON、旧按钮和过期候选不取得安装权限。开始确认即消费该候选，重新解析、重算完整来源，按最新运行代次重新准备十组补丁。全部备份和校验完成后取得的短期检查点须仍有效，最后只调用一次根提交；准备期、编码失败、修订/取消代次耗尽、回调重入及完整依据变化均不能产生部分费用或回执。

[确认界面](../src/ui/fee-envelope-workspace.ts)将随机确认 token、可见候选和当前预览代次绑定。确认按钮先提交当前输入；未勾选、取消、新预览、文件/字段变更、跨标签存储事件或恢复状态使旧确认失效。异步重验中取消后，迟到失败不清除用户后来完成的新预览。后台显示取消代次按提交时最新值推进，不能被旧预备值倒退覆盖。

实际根替换同时撤销客户报价旧确认、清理派生缓存和读取令牌，并保留客户字段与结算输入。项目原文件信息和六类保存证据保持；有新增费用才强制项目待保存，纯引用保留原待保存状态。原 CREATE_NEW 配对、成分和精度资料保持逐字历史，相对新项目显示失配；不偷偷改为 REFERENCE_EXISTING，也不自动继承确认。

## 提交后故障与文件交接

实际应用不自动写浏览器缓存或文件。后续明确缓存沿用已有 Web Locks 协调的原文 CAS 和读回，冲突或写后抛错不回滚费用/回执，也不拿旧原文覆盖实际缓存。显示属于后续步骤；失败时停止显示结果并保留已应用资料，重试只重算当前项目，不重放费用事务。

成功根中同时保留最近应用记录及完整恢复备份。正常面板的“另存最近应用批次恢复备份”与[独立错误恢复页](../src/ui/recovery.ts)的专用按钮都可导出同一份不可变原文。备份为标准 JSON，kind=INTERNAL_RUNTIME_FEE_APPLICATION_BACKUP、version=0.1，保留提交前捕获、候选完整封套、回执、实际预备字段/代次及应用事实；不赋予导入或再应用权限。共享大对象仍使用明确的内部审计引用；不超过 48 MiB 的诊断 JSON 保持原文；更大的完整备份由[编码器](../src/data/runtime-fee-backup.ts)封装为 INTERNAL_RUNTIME_FEE_BACKUP_ARCHIVE / 0.1 标准 JSON，以 GZIP_BASE64_UTF8 无损保留整份原始 UTF-8 文本。提供[内部检查解码函数](../tools/runtime-fee-backup-reader.mjs)，只返回检查数据，不安装来源或重放费用。原文处理上限 256 MiB、最终文件上限 64 MiB，超限整批拒绝，不删字段或截断。

另存取消、失败或仅发起下载不撤销已应用事实、不标记原文件已保存。恢复备份供人工核对与重建，不能当项目 JSON 直接导入；项目与封套仍须分别另存。最近应用记录属于当时批次，不保证后续编辑/业务切换仍与它一致；刷新前应完成文件备份。

## 后续阶段目标

1. 提供一套受限的完整合成工作流，明确展示账单、配对、成分、精度、整批确认及客户重新报价的顺序；逐步解释具体阻断，避免用户在多个面板间猜操作。
2. 完善应用后的继续核对与文件交接：历史原文保留，任何新配对修订、引用映射和资料重绑都要明确执行并撤销旧确认；恢复备份不能直接重放费用。
3. 收敛重复状态和计算前先测量，保持领域规则、旧格式、客户字段隔离和失败恢复回归；不为扩大可点击范围放宽财务门槛。
