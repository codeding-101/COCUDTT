# 费用税务成分附件：文件、来源与交接设计

> 本文记录第五十九轮设计基线。第六十轮已实现[独立附件文件模块](fee-tax-attachment-file-validation.md)，页面/草稿/恢复与费用应用仍未接入；以下“下一轮”按原设计阶段理解。

2026-10-17，第五十九轮。承接[独立数值模块](fee-tax-components-module-validation.md)，本轮确定接入契约、独立状态案例与CI检查，**尚未实现附件读写、Schema、草稿或页面入口**。既有项目0.8/0.9、账单1.0、配对1.0/1.1和运行工具保持。本文只设计软件资料绑定，不新增税务法规结论。

## 独立附件与版本

采用独立内部JSON附件1.0，拟议`kind=INTERNAL_FEE_TAX_ATTACHMENT`。不在旧项目、账单或配对里增加有效字段，也不把旧`fee_tax_components`等同名扩展升级为活动数据。旧扩展在其原容器原样保留；只有专用入口明确打开且严格验证的新附件才可用于只读展示。附件不能通过“打开项目”“打开配对”混读，未来版本/未知活动字段整体拒绝。

拟议字段如下，**不是当前可导入格式**：

```text
kind, version: INTERNAL_FEE_TAX_ATTACHMENT / 1.0
attachment_id: 新附件身份（ASCII 1..80）
revision: 1..1,000,000,000 安全整数
pair_snapshot_json: 完整配对1.0或1.1的原始JSON文本
pair_snapshot_sha256: 上述文本UTF-8字节的SHA-256小写十六进制
records: 0..8条记录
  record_id: ASCII 1..80，附件内唯一
  target: { mapping_id, bill_id, line_id, cost_id, operation }
  input: 独立模块0.1的一行完整输入
  sources: { tax, credit, customs }
    各项为 { provenance, reference, valid_from, valid_to, checked_on }
  acknowledgements: { tax, credit, customs }
    各项为 null | { basis_sha256 }
retired_record_ids: 0..200个已删除记录ID，不复用
content_sha256: 除本字段外完整附件的规范JSON指纹
```

三项来源的`provenance`只取UNSPECIFIED、EXAMPLE或USER_SUPPLIED。reference最多200个UTF-16代码单元，允许未填写；日期允许空文本或有效ISO日历日，已给起止日不得倒置。未完成来源可以保存，不能编造日期或引用来通过格式。确认动作另要求reference非空、日期齐全且适用。USER_SUPPLIED表示用户提供，不代表已查验真实凭证。来源文字与独立输入的抵扣凭证/资格引用都进入快照，不互相代填。

目标沿用配对中的完整映射身份，operation为CREATE_NEW或REFERENCE_EXISTING；既有引用标识遵守原格式上限，不截短成80位。`input.line_id`是成分集合内的短标识，**不要求等于账单行ID**，避免旧账单最多200字符的标识被新模块80位限制破坏。最多8条记录的record_id、input.line_id和活动mapping_id分别唯一；同一映射不拆成多条成分，拆单/混合税率另行设计。删除ID保留，换目标须删除后新建记录，不默默改写身份。

输入必须通过既有独立模块的结构及精确算术校验；空附件允许尚未录入。不存储可信计算结果，打开和展示时重算分数/未知合计。未知金额/分支按独立契约保留；不能因有附件而给旧CostItem拆税。

## 完整来源、指纹与修订

附件保存完整配对原文，包含项目、账单、术语、数量、费用、币种、汇率、税务资料、选择、活动/删除映射以及已有核对计划；不能只保存ID、修订或选中费用金额。最大内嵌配对10MiB，附件整体最大24MiB，均按实际UTF-8字节计。外层JSON转义可能放大内嵌文本；必须分别检查两层限额，不能用字符数代替字节数。

配对快照按原文UTF-8计算指纹；仅换空白/字段顺序也视为新来源，不自动归一化或延续核对。当前工作区比对时，用统一配对序列化得到的原文严格比对；导入保留的非标准排版须明确重新捕获来源，不能在打开时悄悄重写原文并恢复核对。原文、配对校验和实时比对共同使用，不能凭文件名或“相同订单号”绑定。

记录核对指纹覆盖：契约标识、attachment_id、record_id、pair_snapshot_sha256、完整target/input/sources。使用规范JSON：对象键按UTF-16代码单元升序，数组保序，字符串及十进制金额不规范化；仅接受严格JSON数据，不允许非有限数、访问器、类实例、循环或重复JSON键。这里的三项核对回执、附件revision/content_sha256不进入记录核对指纹，避免确认自身循环，也避免确认一项令另两项失效。完整附件指纹则包含全部回执和revision。

保存更新须携带当前完整附件content_sha256作为租约；修订不相同或租约不相同均拒绝。无变化另存保持身份/修订；真正更新递增附件修订，来源配对本身不被修改。达到上限拒绝更新，不回绕。指纹可被人重新生成，**不是数字签名、凭证认证、全局业务唯一性或跨标签事务锁**。

## 目标与金额边界

运行时须验证完整内嵌配对，再核对完整映射元组、活动目标、对应账单行和当前术语适用性。目标消失、被退休或换了映射ID，即使复用费用名称/行号也保留为孤立待复核记录；不自动重连最近似行。来源重绑保留原输入/目标/来源文字，撤销所有回执，不删除无法绑定记录。

首版只记录人工选择的单币种服务费用成分假设。衍生进口VAT、关税、消费税、代缴税、红字/退款、不同税种/税率混合不能转成服务费记录；不从自由费用名称推定税种，也不把已有用户确认当成分类证据。实际类型及候选资格检查在文件模块实现时复用原提案/账单核对，并增加独立回归。

input.currency须与对应账单原币及目标原币一致；已知gross须与账单**未舍入原值**精确相等。未知、原账单无法计算、金额/币种不一致或既有提案阻断均列待复核，不能确认新回执，不按核心6位精度或容差悄悄接受。已有目标费用金额不同时继续列原待办，不用附件改写。独立数值函数仍可展示原始假设算术，但须标注失配，禁止表示当前业务结论。

## 三项回执与变更失效

税务成分、抵扣假设和海关成分分别由明确动作记录“已核对该用户假设”；不提供全局“已合规”“可抵扣”“可应用”状态。对应分支UNKNOWN不能确认；NO_SEPARATION可确认“不分离选择”，净额/税额仍未知。NONE及NOT_ADDED只确认本次选择及依据，不变成法律结论。

确认时须同时满足：完整当前来源/目标/原币金额相符、来源为USER_SUPPLIED、reference和三个日期明确有效、valid_from≤复核日≤valid_to、checked_on≤复核日、该facet分支不是UNKNOWN。复核日取配对账单review_date，不偷偷读取系统今天。EXAMPLE不能转成用户确认；要明确新建真实来源并重新核对，不能只切换显示标签。导入回执必须重算完整basis并重新检查条件；过期/假指纹/失配回执保留但显示待复核，绝不据回执改变资格或原待办。

| 事件 | 结果 |
|---|---|
| 仅确认一个facet | 只新增该回执；其余有效回执保持，附件修订递增 |
| 修改任一成分或任一来源文字/日期 | 该记录三项回执全部清空；不影响其他未改记录的basis |
| 任一配对字段/已有核对记录变化，或来源原文排版变化 | 所有成分记录显示来源失配；明确重绑后撤销全部旧回执 |
| 目标删除、退休或替换 | 保留原记录/目标/文字，显示孤立；重新选目标必须新建记录 |
| 同一资料另存/重命名下载文件 | 身份与已有效回执保持，不新建业务、不延长来源日期 |
| 新业务副本 | 新附件身份、空记录与空退休ID；不自动搬运旧税务/凭证假设或重写未知扩展 |
| 打开/恢复旧附件 | 先完整验证并检查实时来源；不自动确认、重绑或清除孤立记录 |

附件不随既有“新业务副本”按钮自动生成。本轮没有修改该按钮；未来需明确告诉用户新附件为空，原附件可备份保留。恢复历史文件不允许覆盖正在编辑的当前状态；同一脱机文件可形成多个分支，必须提示冲突而非宣称全局幂等。

## 文件、草稿、异步与输出

未来分为三步交付：独立纯函数/严格文件与离线Schema；控制器/草稿及内部快照；完整界面及公开体验。每步须单独验收，不能以本设计检查冒充文件或浏览器通过。

- 打开先检查原始字节、重复键、格式版本、两层JSON、完整指纹、配对及记录约束；全部成功后才准备完整候选。非法文件保留原文供备份，不部分安装配对或记录。打开附件默认独立预览，不替换当前项目/账单。
- 另存冻结完整候选及其修订。等待期间继续编辑，下载成功也只能说明旧候选已保存，不能将新修订标为已保存；取消/失败保留所有资料和未保存状态。文件选择/读取使用操作令牌和完整实时租约，迟到结果不能覆盖新编辑。
- 已提交附件与未提交编辑分别使用新版本独立草稿键；本轮不注册任何键。恢复前验证原文与完整绑定，提供备份；坏草稿不自动覆盖/删除。存储写入失败保留内存并提示另存，跨标签冲突需重读比对，不能自动合并确认。
- 内部HTML/Excel未来记录完整附件快照、版本/指纹、当前来源状态、六列精确结果及未知计数；历史失配记录必须有醒目标识。客户HTML/Excel/PDF/双语摘要继续从公开字段白名单构建，附件原文、凭证/资格引用、内部成本、回执与自由内部说明均不透传。用户手工填入公开文字的内容仍须自行核对，程序无法自动识别所有敏感语义。
- 不以未知小计代替完整总额，不将全部回执已记录表示可交易，不改变原经营利润、进口税基、推荐、付款或资金结果。精度选择、汇率/差额审计、费用映射及原子应用/回滚继续后置。

## 本轮可执行证据与下轮门槛

[合成状态向量](cases/fee-tax-attachment-design.json)和[独立检查器](../tools/check-fee-tax-attachment-design.mjs)验证来源指纹、回执失效、复制/另存、保存竞态、打开隔离、旧扩展及客户投影的**设计状态协议**。向量中的简化配对只是独立状态输入，不是完整业务文件；检查器不调用生产解析器/数值模块，不证明现有浏览器已实现这些动作，也不重复证明税款或数值公式。

限额向量只验证协议边界，未执行大文件解析或存储性能测试；简化金额对照不替代未来实际完整账单的精确金额验证。

下轮先实现独立附件文件模块与严格校验、原始快照及指纹、回执/重绑/身份和有限限额；必须新增真实完整配对的存取/坏结构/变更测试，并验证冻结输入、旧扩展不激活、精确原币对照及原业务结果保持。之后再做异步控制器/草稿恢复/内部输出与UI，最后才讨论精度及实际费用应用。真实手机、真实单据与专业复核继续按用户安排暂缓。
