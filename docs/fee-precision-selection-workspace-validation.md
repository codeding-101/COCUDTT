# 第六十八轮：工作台精度政策与完整交接验收

2026-10-18。承接[独立交接模块](fee-precision-selection-controller-validation.md)，在“高级设置 → 精度与换汇政策 · 内部核对”接入[结构化表单](../src/ui/fee-precision-selection-form.ts)、[面板适配器](../src/ui/fee-precision-selection-workspace.ts)和[工作台](../src/ui/app.ts)。新手模式保持折叠，手机沿用高级设置全屏面板，不另建业务状态副本。

## 实际操作与边界

1. 先在“项目＋账单配对交接”捕获完整当前修订，再在“费用与税务成分”提交独立附件；配对编辑、核对编辑、未提交成分编辑或计算待更新时，精度面板不把来源当作可用。
2. 明确新建空精度文件，选择原成分和通道。原金额、币种及完整目标由文件API重算捕获，不在表单手填；已有记录只编辑政策，更换通道/目标须删除后新增，保留退休编号。
3. 政策默认待明确。ROUND明确最小单位、模式和依据；FX另填用途、目标币种、汇率币种对、汇率类型、汇率日期/有效期/核对日期及来源。没有默认汇率、单位、模式、币种或日期。切换政策类型明确提示清空该类型专属字段。
4. 原值、候选和带符号差额分别显示为精确分数，未知仍未知；FX差额为候选减精确换汇额，以目标币种表示，不能与不同币种原值直接相减。原币/通道不混加，不补平价税尾差。
5. 完整双来源、政策回执、原业务待办与原成分来源/资格问题分别展示。政策确认不消除EXAMPLE、SOURCE_NOT_USER_SUPPLIED、CORE精度、金额或税务待办，不证明抵扣资格，不应用项目费用或海关税基。

中国海关成分诊断沿用既有受限数值模块：只允许C通道、海关汇率换至CNY、0.01及HALF_UP；这不是完税价格/税款计算器，不能用诊断结果覆盖原税款。未新增税制或法规结论，实际合同、税率及资料仍须另行核验。

## 双来源、草稿和恢复

当前来源是完整捕获配对的序列化原文与已提交成分附件的确定性序列化原文，附件内配对必须与当前配对完全一致。不能因为文件名、业务名称、金额相同或内嵌资料有效，就把历史来源当作实时来源。成分编辑开始时立即阻断确认/正式导出；未提交编辑明确放弃且已提交来源原文保持时，原回执可重新按同一依据评估。成分正式修订后，即使只变来源说明，精度政策也失配；明确重绑才采用当前双来源并撤销全部政策确认，保留历史原值及政策，不自动修正孤立目标。

新建、采用、恢复、删除、放弃编辑、重绑和清空槽位均需显式确认；确认绑定文件内容、原编辑文本、完整双来源及令牌，期间变化拒绝执行。采用/恢复还重验控制器候选令牌和原草稿。打开只预览，不安装内嵌项目/账单/附件。

两份独立草稿键现已注册，分别保存已提交精度文件和未提交原文。启动不自动安装，需“检查本机精度草稿 → 核对并恢复 → 确认执行”。恢复精度文件也不会加载成分附件；当前附件未恢复时，原文可备份，但不能提交或正式导出。未知/重复键/未来结构的编辑原文不强行投影，不静默丢字段；内存备份保留完整selection_json和editor_json，资料包不是可直接打开的精度文件。

原槽位冲突、不可读/配额失败仍保留内存，显示分槽状态；输入期间也及时更新写入失败提示而不重建输入节点。精确原文比对后才能明确放弃所选槽位。两个槽位不是原子事务，也不是跨标签全局锁。全局界面故障备份新增精度内存、未提交编辑及可读取的两槽原文；重试不清空精度编辑。

## 保存、内部输出和客户隔离

另存JSON可保存历史文件；HTML/Excel正式内部审计要求可用且完全相符的当前双来源，未提交编辑时均阻断。内部导出冻结点击时完整文件和复核，异步写入期间变化会标明只反映点击时资料，不混入后续编辑，也不标记项目已保存。取消、失败及非法写入结果不能声称成功。下载发起不等于已落盘。

HTML转义文字且无远程依赖；真实XLSX复用已验收文本单元格/完整JSON分片及8MiB拒绝边界，不截断原文。内部输出含完整来源，须明确提醒不能直接发客户。客户投影/HTML/XLSX/PDF路径保持，完整测试重新执行[两种版式实际文件差分](../tests/fee-precision-selection-snapshot.test.ts)，并非只在PDF字节中搜明文。

复现：构建单文件后启动隔离Edge调试页及Vite预览，设置BROWSER_CHECK_PORT、BROWSER_CHECK_PREVIEW、BROWSER_CHECK_OUTPUT，执行`node tools/run-browser-regression.mjs`。精度单套可设置PRECISION_BROWSER_URL核对已发布工具；证据保留每项布尔结果、布局、异常和真实下载文件。公开站点须在最终源码CI和Pages任务通过后核对工具、介绍、演示的正式URL字节，并执行公开精度流程。

该精度脚本默认按本地文件关闭网络，连刷新恢复也按离线验证；设置PRECISION_BROWSER_URL时则保留网络以重载正式HTTP文档，仍限制请求只能为指定正式入口或file/blob/data，分别记录transport及offlineEmulation。原脚本曾把HTTP刷新也当作可在断网后重新加载的本地文件，线上复测定位后修正此测试前提；未更改工具或引入Service Worker，不据HTTP缓存推定网站支持断网刷新。两种模式各自验证40项及四种宽度，不能把线上检查记为另一套完整离线HTTP能力。

每次精度复测使用独立下载子目录，并在报告记录实际路径；重复使用证据输出目录也不会读取前一轮同名下载文件或浏览器自动加后缀的旧产物。
