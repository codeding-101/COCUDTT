# 第七十九轮：真实工作台投影与只读整批费用预览

2026-10-20。承接[运行状态归属迁移](workbench-state-validation.md)和[完整费用快照](fee-workbench-validation.md)。本轮把实际页面的项目、账单、配对、成分附件、精度选择及封套投影到严格快照，接入真实整批校验。**运行页面仍不写入费用、回执或应用账本。**

## 页面体验

展开“项目资料封套 · 内部交接”，再展开默认折叠的“整批费用预览”，点击“核对当前工作台并预览”。有完整且相符的资料时，列出整个批次的账单/行、映射、费用、原币原金额，以及拟新增或仅引用已有费用。不能逐行跳过失败项，也不把引用再计一遍。候选中的真实计划由事务模块准备，界面不自行拼造金融结果。

没有封套、账单或其他必需资料时显示具体待办；来源原文（包括空白）不同、历史未知、未提交编辑、原始FX不完整及读取/写入/候选操作未完成均不能给出可用整批候选。缺少主要文件时仍列出已捕获的未提交输入与活动状态，不靠过滤坏行生成“完整来源”。预览只表示通过当前软件的限定检查，不认证真实订单、付款事实或全局未重复。

“另存当前工作台检查备份”导出内部JSON，包含点击时完整来源、原始FX与保留租约、未提交原文、文件信息、控制器代次、待采用候选、保存/缓存原文及客户/结算等辅助输入。它是诊断备份，没有文件导入或确认权限，不应发送客户。原文件保存证据未知的旧面板明确保留null；不以下载发起、规范化重序列化、文件名或内容摘要冒充原始已保存文本。封套有可核实的原始保存文本时单独保留。

## 实际接入与异步边界

- [app投影](../src/ui/app.ts)从10组实际参与者读取资料，区分财务来源、编辑原文、读取/变更状态和辅助资料；原32个工作流字段增加项目读取令牌为33个。未使用“当前来源不可用就返回null”的旧简化入口代替完整捕获。
- 四个旧控制器补充精确读取令牌和只读内部捕获；成功、失败、取消及较早读取迟到完成分别处理，不以中文提示文字推断是否正在读取。项目读取也保留实际令牌；其他操作推进代次即使旧读取失效。
- [运行预览适配](../src/ui/fee-workbench-preview.ts)在首个await之前严格复制并冻结捕获；调用真实FeeWorkbenchTransaction.open/preview，只保留只读结果。事务实例不交给页面，不调用confirm/cache/save或状态持有者commit。
- [封套工作区](../src/ui/fee-envelope-workspace.ts)在原有面板接入；等待期间可清除，外部修改、跨标签事件和修改后改回均撤销旧代次。异步完成还重捕获并逐字比较完整资料，变化时丢弃迟到预览。刷新保留预览面板的展开状态。
- 当前检查备份和候选不是金融批准令牌；原客户确认也不能随候选自动成为有效确认。既有项目、结果、历史、缓存及保存标记不因只读预览变化。
