# 独立编辑与完整继续交接

2026-10-30，第108轮，本地开发原型。承接[第107轮只读重建](fee-package-session-design.md)，开放七个最小交易字段、明确来源同步、完整交接下载及再次独立编辑。计算仍由原引擎执行；费用应用、客户报价和正式工作台切换另行验收。

## 原输入和当前资料分别保全

原内部包0.1只能携带当前资料、原恢复档案及来源记录，没有完整上一份输入的位置。本轮增加单独的继续交接载体0.1：GZIP_BASE64_UTF8外层包含大小、SHA-256与零写入声明，展开体携带上一份完整输入和本轮完整旧格式项目包。原项目、封套、恢复档案及内部包0.1均不改版。

[格式实现](../tools/fee-package-continuation-format.ts)逐层校验摘要、UTF-8、大小、字段、来源连续性和旧记录前缀。每个父文件保留完整文本、文件名、字节数及摘要，包含再上一份交接文件；本轮当前项目包仍经原解析器完整验证。原恢复档案和既有应用备份逐字不变，不以删除历史换容量。不修改资料时另存原输入的文本，不凭空增加历史层。

来源更新沿用原完整before/after封套、差异及问题记录，新记录序号承接继承记录。父子封套的项目、历史来源、费用账本和归档必须保持连续，不能把未知历史改为已核对。打开仅重建已提交资料；旧草稿、旧确认、付款、敏感性、客户字段和单独文件保存证据继续保持原边界。

## 独立编辑与明确交接

[编辑适配器](../tools/fee-package-continuation.ts)先复用原包校验与十组持有者准备，私有桥接得到新的业务副本。对外只开放原最小交易表单、来源同步和内部交接；不开放新费用应用或客户导出。原只读接口保持只读，原业务副本和界面不被安装覆盖。

[组合面板](../tools/fee-package-continuation-panel.ts)复用原交易表单及来源核对面板。有效输入按原规则提交、重算；数量变更不自动成倍放大既有总金额。修改项目后必须明确核对并同步当前来源，不能把未同步封套导出成完整交接。全局历史摘要区分继承记录和本轮记录，避免局部面板从零计数造成误解。

完整交接经过准备摘要、明确下载、检查下载后明确确认保存三步。浏览器DOWNLOAD_STARTED只表示发起下载；只有当前私有回执的显式保存确认才能清除待交接标记。复制、过期、跨所有者及上下文ABA回执不能确认保存。当前项目分项、原始输入分项下载均不代替完整交接，也不清除待保存标记。部分文件名固定为JSON，避免把输入文件名作为下载执行格式。

存在未交接修改时阻止另开文件。新根安装前失败保留旧编辑副本，成功安装后显示失败不声称回滚。打开和导出分别使用单物理任务槽；逻辑取消即时返回，物理任务结束前不能复用。迟到结果不能重新取得候选、保存或安装资格。

## 预算在来源覆盖前检查

原完整包仍限64 MiB，来源历史仍限64条／64 MiB。新增继续文件限64 MiB编码体、256 MiB累计展开链和16层；累计展开链包含各祖先展开体及末端旧项目包，不能只检查当前压缩大小。解压前先核对声明预算，流式解压同时限制实际输出；要求环境支持本机CompressionStream和DecompressionStream。

来源安装之前同步计算完整候选的旧项目包大小、历史预算、累计展开大小和层数。超限不提交来源、不截断旧记录，当前交易输入仍可另存项目。压缩后的64 MiB限制还需在准备文件时检查；如果该步骤失败，已明确同步的记录和待保存标记仍保留，不伪称回滚或保存成功。某些大资料可打开但无法追加一次完整来源记录，这是现有预算边界。

原128／256／48／64 MiB恢复预算、原节点和深度保护、4／8笔容量结论全部保持。新载体不是放宽费用容量，也不构成性能或峰值内存改善证据。SHA-256仅验证完整性，不证明来源真实、法规适用或专业复核通过。
