面向外贸业务人员 · 本地测算

把一笔进口报价，拆成可复核的成本方案。

货物价格、运保费、税款和费用承担放在同一套测算中。每个方案显示已知金额与待确认条件，帮助业务人员准备谈判、交接和内部复核。

打开离线工具跟着合成案例操作了解怎样开始

工具与本页放在同一目录即可打开。介绍页不读取项目文件或交易数据。

新手／专业工作台：先填交易、商品和报价，再查看当前测算；运保费可逐笔编辑原币金额，关键字段有帮助；结果下的“读懂本次计算”展示真实操作数、原币换算和海关计税，并跳转完整依据。手机高级设置可单独全屏打开，完成后返回测算；复杂费用与税务按需展开。

解决的问题

价格相近，不代表落地成本相同。

同一笔业务，费用是否已含在报价内、运输由谁组织、适用税率和海关汇率，都可能改变买方总支付。工具把这些事实分开录入，保留计算口径与未确认项。

减少漏项与重复计入

费用记录节点、原因、计价方式和“已含于”关系。方案专属费用按术语启用，替代报价组避免同一方案同时计入两份运价。

比较可解释的支付

逐方案汇总买卖方费用、完税价格和税款。卖方采购成本未知时，利润明确不可评估，仍可测算已知的买方支付。

把条件带入复核

税率与汇率来源、有效期和人工核对状态随结果保存。不满足业务前提的方案显示原因，避免把输入不完整当成推荐依据。

三步工作流

从报价到内部测算报告

01 / 建立交易

确认价格与路线

先用“中国进口示例”了解口径，再新建空白交易。录入单商品、贸易路线、申报日期和货物净价；确认报价是否捆绑运保费。

02 / 补齐成本与依据

记录费用和条件

填运费、保险及其他费用，选择适用术语。记录税率、商业与海关汇率依据，以及待遇资格、抵扣前提和必要调整。

03 / 比较与交接

核对金额与待办

比较各方案支付及风险提示，逐项检查未确认条件。保存 JSON 项目继续编辑，或导出带输入快照的内部 HTML 报告。

使用前明确范围

当前中国进口主流程针对单商品一票。其他国家的通用税率输入不等于已核验当地税制；多商品同票、复杂消费税和贸易救济税等需独立建模。原产地规则、待遇资格、可抵扣条件和保险合同仍需人工核对。

示例和自动化测试使用合成数据。尚未完成真实交易单据对照，不能据此宣称业务准确率或全面符合最新法规。

技术与设计

规则、数据与界面各有职责

源码以 TypeScript 模块维护，交付为可离线打开的单文件工具。开发便利和交易数据隐私分别由构建工具与本地运行方式保证。

Domain / 类型与事实

src/domain
费用、贸易节点、术语、税务口径、来源和警告类型。

Data / 文件与预设

src/data
版本化项目结构、输入校验、空白与示例项目、费用预设。

Engine / 规则与计算

src/engine
费用选择、依赖图、归属规则、汇率、税款与方案比较。

UI / 交互与报告

src/ui
表单和结果视图、文件操作、应用状态与独立报告生成。

采用的工程工具

TypeScript：启用 strict 和 noUncheckedIndexedAccess，让未知或缺失输入在类型与运行校验中被识别。decimal.js：十进制金额运算，税款按明确规则舍入。Vite：开发和构建。Vitest：计算、文件安全与业务边界回归。

明确的设计取舍

本地运行避免将交易输入交给服务器；来源内容仍由使用者查验。规则和计算不依赖界面，文件结构校验与业务可用性判断分开。金额缺失不静默变成零，无法比较的方案保留原因。单文件分发简化使用，模块化源码保留可维护性。
