## 解决什么问题

面向需要测算和比较报价的外贸业务人员：把货物净价、运输保险、其他费用、税率及汇率放在同一笔交易中，说明每笔费用的承担方和依据，比较买方总支付及已知条件下的卖方利润，并保留来源和待核对事项。近期重点是中国一般贸易进口、单商品一票。

设计上将货损风险、费用承担、商业报价和海关计税分开；未知成本不补零，待确认资料不作为确定的推荐依据。纯前端本地运行便于处理敏感报价，以项目JSON保存和迁移数据。

## 怎么打开

**方式一（最省事）**：直接点开 <https://codeding-101.github.io/COCUDTT/>

任何设备都行，包括手机——不用下载、不用注册、不用装任何东西。代价是数据存在浏览器本地，换设备要用项目文件迁移（见下）。

**方式二（日常使用推荐）**：下载本仓库根目录的 `trade-cost-engine.html`，双击打开。离线可用。

**方式三**：点仓库页面右上角 `Code` → `Download ZIP`，解压后双击那个文件。

想发给别人，直接把这一个文件发过去就行——样式和脚本都打包在里面了。

> **数据不会自动跟着设备走。** 草稿和项目文件都存在各自设备自己的浏览器里，
> 所以在电脑上录的交易，手机上打开链接是看不到的。
> 跨设备传递用「保存项目」导出的 `.json` 文件：发到自己的微信或邮箱，
> 在另一台设备上点「打开项目」选它即可。这是「数据不出本机」的必然代价。

## 几条容易误解的口径

- **税额是否相同取决于计税事实。** 货值、实际启用费用、估价调整及税务事实相同时税额一致；不同方案采用不同运价时，系统会重新计算税基与税额。不能仅凭税额不同认定录错数据。
- **跨术语比"报价金额"没有意义。** CIF 报 108,300 和 FOB 报 100,500 谁更好？答案取决于看买方总支付还是卖方利润，所以对比表同时给这两列。
- **"固定报价"和"固定买方总支付"回答的是不同问题。** 前者是"价格不变，我多承担环节会亏多少"；后者是"买方只肯出这个总价，我该报多少、承担到哪一环"。后者下各术语的利润往往趋于一致——这是正常的。
- **中国进口不适用中国出口退税。** 旧/通用模式可按录入假设估算出口退税，结果展示不含退税利润；实际可退金额、主体与期限需另行核验，不代表境外卖方税务已经建模。
- **CIF/CIP的保险义务不只是一笔保费。** 默认险别不同：CIF采用Institute Cargo Clauses (C)，CIP采用(A)；须核对保额、承保区间和合同约定。当前录入保费及提示不能证明保单符合要求。依据见[ICC Academy说明](https://academy.iccwbo.org/incoterms/article/incoterms-2020-cip-or-cif/)。

## 已知边界

- **未做**：按完税价格高低二选一的"选择型复合税"（遇到请手工录入税额）。
- **方案费用与报价**：不同组织方式的运价分别录入并设置适用术语，同一运段的替代报价填同组以防叠加。实际报价模式按术语独立录入；原三种基准用于模拟。各方案仍共用同一商品净价与范围；净价不同请分项目测算，避免把整价误作海关净价。
- 不支持：多用户协作、审批流、历史版本对比。

### 容量

一笔交易的费用项建议控制在 **100 条以内**。实测（浏览器、本机）：

| 费用项数 | 打开页面 | 改一个数字后重算 |
|---|---|---|
| 50 | 0.5 秒 | 0.07 秒 |
| 150 | 0.3 秒 | 0.45 秒 |
| 300 | 1.4 秒 | 1.7 秒 |

超出这个量级不会算错，只是改完一个数字要等半秒左右。计算本身很快（300 笔费用算完 11 种术语只要 34 毫秒），慢的是把几百张录入卡片重绘一遍。

## 出问题了

- **双击打开是没样式的裸页面**：浏览器拦掉了页面里的脚本。换 Chrome 或 Edge 打开；仍然不行就把浏览器控制台（F12）的报错发出来。
- **界面提示"无法计算"**：按提示补全输入即可，引擎不会在缺数据时猜一个结果。
  最常见的原因是缺少对应类型的汇率簿。
- **数字对不上**：先核对各方案启用费用、商业与海关汇率、净价及估价调整，再逐项对照税基和税额；不同运价可能依法形成不同计税价格。
- **开发时改完代码页面变成裸页面**：重启开发服务器（`npm run dev`）。

```bash
npm run dev        # 开发模式
npm test           # 计算引擎、项目文件与界面事件回归测试
npm run audit      # 静态审查：未处理的界面字段、声明了却无人产生的编码
npm run typecheck  # 类型检查
npm run build:single   # 生成 trade-cost-engine.html
npm run build:catalog  # 重建两份Schema与四种模板；CI检查生成物一致
npm run build      # 生成 dist/ 静态站点
node tools/check-import-cases.mjs  # 默认对照三笔合成案例，不代表真实业务验收
node tools/check-import-cases.mjs /path/to/cases  # 本机脱敏案例目录
```

设计与决策记录见 `docs/design.md`（含每个决策的理由、修正过的问题、以及为什么这么选）。
一份完整的样例输出见 `docs/sample-output.txt`。
